- findings:
  - MINOR — `GoalSlot.write` is not crash-atomic: it fsyncs the temp file then does `removeItem(destination)` + `moveItem` as two steps (`GoalSlot.swift:193–201`). A crash between remove and move leaves the slot absent; a later run with the same goal identity and a *fresh/empty ledger* would recreate an unconsumed slot, i.e. the one-shot marker could be reset. Today this residual is contained by the ledger: production resume always requires the non-empty ledger + checkpoint/anchor before any reservation (`PersistentTransactionOwner.swift:161,172–195`, `LiveExecutionEngine.swift:139–141`), and the consumed-slot+empty-ledger guard re-refuses when a consumed slot survives (`PersistentTransactionOwner.swift:167–170`). The dangerous combination requires simultaneously losing the ledger/checkpoint and the slot write window. Fix direction: write via `renamex_np`/`rename(2)` directly onto the destination (or `Foundation.replaceItemAt`) so there is no remove window.
  - MINOR — `OneShotAuthorizationGate` is inspect-only in production: the type only reads a `.consumed` marker and no production code writes it (`OneShotAuthorization.swift:14–24`; only `main.swift:119–124` inspects it pre-preflight). The binding one-shot authority in the live path is the goal slot + ledger, so this is not a fail-open, but it is an unimplemented convenience control whose absence must not be mistaken for authorization.
  - MINOR — the engine's live `run()` short-circuits any non-empty ledger to observe-only (`LiveExecutionEngine.swift:139–141`) and requires `currentState == nil` for fresh execution (`:142–144`). A same-ledger "continue from pre-intent state to dispatch" is therefore implemented only for `runPreflight` (`:250–270` continuation; `ComposedAdaptersTests.testPreIntentContinuationResumesWithoutReusingEvidence` covers it), not for `run()`. This is fail-closed, but plan C4's continuation semantics are narrower in `run()` than the text suggests; fresh-ledger `run()` also skips resume-time ledger/anchor checks (it is gated by goal slot + PHASE_B eligibility instead).
  - INFO — unguarded internal helpers remain in the chooser driver: `pressDefaultButton` (`FolderChooserDriver.swift:267–274`) and `confirmWithReturnKey` (`:276–278`) can post input without the durable intent/attempt gate; neither has a production caller today (verified by `rg` over `rev28/Sources`), and both are `internal`/`@discardableResult`.
