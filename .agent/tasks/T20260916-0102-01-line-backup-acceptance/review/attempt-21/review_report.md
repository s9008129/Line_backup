## FINDINGS

### RV-1 — `BLOCKER` — SEMANTIC_CONTRACT / TEST (§16.3, plan.md:90–111; Cases 22, 09, 10A, 01)
Evidence: §16.3 requires `result.json` to carry `{manifest_path, manifest_sha256, manifest_bytes, result_sha256, result_bytes}` while `manifest.json` “lists every artifact of that verify run” with `path/bytes/sha256` and finalize “recomputes … the sha256/bytes of the exact result bytes it read”. The shipped verifier's manifest already includes `result.json` itself (verified read-only: `evidence/20260916-product-verify/attempt-01/manifest.json` lists `result.json` at 18993 bytes `e331cc99…`). Result → manifest hash and manifest → result hash are therefore mutually recursive; a result cannot contain the hash of its own final bytes without an unstated canonicalization, and the manifest cannot list the result's hash while the result lists the manifest's hash without solving a fixed point. No canonicalization, field-exclusion, or write-order rule is given anywhere in the plan (`grep` for canonicalization/exclusion rules: none).
Failure mechanism: Stage 04 cannot implement the finalize precondition as written; it must either invent a hashing domain (a semantic-contract change that invalidates the approval, per §16.8/§Closure) or implement something the acceptance oracle cannot independently derive. The second clause of §16.3 — “A payload that merely looks like a result (hand-written or copied) therefore cannot finalize anything” — is an authenticity claim that an integrity-only, self-consistent hand-authored chain would satisfy (row 22a only covers a *chainless* payload).
Smallest required correction: pin one acyclic scheme (e.g., the manifest excludes `result.json` and the result records only `manifest_path`/`manifest_sha256`/`manifest_bytes`; or the result's self-fields are defined over an explicit canonical projection and the manifest's listing of the result is excluded), define exactly what finalize recomputes and in what order, add a self-consistent forged-chain negative row (or an external anchor such as a finalize-side destination/run re-check), and align the wording of the “cannot finalize anything” claim with what is actually enforced.
