- **每一步之間都要「自我核對」，核對不過就立刻停**（不准硬闖、不准自己找別的路）。

## 事後查明的真相

同一張「冷凍畫面」事後用 **macOS 內建的 Vision** 重讀（同一個檔案、同一個像素）：

- `2024/05/13~05/17`，信心 **1.00**
- **`57張照片`，信心 1.00**

也就是說：**畫面是對的相簿、照片就是 57 張；是舊的文字辨識引擎（tesseract）把很小的那排字讀錯了**。同一次 run 的三個探針還分別讀成「75」「27」「5」——三個都不一樣，本身就是「這個讀取器不穩定」的證據。

## 所以瓶頸是什麼（依重要性排序）

1. **裁判比選手弱**：整個流程的成敗押在「讀出畫面上那排小字」的能力上，而舊引擎做不到；一次讀錯就全盤中止。
2. **零容錯設計**：一次點擊、不重試、不能改路。好處是絕不會誤存或誤刪，代價是**一次誤判就要請您出面**。
3. **事前授權＋一次性的規矩**：許可證是「事前」給的，關卡沒過就作廢，不能沿用、不能補救——所以只能停下來問您（這正是這次發生的事）。
4. **環境會變**：LINE 視窗會切換、畫面會消失；這次 run 之前就曾因為視窗離開畫面而中止一次，需要您復原。
5. **另外還有一個獨立的文書卡點**：來源紀錄裡「相簿日期」的寫法與規定的短格式不同（多寫了一次年份），導致「這 57 張是否就是那本相簿的備份」無法合法認定。**您已選擇用更正版紀錄解決**。
