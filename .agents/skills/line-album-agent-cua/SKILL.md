# LINE 相簿備份

由 AI Agent 判讀畫面、選擇下一步，Computer Use 執行輸入；提示詞啟動，必要小工具協助記錄與驗證。不新增控制器或授權框架。

## 日常預設

預設完成指定列表所有尚未備份、未排除的相簿。每次啟動都自動檢查前次任務：有進度就接續，沒有才開始新任務；不要求使用者選模式、填 MODE／RESUME 或提示「接續」。完整盤點是備份中的必要步驟，不是另外一個使用者模式。

只有使用者明確要求審查／優化 Skill 時才只做文件與離線檢查，不啟動或操作 LINE。討論提示詞不是提交備份任務；只有實際任務授權及前景交接才允許 GUI 輸入。

## 工作流程

1. **自動找回前次任務。** 先讀專案 `.local/line-backup/active-task.json` 指向的原紀錄，再查真正完成、排除、操作及目的地；不能只讀一個狀態字串。依 [啟動與自動接續](references/backup-and-resume.md) 判斷前次已完成、仍在下載、待驗證、已中斷或未知；不用使用者提供接續參數。入口檔不存在時查本次指定位置及已知歷史來源，不直接當成全新空帳。
2. **接受人工交接。** 使用者開好相簿列表並交出前景，首次任務另指定儲存位置；接續自動沿用原位置。這個列表就是對象，不用群組名稱或中文 OCR（含模糊比對）辨識群組。疑似另一列表才問，不自動改配。只用當次文件支援的原生工具；前景中斷就停止輸入。
3. **完整盤點並排程。** 依 [盤點方法](references/inventory.md) 從頂到底，以相鄰畫面重疊避免漏卡，保存總本數、逐本狀態及有序下載清單。日期／張數相同仍須其他視覺依據；缺頁先小步回捲補接，仍有歧義才停下釐清。接續時核對已保存清單與當下列表，內容有變或覆蓋不足才重建；不能沿用舊座標。盤點及對帳完成後，自動繼續下載，不停在回報清單等另一個指令。
4. **逐本下載及驗證。** 讀 [操作方法](references/verified-experience.md) 與 [備份及恢復](references/backup-and-resume.md)。詳細頁再次核對相簿；保存操作前紀錄，確認唯一「儲存全部」，只送一次，核對新空白目的地。下載後逐檔核對數量、SHA-256 及 ImageIO 完整解碼，保存完成紀錄並讀回，再處理下一本。
5. **結束對帳。** 總本數須等於「已完成＋已排除＋待下載＋先前未完成＋未知＋受保護歷史」。只有已完成及排除以外均為零，且列表覆蓋證據完整，才回報這次列表全部處理完成。列表內容有變先更新盤點，不覆寫舊完成事實。

## 保護資料與接續

- 已完成、已人工備份及已排除的不重下載；證據不足的舊資料先保護並查證。
- 一次只處理一本。結果未知不重送；舊計數為零不能推翻實際已派送事件。
- **自動相簿級恢復：**任務初始授權涵蓋確認中斷後的恢復時，Agent 確認前次已停止且未完成、保留原檔，自行在另一個新空白目錄恢復該本，不逐本要求使用者重下接續指令。已完成的一律跳過；原授權不含恢復或結果無法釐清時才問。不承諾 LINE 能只補缺檔。
- 不發訊息、刪除、分享或覆寫照片；不修改舊完成事實。儲存位置、身分、操作結果不明或工具拒絕時停下，不換入口繞過、偽造批准或重置紀錄。
- 主視窗看不到選單，先查當次支援的 popup 觀察能力；沒有工具就說明缺口，不盲點、不用舊座標。

## 回報與參考

用白話回報總本數、各狀態數量、已驗證張數、目前阻塞及下一步；實測、文件規範與尚未測試的能力分開說。私人畫面、照片與原始檔名留本機；保存可接續的紀錄，不只依靠聊天記憶。

日常完成不是舊正式 AUTO 驗收，也不改正式 VERIFIED。只有明確處理舊正式研究時才讀 [歷史流程](references/legacy-formal.md)；本 Skill 不修改其可執行限制。使用者啟動提示詞見 [使用手冊](../../../docs/LINE相簿備份_使用手冊.md)。
