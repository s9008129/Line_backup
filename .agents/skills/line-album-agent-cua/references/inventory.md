# 完整盤點：必備能力

目標：在下載前知道列表共有幾本、每本的處理狀態，以及哪些本要下載。由 Agent 使用既有原生 Computer Use 瀏覽及判讀，不新增捲動控制器。文件規範不是已完成實機驗證的證明。

## 使用邊界

- Owner 人工開啟指定 LINE 畫面並交接前景；先以當次 AX／畫面確認它是否為目標相簿列表，再進入本文件流程。確認後的列表就是對象，不用群組名稱／中文 OCR 搜尋、選擇或核准群組。名稱可由當次交接畫面讀取作顯示及目錄，但不可用於搜尋、選擇、核准、dedupe、歷史合併或身分判定。
- 盤點是備份任務的必做階段，使用者不必另外選模式。先觀察、列表捲動及保存清單；需要辨識歧義候選時，在任務導覽授權內開詳細頁核對。清單及對帳完成後，自動進入已授權的下載階段。
- 審查 Skill 不取得前景。盤點階段不先派送 Save All；這是先後順序，不是要使用者盤點完再下另一道下載指令。
- 接續任務沿用 Owner 指定目的地的既有紀錄，以新畫面和卡片脈絡核對。若發現可能是另一列表，停止並問 Owner，不依名稱猜配，也不自動啟動另一群組任務。
- 開始捲動前先確認入口確為相簿列表。盤點尚未完成時，若交接或返回後落在相簿詳細頁或單張照片檢視器，依 [入口與導覽條件](verified-experience.md) 處理：有當次可靠返回控制項或符合角色／焦點的已驗證快捷鍵時返回一次並核對原列表；沒有依據就保留原視窗、停止相關輸入，先唯讀釐清，仍不能判定才問入口。入口未確認前不捲動、不盤點、不下載。

## 原生捲動方法

沿用 [重疊捲動方法](verified-experience.md)：在已確認的相簿列表捲動，一次動作後立即重新觀察，保留相鄰畫面的共同卡片。四分之一可視高度已有成功操作經驗；每次仍依當下畫面核對位移與重疊，不沿用舊位置。

在本 Session 的 CUA 文件明確提供 macOS `App.scroll(target, direction, pages)` 時，可用以下呼叫形狀；`listTarget` 必須來自最新 AX 的列表元素或已確認座標基準下的安全列表區域：

```javascript
await lineApp.scroll(listTarget, "down", 0.25);
await lineApp.getAXState();
await lineApp.getScreenshot();
```

`lineApp`、`listTarget` 是當次實際觀察建立的變數，不能直接照抄舊元素編號或座標。不同平台的參數可能不同，先讀本次工具文件。取得 app 可能啟動程式，Owner 尚未人工開啟／交接時，不藉此代替交接。

- 每次只捲一次，觀察後才決定下一步；不連續盲捲、猜跳底端或以捲動次數推算總本數。
- 過期 AX ID 先重新取得；座標基準不明就停。選單、下載視窗、對話框或編輯欄位占用列表時不捲動。
- 無位移先分辨是否真到邊界、工具未生效或內容尚未載入，不能把工具失效當底端。
- 這是一般列表盤點，不冒充已退役流程的正式 G2 驗收；要求重新研究舊流程時另定有界任務。

## 從頭到尾列清單

1. **建立起點。** 觀察當前列表；不在頂端時，朝上小幅捲動並逐次觀察。以頂端邊界及同一首卡再次向上無位移交叉確認；沒有可靠起點就記盤點未完成。
2. **記錄每張卡片。** 依列表順序給本次流水號，記日期範圍、預期張數、封面／鄰接／詳細頁等可區分的視覺依據及觀察來源。視覺身分確認後再捕捉相簿顯示名；名稱可作顯示與目錄，不作身分依據。完全讀不到名稱才問 Owner。日期和張數相同不能直接合併。
3. **有序重疊。** 下一畫面必須與上一畫面共享可確認為同一張的卡片，且前頁末段與後頁首段順序一致。部分可見卡片先保留待確認，不漏記，也不直接算成新一本。
4. **修補缺頁。** 捲太多而失去重疊時，保留缺頁紀錄，以較小步距向回核對，接回最後已證明的畫面；仍不能接回則重建本輪盤點或停止。不能因「看起來差不多」拼接清單。
5. **確認底端。** 末頁載入穩定後，再向下小幅捲動；同一末卡、同一列表、卡片次序及可靠位置／視覺位移均不變，才支持已到底。一次無變化但原因不明不能證明到底。
6. **逐本對帳。** 與該列表已確認的歷史完成、人工備份、排除與中斷紀錄比對，保存逐本狀態與來源。舊紀錄不足先保護，不因缺少標記就重下。

任何列表重排、新增／刪除卡片、視窗切換或前景中斷，都先保存斷點。重新觀察後判斷能否證明同一列表連續性；無法證明就重新盤點，不把舊畫面游標當新的控制位置。

## 必須交付的清單

每本只能列入一個當前狀態：已完成、已排除、待下載、先前未完成、未知、受保護歷史。未完成與待下載分開，避免直接把中斷相簿排入一般新下載。

```text
總本數 = 已完成 + 已排除 + 待下載 + 先前未完成 + 未知 + 受保護歷史
```

### 人工備份與六類狀態

「已人工備份」是來源說明，不是第七種狀態，不另加一次計數。每本依現有工具投影只歸入一類：

| 人工備份的實際證據 | 唯一歸類與處置 |
|---|---|
| 同一列表／相簿身分已核對，且現有 completion 或正規 history 已依紀錄工具要求確認完整證據 | 已完成（COMPLETED）；人工來源可作註記，只計一次，不重下 |
| 只有 Owner 聲明、照片存在、舊格式或證據不足，尚不能由工具認定完成 | 受保護歷史（PROTECTED_HISTORY）；保留來源，不重下，不計已完成／排除，也不捏造 manifest 或解碼證據 |
| 已有 UNKNOWN 或未解派送／命名交易 | 保留原工具狀態並先處理該阻塞；人工聲明不能覆蓋它或解鎖後續派送 |

沒有證據的人工備份不能默認為 EXCLUDED；只有另外已保存、同列表／相簿的有效排除決定才歸已排除。人工聲明與既有完成事實衝突或檔案漂移時保留原紀錄，停止派送並唯讀查證，不自行降格、升格或補下。正規 history 的證據要求見 [紀錄工具](daily-backup.md)。


保存盤點時間、當次列表／任務本地識別、頂底與重疊證據索引、每本狀態及依序待下載清單。正式備份位置已指定時沿用其 backup-records；未指定時先保存本任務私有盤點草稿，目的地標「未指定」，不要猜路徑或因此初始化正式備份狀態。既有 `daily.py` 可協助記錄；它要求的歷史／目的地資料缺失時如實回報，不偽造輸入以取得 PASS。

只有頂底及中間覆蓋成立、無漏卡／重複／身份歧義且總數對上，才報「列表已完整盤點」。若只是個別舊證據不足形成受保護歷史，且完整盤點、列表連續性及其他候選身分均已核對，可以保留並跳過該本，繼續其他合格項；受保護項不計完成／排除，整份列表仍未全部完成。未知卡片、漏頁或身分歧義使清單尚未對帳時不可下載。活動下載、結果未知的 attempt 或未完成命名交易須先處理，不能跳過另送；共通決策見 [例外處置](backup-and-resume.md#例外處置與停止範圍)。新圖或改變張數須保留舊完成事實並另查差異。

先前未完成相簿依原任務授權自動進入相簿級恢復：確認前次已終止且結果明確後，保留原檔，在另一個新空白目錄 `<相簿目錄名> (恢復 N)` 恢復該本。授權不足或 UNKNOWN 無法查清才問；UNKNOWN 不自動重送。
