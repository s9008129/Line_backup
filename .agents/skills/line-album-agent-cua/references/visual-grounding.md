# LINE popup 的觀察與安全定位

當主視窗 screenshot／AX 沒顯示選單、元素不可讀或輸入座標不明時讀取。目標是由 Agent 用現有工具補足觀察，再自行操作已授權動作。這不是新 GUI 控制器，也不保證每個 Session 都具備完整桌面能力。

## 觀察授權與資料範圍

當次正式備份 Prompt 明示的唯讀 AX、LINE／popup 截圖及本機離線 OCR 屬觀察授權，不授予其他應用操作。桌面截圖可能暫含其他可見視窗；只在 LINE popup 觀察需要、Owner 授權且平台允許時使用，優先採指定視窗／區域來源，僅保留本任務所需區域於專案私有證據，不主動開啟或辨識無關內容，不上傳外部 OCR／雲端服務。若工具只能先取得整張桌面，原圖僅作當次定位的暫存，裁出相關區域後不列入持久證據；若無法限制保存範圍就停止該來源。不得刪改既有歷史證據。

OS 螢幕擷取權限不等於 Owner 同意；只交前景或只審查文件也不授權擷取桌面。若既有任務沒有涵蓋必要的桌面觀察，缺的是該觀察的同意，僅釐清這一項，不重索已有效的 Save All 授權。平台拒絕或前景中斷仍停止，不換入口繞過。中文 OCR 可取得顯示名稱，不用來選群組或認領歷史。

## 先分清缺什麼

| 實際問題 | Agent 下一步 |
|---|---|
| 已授權整份列表下載，但 AX 沒有「儲存全部」 | 查當前可見畫面及 popup；不要求再次授權 |
| 只交出前景，沒有任何備份任務授權 | 先確認任務範圍；前景本身不授予下載權限 |
| 主視窗畫面不含 popup | 查其他已支援的觀察來源，不能當成選單未開 |
| 點過 `⋯` 一次，app-bound 截圖／AX 完全沒變 | 這是該來源沒有新資訊，不是 `MENU_CLOSED_CONFIRMED`；先查可顯示 popup 的其他來源與視窗焦點，狀態仍未知就不做第二次選單輸入 |
| 已點 Save All、工具逾時或畫面未變 | 查 chooser、進度與目的地；可能已派送，不重點 |
| popup 可見，卻無可靠輸入映射 | 保存畫面及具體缺口，停止該輸入；更多授權文字無法補足映射 |

## 觀察來源與座標

1. 讀當次 CUA 文件，確認 app／視窗、截圖涵蓋範圍、click 座標原點及單位。只呼叫文件實際提供的 API；沒有 `listWindows` 就不用猜另一個 API 名稱反覆嘗試。
2. 開啟詳細頁的選單後，重新取得畫面／AX。主視窗不可見時，若當次工具提供桌面、popup 或指定視窗觀察，改看該來源。AX 可定位就採用最新元素；AX 沒文字時可由清楚畫面辨識唯一「儲存全部」。OCR 只協助文字和框，不取代視覺脈絡；禁止用中文 OCR 選群組。
3. 若原生 CUA 無法擷取 popup，依上節當次 Owner 觀察授權且當前平台允許唯讀本機桌面截圖，可用既有 `screencapture` 保存當前畫面並以影像工具檢視；只保留相關區域於本機。這補足觀察，不改用 shell／AppleScript 派送 GUI。平台拒絕擷取時停止，不換入口繞過。
4. 使用輔助畫面之前，核對同一 LINE 詳細頁、視窗位置、顯示器與 popup 仍開啟，並取得可證明的座標轉換。記錄截圖像素尺寸、是否裁切／縮放、原點、app 視窗原點和輸入單位。只有文件／當次工具提供的 geometry 或其他當次可驗證量測成立才轉換。不能只憑一般 Retina 常識假設兩倍、用裁切圖座標直接點、憑 chooser 結果倒推先前映射安全。
5. 共同標題框只能提供候選位移，不能單獨證明兩來源同尺度。優先使用當次工具 geometry；若使用共同錨點，須另核對軸向、原點、尺度、裁切與輸入單位，並以另一個共同可見的穩定位置或視窗邊緣交叉核對。只有同尺度與軸向已證明，才可只減 offset；未知時不假設一比一或 Retina 倍率。將映射誤差納入安全區判斷，點位可能跨到刪除／分享列就停止。
6. 本文件只提供觀察／映射方法；派送前讀回、單次點擊及結果查證統一依 [Save All 流程](backup-and-resume.md#開啟相簿與儲存全部)。

每次關閉／重開 popup、視窗移動、縮放、顯示器變更或前景交接中斷，都使先前定位失效，必須重新擷取及核對。不得使用前次 Session 座標，或同一 Session 稍早已關閉 popup 的位置。沒有畫面變化不證明沒點到，也不能藉由反覆重開選單重送 Save All。

選單狀態必須由能看見 popup 的來源判斷，或由當次工具明確回報的視窗／控制狀態判斷；單一 `app-bound` 來源的「未變」不足以證明選單已關。若第一次 `⋯` 輸入可能只啟用了目標視窗、可能已開了一個未納入截圖的 popup，或可能有短暫延遲，狀態就是 `MENU_STATE_UNKNOWN`，不是已關。未知時只能增加觀察；必須先取得 `MENU_CLOSED_CONFIRMED` 且確認尚無 Save All 派送、chooser、進度或下載，才可按 [Save All 流程](backup-and-resume.md#開啟相簿與儲存全部) 做一次有界的選單開啟復原。選單輸入與 Save All 派送分開計數，任何 Save All 結果未知都不得用重開選單查證。

## 自主查證與停止

每次觀察要回答新的問題：選單是否在另一層、文字能否辨識、映射是否成立、動作是否已送出。只有畫面仍載入或有進度時才等待再看；相同方法沒有新資訊時換用已有支援的觀察來源，不重複盲點或建新框架。

所有可用且允許的來源仍不能可靠定位時，保存最後畫面、工具回覆、最後動作及是否可能已派送。用白話指出一件需處理的事，例如「已授權下載，但目前工具無法把選單畫面可靠對應到點擊位置；請將 LINE 留在原相簿，待可用的視窗觀察能力恢復後再交接」。確實只需重交前景時才要求重交；不要聲稱重交一定修復缺少的 API，不把請使用者代點當作全自動成功。

## 經驗的適用範圍

2026-10-26 實測中，app-bound CUA screenshot／AX 漏掉獨立 popup，唯讀桌面截圖看到了選單；後續 CUA 點擊打開 chooser，單本 51 張驗證完成。但當次重開 popup 後沒有重新擷取 popup，故不能把該座標作為可重用方法。2026-10-30 的特定 macOS CUA Session 已以每本新鮮 popup／共同錨點映射完成四本／141 張，獨立 E2E PASS；來源見 [根因紀錄](../../../../docs/LINE相簿SaveAll決策根因與E2E修正紀錄.md)。此成功不證明任意縮放、多螢幕或平台均可安全套用 offset，也不回填舊文字案例／模型矩陣 PASS。跨 Session 恢復與跨模型遵循率仍未測。
