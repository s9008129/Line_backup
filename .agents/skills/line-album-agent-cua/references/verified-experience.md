# 可重用的 LINE 操作方法

這裡保留會影響操作判斷的方法，不依賴審查編號、工作分支、舊座標、視窗編號或先前聊天。原始測試報告留在專案證據紀錄中；成功經驗不保證所有版本或工具都適用。

## 先判定入口，再導覽

每次交接、返回或從另一個頁面轉入時，先用當次 AX／畫面確認實際狀態。Owner 口語稱「列表」不能代替畫面證據；AX 缺少文字也不代表可靠視覺定位不可用。單本相簿的標題、日期及張數不能自行證明它與舊任務或某個原列表相同。

| 當次入口 | 有證據時 | 證據不足時 |
|---|---|---|
| 已確認列表 | 依原頂端／底端、重疊盤點與紀錄對帳 | 補觀察或小步補接，不先下載 |
| 已核對合格目標相簿詳細頁，完整盤點對帳有效 | 依 [Save All 流程](backup-and-resume.md#開啟相簿與儲存全部) 前進，不先返回 | 資格、身分或歷史不明先查證；不能僅憑標題／日期／張數認領 |
| 出處未明的相簿詳細頁／單張照片檢視器／確需返回的盤點或完成階段 | 用當前可靠返回控制項，或符合目前角色／焦點的已驗證快捷鍵返回已確認原列表；返回一次後再核對 | 保留原視窗；可唯讀釐清，仍不能判定才問入口或請 Owner 開好指定列表，不猜 Escape／Command-W／關閉，不下載 |
| LINE 選單／未核對 chooser | 出處、焦點及本次原操作可核對時，沿原流程前進 | 停止相關輸入，不猜取消／Return／返回 |
| 下載進度 | 依原紀錄及已知目的地觀察 | 結果 UNKNOWN 先查證，不另起相簿、不重送 |
| 聊天／其他／不明頁 | 唯讀確認是否仍有原任務連續性 | 不用群組名稱／中文 OCR 搜尋，不自動重開或改配列表；必要時重新交接 |

已核對出處、焦點、本次操作與完整路徑的 macOS 儲存位置 chooser 保留既有「前往資料夾」流程；這是特定 chooser 流程，不是通用 Return 或視窗返回授權。

## 每個導覽動作的前後條件

1. 輸入前確認授權與有效前景，並保留可核對的工作證據：目前頁面／視窗角色／焦點、目標、作用依據、預期頁面及可能關閉／取消的副作用。只需證據，不要求內部思考過程或逐點請示。
2. 作用依據須來自當次可辨識控制項／AX 動作，或有實證且匹配目前角色及焦點的快捷鍵。API 支援、OS 慣例、舊座標與「通常如此」都不夠；關閉控制項存在也不代表它能返回列表。
3. Escape、Command-W 與關閉按鈕不能當未知頁面的通用返回／復原方法，不靠試按驗證，也不全面禁鍵盤。已核對的 chooser 仍可沿既有流程使用 `super+shift+g`、路徑欄位讀回、Return 前往、再核對完整路徑與單次確認。
4. 每次輸入後重新觀察，確認原任務、頁面與焦點符合預期才前進。意外到聊天、來源視窗消失或前景中斷時，停止依賴原身分／定位的輸入；前景中斷後完全停止 GUI 輸入，不連按快捷鍵或猜重開來源。
5. 只有確需返回時才適用返回條件；已核對合格目標詳細頁依 Save All 流程前進。出處未明的詳細頁或單張照片檢視器沒有可靠返回依據時，保留原視窗並停止相關輸入；先唯讀釐清，仍不能判定才問入口。找到當次返回控制項或匹配角色／焦點的已驗證快捷鍵時，自主返回一次並核對原列表，不因缺少通用快捷鍵而一律停住。

## 歷史事件與證據邊界

2026-10-30 的本專案事件摘要記載：交接畫面顯示單本相簿標題、20 張照片及照片網格，AX 只有關閉／縮小等控制，沒有清楚返回入口。Agent 呼叫 `pressKey("Escape")` 後確實取得 AX／截圖，發現原相簿視窗消失、聊天主畫面出現；Owner 回報相簿視窗被關。這是當次截圖與回報整理的歷史 `OBSERVED`，沒有另存原始像素，也不是為本文件重新操作或重播。

這項事件支持「操作後觀察不足以取代輸入前的作用依據」；不能推廣成所有 LINE 版本按 Escape 都會關窗，也不能歸因於特定模型。上列規則是待後續模型案例與獨立 GUI 驗收的規範，不是本文件已完成的模型或實機 PASS。

## 在列表中開啟正確相簿

以當下卡片的日期、張數、封面及相鄰卡片確認目標。點文字／日期區域開啟相簿，避開照片縮圖；進頁面後再核對相簿詳細頁形狀、總張數及可區分的視覺內容。合格詳細頁同時有相簿標題、`N張照片`、日期區與照片網格；若看到 `(n/N)`、上／下一張或單張大圖，那是單張檢視器，不得從該處開 `⋯` 找 Save All，先依可靠返回條件回到相簿詳細頁。

日期及張數相同不代表同一本；中文名稱不作列表身分依據。開錯相簿就不開下載選單；依上文條件確認可靠返回入口後返回並重新定位，沒有依據就保留原視窗、停止相關輸入。AX 編號過期時重新觀察，不用舊編號或原位置繼續點。

## 以重疊畫面捲動

先確認目標是相簿列表，再以原生 Computer Use 小幅捲動；四分之一可視高度已有成功經驗。每次動作後觀察新畫面／AX，確認確實移動，且前頁末段與後頁首段保留可識別的共同卡片。

缺少重疊就縮小步距並補回缺頁；不能用多次盲捲、AX row 數或舊 scrollbar 數值推算完整性。頂端、底端及逐本清單的完整流程見 [完整盤點](inventory.md)。

## 找到真正的儲存全部選單

下載的順序與停止條件統一依 [Save All 流程](backup-and-resume.md#開啟相簿與儲存全部)。popup 不在主視窗來源時，讀 [畫面觀察與定位](visual-grounding.md) 補足當次證據；AX 缺標籤或 repo 缺 locator 函式，不能直接推論 Agent 無法視覺定位。

2026-10-31 的後續現場證據推翻了「第一次只啟用視窗、第二次才開選單」的舊假設。該 Session 有可保存 mapping 的連續 17 本相簿，每本都是 `menu_open_inputs=1`、`save_all_dispatches=1`；其中同一本在一次點擊後，`app-bound` 截圖／AX 仍只顯示相簿詳細頁，但同一次點擊後的桌面局部截圖清楚顯示完整五項 popup。根因是 app-bound 來源不合成視窗外的獨立 popup，不是點擊第一次失效。正確順序是一次 `⋯`，同時保存 app-bound 與桌面局部證據；桌面清楚看到唯一選單即記 `MENU_OPEN_CONFIRMED` 並映射 Save All，不再點第二次。只有能顯示 popup 的來源也確認關閉、尚無任何派送時，才保留一次有界復原；Save All 永遠只有一個派送 gate。

本次 macOS CUA 座標點擊使用 `app.click([x, y])`；`app.click({x, y})` 會以 `elementIndex must be an integer` 拒絕。app 截圖回傳的 bytes 可直接以 Node `fs.writeFile` 保存為證據。這些是本 Session 的 API 形狀，不取代當次文件。

## 選擇儲存位置與驗證

每本使用新空白目錄；看到確定的資料夾選擇視窗後，用「前往資料夾」輸入完整絕對路徑，觀察路徑及末層資料夾正確才確認一次。不靠 chooser 的上次位置或猜資料夾列座標。

2026-10-26 的 macOS CUA 不支援指定元素 index 的 `typeText`，`paste` 回傳也未改變欄位；核對前往資料夾欄位已聚焦後，不帶 index 的 `typeText` 成功。2026-10-31 另一次實測中，含中文的完整路徑以 `typeText` 輸入後變成錯誤片段，`paste` 沒有改變欄位，當次支援的 `setValue` 寫入後才讀回完全一致的值，再按 Return 前往。兩次結果不同，不能用單一 API 名稱當通用答案。每次記錄實際輸入方法、API 回傳與欄位讀回；欄位不精確就不前進、不按 Return 盲送，不把歷史 API 形狀當所有版本都支援。

下載後核對實際檔數、非空檔、穩定清單、逐檔 SHA-256 與 ImageIO 完整像素解碼，再保存完成紀錄並讀回。這套組合有真實成功經驗；檔案可解碼本身不證明與服務端原始檔完全相同。操作與工具細節見 [備份與恢復](backup-and-resume.md)。

## 取消與中斷的教訓

進度畫面可能落後實際檔案寫入。曾在畫面仍顯示部分進度時按取消，事後卻已取得整本可解碼檔案。因此「點了取消、視窗關閉」不能獨自證明已停止或只下載一部分，也不能據此宣稱原生續傳成功。另有多本在 `0/N` 停住數秒後才繼續，這是等待狀態；不得取消、重開選單或重送。原生下載視窗也可能比一次自動觀察迴圈更久，輔助流程因視窗仍在而中止時，只重新觀察並保存進度，不重跑整本流程。

每次查實際目的地、操作事件及 LINE 狀態；有完整檔案就先驗證，不重下。下載結果未知就保留 UNKNOWN，不因舊 intent 計數仍為零而忽略實際已派送事件。

目前採相簿級恢復：已完成的跳過；確定停止且未完成的一本，原任務授權涵蓋自動恢復時自行下載到另一個新空白目錄，不逐本再請示。原目錄全數保留，綁定原授權與前次 attempt；授權不涵蓋或結果仍未知才停下。LINE 原生只補缺檔尚未實證，不作日常能力承諾。

## 判斷下一步

- 目標、授權、前景與操作結果清楚：用當前工具完成下一個必要動作。
- 只是畫面或 AX 改變：重新觀察並定位，不先建立新框架。
- 入口不是已確認列表、返回作用依據不足，或動作後頁面／焦點已變：依入口與導覽條件重判；無可靠入口就保留原視窗並停止相關輸入。
- 身分不明、前景中斷、目的地不符、可能覆寫或派送結果未知：停止依賴該前提的輸入；在授權內先唯讀查證，仍無法解決才用白話提出最小問題。前景中斷後不再送 GUI 輸入。

歷史實測成功、當次 Agent 觀察、檔案驗證與正式獨立驗收分開報告；未執行的項目不寫成成功。
