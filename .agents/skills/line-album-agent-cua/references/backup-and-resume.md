# 日常備份與相簿級接續

適用 Owner 已人工選好列表、指定位置並授權的日常 Agent 任務；預設下載全部符合資格的相簿，每次啟動先自動判斷並接續舊進度。審查 Skill 或單純交出前景不是下載授權。先讀本次原生 Computer Use 文件，只使用它明確提供的方法。

## 必備工具與分工

Skill 提供判斷與方法，程式只做精準、可重複的工作。工具可放在專案原有位置，由 Skill 指向來源與用法；不必再複製進 scripts 資料夾。

| 工具 | 輸入與結果 | 使用時機 |
|---|---|---|
| Codex 原生 Computer Use | 當次指定的 LINE 畫面／AX；每次輸入後重新觀察結果 | 取得前景交接後，盤點或已授權的下載 |
| `src/line_backup_batch/image_decode.swift` 對應執行檔 | 相簿目錄及預期張數；退出碼、逐檔 SHA-256、完整像素解碼結果 | 下載穩定後或明確要求核對現有照片；用法見下文 |
| `src/line_backup_batch/daily.py` | 真實觀察及原始紀錄；持久事件、完成／未知狀態與對帳摘要 | 保存清單、派送前紀錄、完成證據及新 Session 接續；欄位見 [紀錄工具](daily-backup.md) |
| 當次已支援的 OCR；另有既存 `scripts/agent_resume/modern_ocr.swift` | 已保存的影像；輸出文字、信心值及左上原點框座標 | 視覺或 AX 資訊不足時選用，不用來辨識群組。此小工具不截圖、不操作 GUI，也不補足缺少的 popup 擷取能力 |

Agent 不靠心算或聊天記憶維護大量相簿清單；工具幫忙加總與持久保存。但 `daily summary` 把尚未完成統一列為 INCOMPLETE，Agent 必須根據是否有先前派送紀錄，分成「待下載」與「先前未完成」回報，不能假裝工具已有獨立 PENDING 欄位。數字對上不證明畫面沒有漏卡，仍須完成盤點的重疊與頂底確認。

不因使用本 Skill 而載入舊 GUI adapter、啟動自動控制器或建立簽章／一般授權系統。現有記錄工具若資料不相容，保留原始來源與阻塞，不重寫一套工具偷渡成功。

離線 OCR 沿用已有來源，不另造一套。需使用時以相符 SDK／編譯器、`-parse-as-library` 及支援該 Vision API 的 macOS deployment target 編譯至隔離位置；傳入一個真實可讀的影像絕對路徑。輸出含 imageWidth／imageHeight、items 的 text／confidence／boxTopLeftPixels；座標是影像內座標，不能直接當螢幕座標。確認退出碼與 JSON，辨識信心不是身分證明；不安裝新工具鏈、不讀無關私人影像。原始工具沒有無參數提示，不空呼叫或當獨立備份入口。

## 開始下載前

先完成 [完整盤點](inventory.md)，保存逐本清單與確定要下載的順序。已完成、已排除及受保護歷史跳過；先前未完成走恢復流程，UNKNOWN 先查證不重送。

使用者只需提供實際儲存位置及當次授權，不需要群組名稱或手填 JSON。確認磁碟已掛載、實際路徑、權限與空間；目的地曾屬另一列表時先問。新空目錄不能作為「從未備份」的證明。

每本操作前保存：本地列表／相簿識別、日期／張數與視覺依據、新空白目的地、預期張數、當次授權來源、操作紀錄及「可能已派送，禁止自動重送」。寫後讀回；寫入失敗就不點儲存全部。不要只留在聊天或暫存目錄。

既有 `daily.py` 是可用的記錄／驗證工具；它的確切輸入與拒絕條件見 [本地紀錄工具](daily-backup.md)。不得在工具拒絕後另寫一份成功紀錄來繞過它。

## 開啟相簿與儲存全部

1. 依最新畫面點卡片文字／日期等非照片區域。進詳細頁後核對日期、張數及可區分的視覺脈絡；不是目標就停止下載，安全返回後重新定位。不能只憑日期／張數判同一本。
2. 依當下畫面找 `⋯`，開啟一次後重新觀察；確認唯一「儲存全部」及安全點位。不要沿用舊座標、假定第幾列，也不點刪除／分享／改名。
3. 主視窗沒顯示選單時，依 [畫面觀察與定位](visual-grounding.md) 查當次可用的 popup／桌面／AX 證據及可靠座標轉換。平台允許的唯讀桌面截圖可補觀察，GUI 輸入仍走 CUA；不能靠連續再點、舊 popup 座標或 shell GUI 補救。原授權充分時不要求再授權，必要證據仍不足才回報具體缺口。
4. 只有操作前紀錄已保存、目標與授權仍有效，才點一次「儲存全部」。呼叫錯誤或介面沒變化都不證明未派送；先觀察，不自行再點。
5. 出現不明／覆寫／破壞性確認視窗就停止，不按 Return 猜測。不把 CUA 動作返回成功當作下載成功。

每次輸入後重新觀察畫面／AX，再決定下一步。這是 Agent 的觀察與判斷迴圈，不搬入舊 Skill 的盲目兩次點擊流程。

## 選擇儲存位置

先在檔案系統建立該本的新空白目錄，再處理明確的 macOS 資料夾選擇視窗，不依賴它記得上次位置。

- 沿用已成功的「前往資料夾」方法：當次工具支援時送 `super+shift+g`，觀察路徑輸入框出現，再輸入展開後的完整絕對路徑。
- 先用當次支援的文字輸入方法並讀回完整欄位。macOS 若不支援元素 index，核對欄位聚焦後採文件允許的不帶 index 輸入；paste 無變化時先確認內容，不重貼後直接送 Return。
- 確認輸入的是這本的新目錄才按 Return 前往；重新觀察路徑／資料夾名稱及選擇視窗，確認完整路徑脈絡相符才確認一次。
- 未核對的對話框不送鍵盤指令，不猜資料夾列座標，不在 chooser 建立／替換既有資料夾。
- 確認後結果不明先觀察 LINE 與該目的地，不重複盲按確認，更不能重派 Save All。確定取消且未開始下載才記該次明確停止；不明就記 UNKNOWN。

這些是可重用方法；本次文件修訂沒有實際操作 chooser，也未保證所有 LINE／macOS 版本相同。

## 下載與檔案驗證

看到下載開始後，不操作其他相簿。觀察進度並唯讀檢查本次目的地；未完成就保留檔案，不自動取消或重下。

驗證須逐項核對：預期與實際照片數、檔案非空、無未釐清暫存／partial／異常項目、檔名／大小／內容穩定、逐檔 SHA-256、ImageIO 完整像素解碼。不能只看副檔名、縮圖、總數或下載視窗消失；相同內容的不同檔案允許保留。

沿用 `src/line_backup_batch/image_decode.swift` 或已確認對應來源的既有 binary；它的呼叫形狀是：

```text
<已核對的 image_decode 執行檔> <本次相簿絕對路徑> <預期照片數>
```

檢查真正退出碼為 0、輸出 `verdict=PASS`、`readOnly=true`、destination／expected／actualEntries 相符，且每檔 decoded、SHA-256 與清單一致。它只接受單張影像來源，並限制每檔小於 512 MiB、邊長不超過 32768、像素不超過五千萬；不支援格式或超限要回報，不能跳過後稱全部通過。完整解碼不能獨自證明與 LINE 服務端原始檔完全相同。

沒有可用執行檔時，先查現有工具；確需編譯才用現有 Swift 與隔離輸出位置，不修改系統工具鏈或新增驗證框架。`daily verify` 已包含穩定樣本與解碼核對，使用時保留真實輸出。

全部驗證通過才保存完成紀錄並讀回。照片可讀但紀錄寫入失敗時，回報「照片驗證完成，完成紀錄尚未保存」，不能因此重新下載。日常紀錄維持人工診斷分類，不改舊正式 VERIFIED。

## 完成一本後繼續整份列表

完成事件讀回成功後，更新清單與已驗證張數，自主返回原相簿列表。用新畫面核對列表連續性、卡片順序與下一本身份；需要捲動時保留重疊，不重用原卡片座標。下一本已完成／排除就跳過，有前次 attempt 就先判斷恢復狀態，其餘合格項重新核對詳細頁、建立新 intent 後下載。

列表新增、張數改變或卡片消失時保存差異並補盤點／查證，不讓舊清單掩蓋變動。遇到身份或歷史未知先自行查證；未解前不派送。只有完整列表覆蓋仍成立且待下載、先前未完成、未知與受保護歷史全為零，才結束任務。一次成功及單本 summary PASS 不代表跨本循環已實測。

## 每次啟動都自動找回任務

使用者不必填接續模式，也不必說「繼續」。Agent 啟動後，先讀專案 `.local/line-backup/active-task.json`，找到前次任務的 `backup_root` 及其 `records_root`（必須是該位置的 backup-records）。這只是紀錄位置索引，不存另一本完成計數或游標；真實進度以該位置的逐本事件、檔案及完成證據為準。

首次建立實際任務、確認 Owner 目的地與前景對應後，由 Agent 保存這個索引並讀回；task_id／local_group_id 若保存，須來自真實紀錄。索引留在本機、不加入 Git，不含憑證。缺失或毀損時查本次指定位置及已知歷史來源，不自行初始化空帳。只有仍無法唯一找到原任務，才問位置或列表對應，不要求使用者判斷下載狀態或填 RESUME。

`backup_root` 必須是已確認的絕對路徑，`records_root` 必須指向其真實 backup-records；不接受任意外來路徑或單靠索引覆蓋原紀錄。使用現有檔案寫入工具原子保存並讀回索引；找不到可信入口時保留原檔。保存新任務入口前保留前一入口的來源，不能因此抹去未完成任務。只在真的開始備份任務時建立索引，不在優化 Skill 時寫假的執行紀錄。

索引遺失時依序查找：使用者本次已給的保存位置及其 backup-records；已保存的前一入口或原任務交接紀錄；專案內已知的 state／manual archives 與 completion-record、checkpoint、batch summary 來源。只查本專案及 Owner 已指定位置，不掃整台電腦。依真實任務識別、保存位置、事件關聯及當前列表脈絡比較候選，不依群組名稱或檔案修改時間猜選。唯一對應成立才重建位置索引；有兩個可能任務或仍無法找到位置，才問那項具體對應，不把中斷當作新任務。

每次先自動閱讀逐本清單、最後操作事件、驗證／完成紀錄及實際目的地；需要確認 LINE 目前是否下載時，再在 Owner 有效前景交接內觀察。把前次情況判明後才開始下一個下載，不以「上次視窗關閉」「資料夾有照片」或單一舊狀態欄位作完成證明。

新任務首次盤點完整列表；接續時讀原清單，核對當下列表是否有變及覆蓋是否完整，再更新必要差異，不把已完成照片重新下載。前次任務全完成也要讀回完成事實；同一列表新增相簿才排新工作。疑似另一列表或 Owner 指定不同位置而對應不明時才問，不依群組名稱猜配。

## 自動判斷與相簿級接續

| 前次實際情況 | 下一步 |
|---|---|
| 已完成且紀錄與檔案吻合 | 跳過，繼續下一本 |
| 完成檔案疑似缺失／變更 | 唯讀查證，不自動補下載 |
| 已確認下載結束，尚未驗證／保存完成 | 驗證現有檔案並保存／核對結果，不重下 |
| LINE 仍在下載 | 保留進度並觀察，不另起同一本 |
| 已確認停止且未完成 | 原任務已授權自動相簿級恢復時，保留部分檔案，自行下載至另一個新空白目錄；只有原授權不涵蓋時才問 |
| 不知道是否送出／是否仍在下載 | UNKNOWN，先查原視窗、事件與目的地；不自動重送 |

舊 intent 的 consumed=0 或 NOT_DISPATCHED 欄位，不能蓋過已記錄的實際派送事件。過往實測曾發生這種落差；不得據此宣稱尚未下載而重送。

先自行查原視窗、事件、檔案完整性與寫入情況，不一遇中斷就問使用者。若只是 intent 尚未記錄結果，事實成立後可記錄第一個真實結果；已明確寫入 UNKNOWN 的紀錄則不能改成 STOPPED 解鎖。工具不支援安全釐清該歷史結果時，保留阻塞，只問無法自行解決的具體問題，不為了接續而刪紀錄或換 ID。

注意現有 `daily.py outcome` 對同一 attempt 只接受第一筆結果：明確 UNKNOWN 不只不能改 STOPPED，也不能再寫 DOWNLOAD_FINISHED；`daily verify` 又要求後者。此時仍可用既有 decoder 唯讀核驗現有檔案並保存獨立證據，但不能宣稱 completion 已提交、改寫 UNKNOWN 或建立新 attempt 重下。回報「照片已驗證／尚未驗證；既有 UNKNOWN 阻止完成紀錄提交」與缺少的安全對帳能力。這是現有工具限制，修正需另作有界源碼工作；不是再索取一次下載授權就能解決。本次 Skill 不變更該限制。

相簿級恢復只重做原任務授權範圍內未完成的一本，不重跑已完成清單。Agent 自行保存新嘗試與舊嘗試的關聯、原始授權來源、確認已停止的事實、新空白目的地及操作前紀錄。若記錄工具需要逐本綁定的恢復資料，由 Agent 依真實的初始任務授權整理，不要求使用者手填，也不偽造一份事後批准。來源沒有包含自動恢復就不能自行擴權。

每本驗證完成就立即保存／讀回紀錄，定期更新可讀進度；不要等整批結束才保存。停止時先停止新派送、保留目前下載與原檔，記錄最後已知結果及需查事項。下次啟動讀同一索引，自動重做上述判斷。

若 Agent 整個程序已結束，Skill 不會自行重新啟動它；使用者重新啟動 Agent 並交回前景後，就自動讀紀錄接續，不需說 RESUME。唯一日常啟動提示詞集中在使用手冊，不維護第二份「接續專用」提示詞。
