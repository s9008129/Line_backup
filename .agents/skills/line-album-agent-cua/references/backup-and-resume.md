# 日常備份與相簿級接續

適用 Owner 已人工選好列表並授權的日常 Agent 任務；未另指定時使用本專案預設位置。預設下載全部符合資格的相簿，每次啟動先自動判斷並接續舊進度。審查 Skill 或單純交出前景不是下載授權。先讀本次原生 Computer Use 文件，只使用它明確提供的方法。

## 必備工具與分工

Skill 提供判斷與方法，程式只做精準、可重複的工作。工具可放在專案原有位置，由 Skill 指向來源與用法；不必再複製進 scripts 資料夾。

| 工具 | 輸入與結果 | 使用時機 |
|---|---|---|
| Codex 原生 Computer Use | 當次指定的 LINE 畫面／AX；每次輸入後重新觀察結果 | 取得前景交接後，盤點或已授權的下載 |
| `src/line_backup_batch/image_decode.swift` 對應執行檔 | 相簿目錄及預期張數；退出碼、逐檔 SHA-256、完整像素解碼結果 | 下載穩定後或明確要求核對現有照片；用法見下文 |
| `src/line_backup_batch/daily.py` | 真實觀察及原始紀錄；持久事件、完成／未知狀態與對帳摘要 | 保存清單、派送前紀錄、完成證據及新 Session 接續；欄位見 [紀錄工具](daily-backup.md) |
| 當次已支援的 OCR；另有既存 `scripts/agent_resume/modern_ocr.swift` | 已保存的影像；輸出文字、信心值及左上原點框座標 | 視覺或 AX 資訊不足時選用，不用來辨識群組。此小工具不截圖、不操作 GUI，也不補足缺少的 popup 擷取能力 |

Agent 不靠心算或聊天記憶維護大量相簿清單；工具幫忙加總與持久保存。但 `daily summary` 把尚未完成統一列為 INCOMPLETE，Agent 必須根據是否有先前派送紀錄，分成「待下載」與「先前未完成」回報，不能假裝工具已有獨立 PENDING 欄位。數字對上不證明畫面沒有漏卡，仍須完成盤點的重疊與頂底確認。

不因使用本 Skill 而載入舊 GUI adapter、啟動自動控制器或建立簽章／一般授權系統。現有記錄工具若資料不相容，保留原始來源與阻塞，不重寫一套工具偷渡成功。

離線 OCR 沿用已有來源，不另造一套。需使用時以相符 SDK／編譯器、`-parse-as-library` 及支援該 Vision API 的 macOS deployment target 編譯至隔離位置；傳入一個真實可讀的影像絕對路徑。輸出含 imageWidth／imageHeight、items 的 text／confidence／boxTopLeftPixels；座標是影像內座標，不能直接當螢幕座標。確認退出碼與 JSON，辨識信心不是身分證明；不安裝新工具鏈、不讀無關私人影像。原始工具沒有無參數提示，不空呼叫或當獨立備份入口。

## 開始下載前

所有導覽先依 [入口與導覽條件](verified-experience.md)。已核對合格目標詳細頁且完整盤點對帳有效時，直接進下列 Save All 流程；缺返回控制本身不阻止下載。出處未明的詳細頁、單張照片檢視器或確需返回的階段，才先處理可靠返回；無據則保留原視窗，先唯讀釐清，仍不能判定才問入口。焦點或身分已變時先重新核對，不先下載。

先完成 [完整盤點](inventory.md)，保存逐本清單與確定要下載的順序。已完成、已排除的跳過；個別舊證據不足的受保護歷史依 [例外處置](#例外處置與停止範圍) 保留並跳過，命名交易造成的保護不可跳過另送。先前未完成走恢復流程，UNKNOWN 先查證不重送。

使用者未另指定時，預設位置是目前專案根目錄下的 `backup/`（本工作區目前為 `/Users/hsiaojohnny/dev/Line_backup/backup`）；以當前專案根目錄計算，不沿用過期的絕對路徑。仍需當次任務授權。確認實際路徑、權限與空間；帳本按列表 UUID 分開，照片同名衝突仍由工具處理，不以目的地名稱判定列表。新空目錄不能作為「從未備份」的證明。

同一列表先由交接畫面或離線 OCR 取得群組顯示名一次，再於每本視覺身分確認後取得相簿顯示名，保存名稱來源；固定順序為 `capture-group-name → capture-album-name → detail → intent → Save All → outcome → verify`。名稱只供顯示與路徑，不能取代 local group、`album_key`、日期／張數或視覺依據。完全讀不到時才問 Owner，不以空名稱或舊 `albums/<UUID>` 猜做新備份。接著保存：本地列表／相簿識別、日期／張數與視覺依據、具名的新空白目的地、預期張數、當次授權來源、操作紀錄及「可能已派送，禁止自動重送」。寫後讀回；寫入失敗就不點儲存全部。不要只留在聊天或暫存目錄。

新目的地是 `BACKUP_ROOT/<相簿實際目錄名>/`；同名不同實體由工具加 ` (2)` 等後綴。既有 `albums/<UUID>` 與照片不遷移。名稱取得與校正命令見 [紀錄工具](daily-backup.md)；使用者不必編輯 JSON。

既有 `daily.py` 是可用的記錄／驗證工具；它的確切輸入與拒絕條件見 [本地紀錄工具](daily-backup.md)。不得在工具拒絕後另寫一份成功紀錄來繞過它。

## 開啟相簿與儲存全部

這是 album-level 下載的唯一有序流程。`選擇項目`、單張／逐張下載均不是 fallback；更多授權文字不能補足缺失的觀察或映射。

1. **核對資格與身分。** 指定列表的完整盤點與歷史對帳有效，目標來自有序清單；已完成、排除、人工備份及受保護歷史不重下；人工備份依 [六類歸類](inventory.md#人工備份與六類狀態) 計數，可能已派送或 UNKNOWN 先查證。從列表以最新卡片文字／日期等非縮圖區域開啟詳細頁，核對日期、張數與可區分視覺脈絡；已在可靠連續的合格詳細頁就不先返回。出處不明不能靠標題／日期／張數認領。
2. **保存派送前紀錄。** 依前節完成名稱取得、最新 detail、direct `intent --album-key`，讀回新空目的地與禁止重送紀錄。失敗就不派送；intent 只保留本地狀態，不簽發 GUI 權限。
3. **開選單一次。** 以最新畫面定位 `⋯`，開啟一次後觀察。若本次已開啟，先觀察既有 popup，不再開；主視窗看不到不表示未開。
4. **補足觀察與映射。** 依 [畫面觀察與定位](visual-grounding.md) 查當次允許的 AX／popup／桌面來源；確認唯一「儲存全部」、安全列內點位及可靠輸入映射。不得使用舊座標或固定列次。所有允許來源皆不可靠時保存具體缺口並停止該輸入，不改走其他下載方法，不要求重複下載授權。平台拒絕時停止，不換入口繞過。
5. **單次派送。** 再確認原授權、前景、身分、intent 讀回及未曾派送，才由 CUA 點一次 Save All。私有操作證據分記 `menu_open_inputs`、`save_all_dispatches`、最新畫面／映射來源、最後動作與緊接結果。計數表示 Agent 所記輸入，未知即標未知，不是 OS 恰好一次審計，也不新增 daily 欄位。
6. **查證結果。** 緊接觀察 chooser／進度／明確錯誤；呼叫成功不等於下載成功，逾時或畫面未變不等於未派送。結果不明時先查原視窗、事件及目的地，仍不明就保留 UNKNOWN，不第二次點擊、不新建 attempt 或目錄解鎖。不明／覆寫／破壞性確認視窗停止，不猜 Return。
7. **收斂完成。** 依下節核對 chooser 的完整路徑後單次確認，觀察下載，以 direct `outcome` 記第一個實際結果，再依檔案驗證流程 `verify` 並保存／讀回 completion。明確 UNKNOWN 仍受既有不可改寫限制，不承諾可提交 completion。完成後才依可靠返回條件核對原列表，重新定位下一本。

輸入前確認授權、有效前景、目前入口／焦點、作用依據、預期頁面及可能關閉／取消的副作用；輸入後重新觀察畫面／AX，核對仍在原任務與預期頁面才決定下一步。意外到聊天、來源視窗消失或前景中斷時，停止依賴舊身分／定位的輸入，不連按快捷鍵或猜重開來源。這是 Agent 的觀察與判斷迴圈，不搬入舊 Skill 的盲目兩次點擊流程。

## 例外處置與停止範圍

以下決策不增加下載入口或工具權限。保存當次觀察來源、最後動作、是否可能派送、原 attempt／目的地及查證結果於本機私有證據；先在原授權內查證，只在仍無法安全處理時提出一個具體問題。工具拒絕就停止依賴該前提的動作，不改程式或換入口繞過。

| 狀態／必要證據 | 授權內下一步與成功訊號 | 停止範圍／所需處理 |
|---|---|---|
| 非列表或詳細頁出處不明 | 依入口方法唯讀查證；有可靠返回依據才返回一次並核對 | 入口／身分未明不下載；仍無據才請 Owner 開好指定列表 |
| 已核對合格詳細頁且盤點有效 | 直接依上節 Save All 前進，不為缺返回入口而停下載 | 資格、歷史或身分不明先查證 |
| 找不到 Save All、popup 不可見或映射不可靠 | 依畫面觀察方法補查既有 popup，取得唯一目標與安全映射 | 來源仍不足就停該輸入，回報具體能力缺口；不重開選單或改下載方式 |
| Save All 或 chooser 確認後結果不明 | 查原視窗、事件與目的地，分辨下載中／待驗證／未知 | 不重點、不以新目錄或 attempt 解鎖；未解前停止後續派送 |
| chooser 路徑不符 | 在已核對的 chooser 依下節修正，讀回本本完整空白目的地 | 無法核對就停確認，不用舊位置或猜 Return |
| 仍在下載 | 觀察既有進度與檔案寫入 | 不主動取消、不另起相簿；等待有新結果 |
| 已知下載完成但尚未驗證 | 保存第一筆真實 outcome，再驗證現有檔案與 completion 讀回 | 驗證或紀錄失敗保留原檔，不重下載 |
| 命名交易中斷／因此顯示受保護 | 依既有 resume-naming 核對交易、hash 並接續 | 未解前不派送其他相簿；不能當普通歷史受保護項跳過 |
| 已明確 STOPPED／NOT_SENT 且未完成 | 初始恢復授權有效時，綁定前次 attempt，保留原檔，在新空白目錄恢復 | 無恢復授權才問；證據不明不以 STOPPED 解鎖 |
| 明確 UNKNOWN 已寫入 | 唯讀查證，必要時 decoder 核驗既有照片 | 不重送或改寫；現有工具無法提交 completion 時分開報告照片與紀錄結果 |
| 個別舊證據不足的歷史 PROTECTED_HISTORY，其他身分／覆蓋明確且無活動／未知派送或 pending 命名交易 | 保留並跳過該本，繼續已對帳合格項 | 不升格完成／排除；最終明列未解項，不稱全列表完成 |
| 漏頁、未知卡片或列表身分歧義 | 補接缺頁／重新觀察並核對，必要時重建盤點 | 未解前不下載；疑似其他列表才請 Owner 釐清，不搜尋或改配 |
| 前景中斷、原視窗消失或意外到聊天 | 保存斷點；唯讀釐清來源連續性 | 前景中斷停止全部 GUI 輸入；其他情況停止舊身分／定位輸入，不自動重開。必要時重新交接，無需重複原有效授權 |
| 完成檔案漂移、任務路徑／目錄身分不符 | 保留原件、紀錄差異 | 停止接續；不能重下補帳、改索引或自行遷移 |

每次觀察須回答新的問題。同一根因最多三次有證據嘗試，連續兩次沒有新資訊就停止相同方法；不為用完次數而重試。動態調整僅限當次文件支援且允許的方法，不是猜 API、重新派送或變更資料規則的許可。

## 選擇儲存位置

先讓 `daily intent` 建立並讀回該本的具名新空白目錄，再處理明確的 macOS 資料夾選擇視窗，不依賴它記得上次位置。

- 沿用已成功的「前往資料夾」方法：當次工具支援時送 `super+shift+g`，觀察路徑輸入框出現，再輸入展開後的完整絕對路徑。
- 先用當次支援的文字輸入方法並讀回完整欄位。macOS 若不支援元素 index，核對欄位聚焦後採文件允許的不帶 index 輸入；paste 無變化時先確認內容，不重貼後直接送 Return。
- 確認輸入的是這本的新目錄才按 Return 前往；重新觀察路徑／資料夾名稱及選擇視窗，確認完整路徑脈絡相符才確認一次。
- 未核對的對話框不送鍵盤指令，不猜資料夾列座標，不在 chooser 建立／替換既有資料夾。
- 確認後結果不明先觀察 LINE 與該目的地，不重複盲按確認，更不能重派 Save All。確定取消且未開始下載才記該次明確停止；不明就記 UNKNOWN。

這些是可重用方法；本次文件修訂沒有實際操作 chooser，也未保證所有 LINE／macOS 版本相同。

## 下載與檔案驗證

看到下載開始後，不操作其他相簿。觀察進度並唯讀檢查本次目的地；未完成就保留檔案，不自動取消或重下。

下載結果必須是明確 `DOWNLOAD_FINISHED` 且原始清單／預期張數穩定。完成驗證前，工具保存原名→暫名→`<相簿目錄名>_001.<ext>` 的完整交易並改名；排序使用原始檔名的 Python 字串升序，至少三位、超過 999 張自動加寬，保留原副檔名。改名後再逐項核對：預期與實際照片數、檔案非空、無未釐清暫存／partial／異常項目、檔名／大小／內容穩定、逐檔 SHA-256、ImageIO 完整像素解碼。不能只看副檔名、縮圖、總數或下載視窗消失；相同內容的不同檔案允許保留。

沿用 `src/line_backup_batch/image_decode.swift` 或已確認對應來源的既有 binary；它的呼叫形狀是：

```text
<已核對的 image_decode 執行檔> <本次相簿絕對路徑> <預期照片數>
```

檢查真正退出碼為 0、輸出 `verdict=PASS`、`readOnly=true`、destination／expected／actualEntries 相符，且每檔 decoded、SHA-256 與清單一致。它只接受單張影像來源，並限制每檔小於 512 MiB、邊長不超過 32768、像素不超過五千萬；不支援格式或超限要回報，不能跳過後稱全部通過。完整解碼不能獨自證明與 LINE 服務端原始檔完全相同。

沒有可用執行檔時，先查本專案現有工具；確需編譯才用現有 Swift，輸出至本專案 `.local/line-backup/bin`，不修改系統工具鏈或新增驗證框架。`daily verify` 已包含穩定樣本與解碼核對，使用時保留真實輸出。

全部驗證通過才保存完成紀錄並讀回。命名或校正中斷時執行 `daily resume-naming`，先核對 journal、目的地與 hash；只有狀態唯一時接續。照片可讀但紀錄寫入失敗時，回報「照片驗證完成，完成紀錄尚未保存」，不能因此重新下載。日常紀錄維持人工診斷分類，不改舊正式 VERIFIED。

## 完成一本後繼續整份列表

完成事件讀回成功後，更新清單與已驗證張數。先依 [入口與導覽條件](verified-experience.md) 確認可靠返回入口；有據才返回一次原相簿列表，無據就保留原視窗、停止相關輸入並回報入口缺口，不猜 Escape／Command-W／關閉。返回後用新畫面核對列表連續性、卡片順序與下一本身份；需要捲動時保留重疊，不重用原卡片座標。下一本已完成／排除就跳過，有前次 attempt 就先判斷恢復狀態，其餘合格項重新核對詳細頁、建立新 intent 後下載。

列表新增、張數改變或卡片消失時保存差異並補盤點／查證，不讓舊清單掩蓋變動。遇到身份或歷史未知先自行查證；未解前不派送。只有完整列表覆蓋仍成立且待下載、先前未完成、未知與受保護歷史全為零，才結束任務。一次成功及單本 summary PASS 不代表跨本循環已實測。

## 每次啟動都自動找回任務

使用者不必填接續模式、UUID 或 JSON，也不必說「繼續」。`Line_backup` 是唯一核心目錄：永久帳本預設在 `backup-records/<local_group_id>/`，照片預設在 `backup/`。`backup-records/index.json` 只登錄位置，各帳本的追加式 `events` 才是狀態來源。`.local/line-backup/active-task.json` 只協助定位最近任務，不是全歷史。

1. 執行 `daily groups` 找全部永久帳本，並讀 active-task；以本次連續列表的可靠 ID 或既存視覺／任務脈絡核對 UUID，不以群組名稱或修改時間猜配。再以 `daily memory --records-root <該 UUID 目錄>` 讀完整逐本事實；`memory`／`summary` 不需 `--root`，照片 root 不存在也能查歷史。
2. 整本完成照片目錄缺席時保留 COMPLETED 與禁止重下，另報「本機不可用；外部副本未驗證」。不要求硬碟在線、提供路徑或先登記歸檔。仍存在的目錄若部分缺檔、內容／中繼資料／身分漂移或 symlink，保護原件並停止新派送；不能將讀不到的目錄都當作正常缺席。活動下載、UNKNOWN 與未完成命名交易不因目錄消失而解除。
3. 新一批照片仍寫入 Owner 指定或預設的專案內目的地。對既有列表先用當次真實交接 `bind`；需要重新建立或更換照片 root 時，再用 `destination` 追加新目的地綁定，保留全部舊 completion 路徑。工具仍會拒絕未解派送、pending 或現存檔案異常；不得以換目的地解鎖。命令見 [紀錄工具](daily-backup.md)。
4. Agent 自行保存並讀回真實 `records_root`、`backup_root` 與 UUID 至 active-task，保存前一入口來源；不以更新索引代替事件。不因索引遺失開新帳；catalog 缺失、帳本損壞或有兩個可能列表時停止相關動作並釐清具體對應。

已遷移的帳本及所需私有證據都在照片區外；Owner 之後複製照片到外接硬碟並刪除整個 `backup/`，不影響其歷史。Agent 本次備份不因此取得刪除照片或操作外接硬碟的權限。保留專案 `backup-records/` 及 `.local/line-backup/`，不把它們當照片暫存區。

### 舊帳本的一次性安全遷移

舊版照片樹內的 `backup-records`，須在 Owner 已授權的維護範圍、無並行下載／其他寫入時，以 `daily migrate-records --root <舊照片 root>` 複製至預設永久區；需要其他受支援的專案內 collection 時才加 `--records-root <collection>`。這是紀錄維護，不是下載或 GUI 授權，也不使用舊 `relocation.prepare` 搬命名帳本。

遷移保留原 UUID、group、事件原文、hash chain、memory anchors、已完成／排除／UNKNOWN／受保護狀態與必要私有證據；校驗新副本並讀回後才切入口。原帳本留下，舊入口拒絕寫入，不能同時維護兩份。中斷、衝突或工具拒絕時保留兩邊，不手改 JSON、不覆蓋帳本、不初始化空帳。舊 relocation 收據只作歷史相容，不能變成新目的地綁定或外部照片已驗證的證明。

專案整體搬移後若永久入口仍指向舊專案或出現綁定歧義，保留兩邊原件並停止相關操作，另作安全對帳；不要把刪除照片區與整個專案搬移混為一談。

`legacy_albums` 的日期／張數只作受保護候選提示，不跨列表認領完成；無關日期不受它阻擋，張數改變也不自動解除保護。既有真實 completion／UNKNOWN 優先，讀記憶不再重開已內嵌的歷史匯入來源。

每次先自動閱讀逐本清單、最後操作事件、驗證／完成紀錄及實際目的地；需要確認 LINE 目前是否下載時，再在 Owner 有效前景交接內觀察。把前次情況判明後才開始下一個下載，不以「上次視窗關閉」「資料夾有照片」或單一舊狀態欄位作完成證明。

新任務首次盤點完整列表；接續時讀原清單。新 Session 先 bind 並開新 scan，以新頂底及重疊觀察對帳；同 Session 核對內容與覆蓋，再更新必要差異，不把已完成照片重新下載。前次任務全完成也要讀回完成事實；同一列表新增相簿才排新工作。疑似另一列表或 Owner 指定不同位置而對應不明時才問，不依群組名稱猜配。

## 自動判斷與相簿級接續

| 前次實際情況 | 下一步 |
|---|---|
| 已完成且本機照片完整，或整本目錄已缺席 | 保留完成並跳過；缺席另報本機不可用，不推定外部副本完整 |
| 完成目錄仍存在但部分缺檔、內容／身分異常 | 保護原件，停止新派送並唯讀查證，不補下載 |
| 已確認下載結束，尚未驗證／保存完成 | 驗證現有檔案並保存／核對結果，不重下 |
| 命名交易中斷，來源／暫名／目標狀態可唯一核對 | 以 `resume-naming` 接續同一交易，不重送、不重下 |
| 名稱校正中斷 | 狀態先顯示 `PROTECTED_HISTORY`；同一校正或 `resume-naming` 成功後才恢復完成 |
| LINE 仍在下載 | 保留進度並觀察，不另起同一本 |
| 已確認停止且未完成 | 原任務已授權自動相簿級恢復時，保留部分檔案，自行下載至另一個新空白目錄；只有原授權不涵蓋時才問 |
| 不知道是否送出／是否仍在下載 | UNKNOWN，先查原視窗、事件與目的地；不自動重送 |

舊 intent 的 consumed=0 或 NOT_DISPATCHED 欄位，不能蓋過已記錄的實際派送事件。過往實測曾發生這種落差；不得據此宣稱尚未下載而重送。

先自行查原視窗、事件、檔案完整性與寫入情況，不一遇中斷就問使用者。若只是 intent 尚未記錄結果，事實成立後可記錄第一個真實結果；已明確寫入 UNKNOWN 的紀錄則不能改成 STOPPED 解鎖。工具不支援安全釐清該歷史結果時，保留阻塞，只問無法自行解決的具體問題，不為了接續而刪紀錄或換 ID。

注意現有 `daily.py outcome` 對同一 attempt 只接受第一筆結果：明確 UNKNOWN 不只不能改 STOPPED，也不能再寫 DOWNLOAD_FINISHED；`daily verify` 又要求後者。此時仍可用既有 decoder 唯讀核驗現有檔案並保存獨立證據，但不能宣稱 completion 已提交、改寫 UNKNOWN 或建立新 attempt 重下。回報「照片已驗證／尚未驗證；既有 UNKNOWN 阻止完成紀錄提交」與缺少的安全對帳能力。這是現有工具限制，修正需另作有界源碼工作；不是再索取一次下載授權就能解決。本次 Skill 不變更該限制。

相簿級恢復只重做原任務授權範圍內未完成的一本，不重跑已完成清單。恢復的新空白目錄使用 `<相簿目錄名> (恢復 N)`，前次目錄與照片全留；工具仍要求逐本綁定的恢復資料。Agent 依真實初始授權整理，不要求使用者手填，也不偽造一份事後批准。來源沒有包含自動恢復就不能自行擴權。

每本驗證完成就立即保存／讀回紀錄，定期更新可讀進度；不要等整批結束才保存。停止時先停止新派送、保留目前下載與原檔，記錄最後已知結果及需查事項。下次啟動讀同一索引，自動重做上述判斷。

若 Agent 整個程序已結束，Skill 不會自行重新啟動它；使用者重新啟動 Agent 並交回前景後，就自動讀紀錄接續，不需說 RESUME。唯一日常啟動提示詞集中在使用手冊，不維護第二份「接續專用」提示詞。
