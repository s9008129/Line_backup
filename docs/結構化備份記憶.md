# 日常備份的結構化記憶

`Line_backup` 是唯一核心目錄。日常備份使用本專案的 Skill、程式、JSON 記憶與照片，啟動／接續不查找封存、外層舊目錄或 Git 歷史。穩定操作方法由 Skill 與程式維護；開發歷程留在 Git。

## 記憶放在哪裡

- `.local/line-backup/active-task.json`：找到本專案的備份位置與真實紀錄，不存另一份進度。
- `backups/backup-records/group.json`：本地列表 UUID 與目的地綁定。
- `backups/backup-records/events/*.json`：追加式盤點、歷史事實、記憶轉入、操作、結果與完成紀錄。
- `backups/backup-records/memory-anchors/*.json`：匯入記憶事件的獨立 SHA-256 校驗紀錄。
- `backups/albums/` 與既存照片目錄：實際照片。當次操作觀察與工具留在本專案 `.local/line-backup/`。

以下指令只讀取 JSON 與核對現存完成檔案，不操作 LINE，也不新增備份事件：

```sh
PYTHONPATH=src /usr/bin/python3 -B -m line_backup_batch.daily memory --root "$PWD/backups"
```

輸出為 `line-backup-memory/v1`：`albums` 是目前逐本身分、狀態、attempt 與 completion；`history` 是已評估的歷史事實；`legacy_albums` 是尚未可靠對應列表的現存照片／排除提示；`coverage` 明示涵蓋範圍。輸出只是投影，事件是唯一狀態來源。

## 如何切斷來源依賴

新的 `history` 匯入只在寫入時查核本專案的來源，將狀態判定、來源 digest、完成所需 manifest／ImageIO 結構化結果，或排除決定摘要內嵌進事件。後續讀記憶不重開匯入來源。來源缺少或身分不合者維持受保護；UNKNOWN 不升格為未派送。

既有舊格式 history 用一次性 `memory-import` 追加內嵌快照，保留原事件；來源缺失時記為受保護，不重新下載或補造完成。此為離線資料整理，不需要前景交接，也不產生 GUI 權限。

每個結構化 history／memory 匯入事件另存一份不可覆寫的 SHA-256 校驗紀錄。讀取核對內容及集合，末筆記憶單獨被改寫／移除也會停止。寫入中斷而缺校驗紀錄同樣停止。這是本機一致性檢查，不是簽章，也不保證防止有權同時修改事件與校驗檔的人。

工具拒絕本專案以外的目的地 root、CLI 輸入與證據引用；本機編譯工具也放在專案內。這個路徑限制不是 OS sandbox 或網路隔離。
