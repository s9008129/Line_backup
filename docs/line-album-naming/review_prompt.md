## 審查重點

1. **日常路徑真正符合要求。** 從使用者交接、取得 OCR 名稱、清單、準備目錄、儲存全部、改名、驗證到完成紀錄，逐步追蹤實際可呼叫介面與 Skill 指令。檢查一般新備份是否能不經意回退到 `albums/<UUID>`；如有舊介面相容分支，要核實正常新任務是否可到達，並以測試或具體執行路徑說明，不能僅憑存在分支就判缺陷。確認新名稱確實保存來源，無法取得時的行為與使用者決策一致。
2. **身分和名稱分離。** OCR 名稱、資料夾名稱、日期／張數、同名群組或相簿不能單獨作為身分、去重或授權證明。檢查原本的交接、詳細頁核對、不同列表隔離、歷史保護，以及名稱被截斷、清理或校正後的關聯。
3. **資料不丟失、不覆寫。** 檢查原檔名排序、序號位數、副檔名、相同內容多檔、名稱碰撞與大小寫／Unicode／非法字元／過長名稱；驗證目標存在、符號連結、路徑逃逸、替換及並行競態時拒絕或安全處理。完成紀錄須在改名後數量、非空、穩定取樣、逐檔 SHA-256 和 ImageIO 完整解碼均實際通過後才寫入；hash 一致不證明與 LINE 伺服器原始位元相同。
4. **中斷與校正。** 對照持久紀錄、鎖、檔案操作與讀回的先後順序，檢查每個建立目錄、保存計畫、改名、追加事件、驗證及提交前後的中斷／重啟。確認只能在來源、目標、hash 與紀錄唯一一致時接續；狀態不明或檔案異動須停止，不能因重試、重設、換目錄或丟棄紀錄造成重送、覆寫或虛報完成。特別檢查未完成的群組／相簿校正、目標已存在、部分成功、多次校正與跨相簿關聯。
5. **歷史與狀態投影。** 檢查舊完成事件、事件鏈、memory anchors、intent／outcome／completion 與路徑／檔名校正的關聯；已合法校正的完成紀錄需驗證最新有效位置，舊格式仍能按原規則檢查，不能改寫歷史或把受保護歷史升格。`UNKNOWN` 不解鎖、不重送；恢復採新的空白目錄並保留原 attempt。確認專案搬移的舊綁定不被新命名功能靜默繞過。
6. **Skill 和使用者體驗。** 對照 Skill、盤點／備份／紀錄參考文件與使用手冊，確認說明和程式實際介面一致：OCR 只用於命名、先取得名稱再派送、chooser 路徑、改名與完成順序、校正方法、錯誤與恢復，以及不要求使用者手填 JSON。既有 `albums/<UUID>` 描述如仍保留，須清楚說明它是否僅適用舊資料；不可讓 Agent 對新備份照舊操作。確認未削弱既有前景交接、Save All 一次、無授權不操作及既有預設路徑保護。
7. **可執行的校正介面。** 確認群組／相簿名稱校正真的可由使用者依 `--help` 和手冊操作，而不是只存在內部函式；檢查群組校正涉及全部受影響的新格式相簿，且缺陷、未知 attempt、舊格式或衝突不會被部分略過。直接在 Finder 改名不應被誤報成已安全校正。
8. **測試與驗收證據。** 檢查測試是否真正覆蓋上述核心場景、失敗及中斷邊界，而非只重複實作邏輯。實作完成且不與其他 Agent 衝突時，可在隔離合成 fixture 執行 `PYTHONPATH=src /usr/bin/python3 -B -m unittest discover -s tests -p test_daily_records.py` 和實作新增的必要測試；記錄實際命令、環境、退出碼及結果。只使用現有相容 Swift SDK，不改系統工具鏈。禁止以真實照片、實際任務紀錄或 LINE 作測試資料。
