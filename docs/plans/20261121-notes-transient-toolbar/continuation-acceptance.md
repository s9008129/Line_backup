# 中斷接續的完整性驗證

Owner 補充的成功條件是接續並完成該列表應保存的照片和影片。保持原本的派送、隔離、身分與檔案安全邊界。補下載以新暫存接續，能保留已驗證的完成檔。成功與否看逐項核對結果。

Agent 從當次覆蓋完整的清單，逐項對照已核對來源、完成事件與檔案檢查。原交易若有充分證據，接續原交易。需要補下載時，使用原有安全流程。已驗證項跳過，待處理的合格項依序完成。整份清單只在所有應保存媒體都有可追溯的完成和檔案檢查證據時回報成功。有未解的待補項、安全耗盡項或無法核對的檔案時，保留精確缺項和可查狀態。

新增一個合成回歸，使用既有測試 fixture 和 Notes 入口。S1 做完一張照片後，在影片 attempt 已保存但尚無 outcome 時中斷，另留一張待處理照片。S2 重開帳本與 bind，先記實際可支持的 UNKNOWN，安全隔離後完成掃描和細盤。僅影片建一筆 v5。用日常 download-check 保存影片與剩餘照片。最終重開帳本，對照每一個預期 key、檔案種類、SHA-256、完成紀錄與可用性。驗證整份清單從未完成變成 `all_known_media_complete=true`，S1 的完成紀錄及檔案皆保留。既有負面回歸繼續驗證有耗盡欠件時即使其他項全完成，整份清單仍為未完成。

驗證切片只加 `tests/test_notes_unknown_recovery.py`。Leader 負責執行。必要時僅在相同正式 Prompt 與 Skill 的結尾明確化最終逐項對帳，使用已有欄位及交易，不增加 Owner 介入步驟。真實 LINE 運行仍須有實際前景交接與任務授權。合成回歸所驗證的是帳本及檔案完整性。
