重要解讀：

- scan_coverage=COMPLETE 是卡片掃描完成，不是媒體備份完成。
- notes_capture 收據的 status=COMPLETE 是摘要命令輸出擷取完成，不代表備份成功。
- dispatch_blockers=[] 只表示摘要沒有列出的帳本業務 blocker；它不證明 GUI 下載控制已找到。
- dispatch_authorized=false 是這次唯讀 summary 的回傳欄位，不撤銷使用者原始 Prompt 的 GUI 授權，也不代表 CLI 拒絕。實際停止條件是 GUI 控制來源與定位未獲證明。
- 各媒體 source_availability=UNKNOWN 是摘要中的來源可用性欄位；status_counts.UNKNOWN=0 且 unresolved_attempts=[]。這不是 UNKNOWN attempt，沒有任何下載結果可 reconcile。
- notes CLI 的 --help、lists、summary、bind、scan start/page/finish、兩筆 post 及一次 media --items 輸出均由 line_backup_batch.notes_capture 保存；摘要與事件資料已讀回。notes CLI --help、scan、post、media 與 final summary 的 child exit 都是 0。每條命令的原始 argv 與 stdout／stderr／receipt 留在下方私有 task 目錄。
- 沒有執行照片像素解碼、影片解碼或 completion 讀回，因為沒有下載結果。下載 E2E、混合附件 chooser、跨 Session 續接與恢復均為 NOT_RUN。

## 7. 事實、推論與未知

### 已證實事實

- 使用者授權與當次前景交接成立；已依記事本流程完成入口核對、全列表掃描、貼文細盤及媒體建檔。
- 當次 viewer 頁面沒有可從 AX 或截圖證明為 LINE 記事本下載控制的控制項。
- 5 個媒體仍是 PENDING；沒有 attempt、chooser、下載結果或 completion。
- 既有帳本與當次列表比對後唯一選中；active 定位差異沒有造成跨列表操作。
- notes CLI 可記錄列表、貼文與媒體，但此處沒有 CLI 對當次 GUI 控制的觀察證據。

### 合理推論（需分析者檢驗）

- 本次停在 GUI 控制可辨識性門檻；現有證據不能把原因歸為 notes CLI 故障或使用者未授權。
- dispatch_blockers=[] 與 GUI 無法證明控制可以同時成立；summary 欄位不代表工具看過 LINE 畫面。
- 根因候選包括：控制位於另一個 Notes 畫面、控制需安全的 hover／次級操作、目前 UI／版本差異、操作知識或 reference 不足，或本次探索未覆蓋控制所在位置。這些都是待證假設，尚未排名。

### 尚未知

- LINE 記事本對目前照片 viewer 的正式下載入口及其所屬畫面。
- 控制是否只在 hover、貼文卡片或其他記事本上下文出現；是否能由 AX 命名或只能從當次畫面定位。
- 當次 LINE、macOS 版本與登入／服務狀態；本次沒有記錄這些資訊。
- 相關 Skill/reference 是否已有被忽略的明確入口，或需補充一條能由當次畫面證實的導覽說明。
- CLI summary 是否有意只表示帳本可派送狀態，或需要更清楚區分 GUI 未確認；目前不能僅以 dispatch_blockers=[] 判定缺陷。
