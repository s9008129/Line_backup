# 記事本下載就緒與自動接續修復計畫

## 目標與範圍

沿用手冊中的正式記事本備份 Prompt。Agent 從當次前景及永久記憶自行核對列表、貼文、媒體與未決交易，逐項判斷是否能建立 intent。已隔離舊 UNKNOWN 的合格項仍接續既有 v5 流程。前景有效時，Agent 自行處理局部阻塞及後續合格項。前景失效時，安全續接需要使用者重新交接同一列表。

本輪基線為 `d23cb522d69e50b722959d293754bbc299d0cf15`。實作目標是消除兩個有證據的派送前順序缺口，並讓 Agent 依正確的額度範圍接續。當次 LINE 控制與平台能力仍需實機證據，舊欠件與舊結果依原始追加紀錄保留。

## 修復設計

1. 在既有 `notesIntentDispatch` 範本加入只讀的 `checkDownloadReadiness({app, observation, windowBinding, branch, decision})`。Agent 先按 B1 以當次原件完成身分、返回、控制歸屬／啟用、前景、映射及額度判斷，再將正面證據傳給 helper。helper 檢查可機判的能力、欄位及 refs，不執行 CLI、不送輸入、不建 attempt，不生成或猜測視窗 ID。`READY` 才走現有 intent 命令。一般、精確恢復、既有 v5 或已確認 restart 各自照既有資格檢查。
2. 共用現行下載 helper 的 LINE app／已知視窗 ID 條件。檢查同一 app handle 有當次觀察及既有 click 能力，並確認已保存的 app-bound 觀察含原 AX／截圖 refs。直接分支檢查已核對的控制定位、座標空間、有限幾何與嚴格內點。隱藏分支檢查既有可執行 reveal 方法、當次前置 refs、安全區／映射及 ordinal／budget／prior refs。候選 2 另須當次 B1 判定新證據成立，且有證據引用。分支不足即失敗，保留具體 blocker。同次能力無法提供視窗 ID 時，記錄缺口並在 intent 前保留該項。使用標題、序號、檔名、假 ID 或透過外部工具找座標均無法替代當次原件。
3. 以同一 reference 範例展示取得當次已讀回觀察、執行檢查、STOP 與 READY 分支。意圖建立後仍重取當次原件或使用現有同次 reveal after，依 B1 重核對控制、視窗及映射。下載固定 slot 與唯一 input 邊界繼續由原 helper 驗證。當次判讀、輸入呼叫、native receipt、chooser／檔案結果各依現有證據記錄；一個階段的 pre-call blocker 無法替另一階段作結果判斷。
4. 限定本輪變更在 Skill、reference 的既有範本與對應測試。現有 CLI、帳本 schema／投影、固定 slot、Notes 與相簿入口及活資料留在原授權邊界。v5 額度仍於有效 intent append 時消耗。若某項於 intent 前停止，可靠返回且無全域 blocker 時，Agent 自主接續其他項；前景失效、無法安全隔離的 UNKNOWN、活動下載、未完成命名、LOCAL_CHANGED 或身分歧義仍須依既有規則停止。舊 UNKNOWN 按同一媒體的證據與額度進行既有有限查證／隔離。別項的 v5 不消耗此項額度；舊 v5 NOT_SENT 依已保存結果與既有精確恢復證據處理，額度不退還。
5. 當次已證實的可執行 reveal composition 為選中縮圖安全邊緣一次輸入及同次 after。新 hover adapter 或無視窗 ID 的派送契約，須先有可支持同等安全性的正面平台證據。兩者均不列入本切片。真實操作時由 Agent 自行讀當次工具能力、重新取得安全上下文，並記錄具體停止原因。

## 驗證與完成證據

- 直接定位、合法隱藏候選 1、具真正新證據的候選 2 均應通過。缺視窗 ID／`UNKNOWN`、錯 app、缺能力、缺觀察原件、缺控制定位或映射、無安全 reveal、額度不符、缺候選 2 的新證據均應拒絕。檢查本身零 click、零 capture、零 CLI、零 slot。
- 對照範例控制流。STOP 時正式流程不建立 intent，v5 恢復額度未被該流程消耗。CLI 直接呼叫的既有帳本契約、v5 append 額度及 UNKNOWN 隔離測試照常通過。加入雙媒體合成回歸，證明 A 的 v5 `NOT_SENT` 消耗 A 額度而不阻斷 B 的首次隔離與合格 v5，且未隔離 B 仍維持全域停止。離線證明範圍限於 helper 行為、範例及 CLI 回歸。
- 當次下載仍須通過既有同份觀察／after 綁定與一次呼叫。測試包含拒絕時不送 download click、合法成功分支使用固定 slot、舊或其他 after 不支持當次派送。
- 核對 Skill 主文、B1、CLI 派送順序，以及合法返回後接續其他項的規則語意一致。執行 notes CLI help、全套 notes tests、daily 相簿 records tests、`git diff --check`。
- 真實 LINE 下載、chooser、檔案基本檢查與 completion，以及同一正式 Prompt 的跨 Session 恢復均列 NOT_RUN。本回合只授權分析、計畫、修復及 Git 交付。當次前景、平台欄位來源與真實控制行為須在日常入口核對。
