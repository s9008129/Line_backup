# F01-S1 行為演練與結果

## 地位、版本與方法

本文件是 F01-S1 的 `V1` 離線行為演練，只核對修改後的 Skill／GUI／evidence 文件是否能把「來源已見卡片」帶到 page 與 finish 判斷。它不是 notes CLI 實作、CLI 自動拒絕證明、模型遵循率、GUI 操作、真實帳本、下載或獨立 Acceptance。

- 核准計畫：[plan.md](plan.md)，SHA-256 `58e38a4755717fc3c6ac39b82c49fd3c2c65c45e8bc662e05b0158e6f3620dfc`。
- 核准交接：[handoff.md](handoff.md)，SHA-256 `6ab8d3bb102ecd7329c7da3b0997e72b21ba8d3ad79c7dc6ea92a8392eca07b8`。
- 計畫簡潔性審查：[simplicity-plan-review.md](simplicity-plan-review.md)，審查結論只涵蓋計畫，不替代本切片驗收。
- 方法：Implementer 依修改後的三份產品文件，逐一閱讀合成來源觀察、擬 rows、page／finish 狀態及來源變動，先記來源→rows，再記 rows→來源，最後輸出停止或可到下一步的理由。每案保留可定位的合成區域、邊界及前後脈絡。沒有把預期答案寫進來源，也沒有呼叫 notes CLI 或 GUI。

本輪演練的「符合」只表示候選文字在這些合成輸入上導出計畫要求的決策，不表示任何模型或真實畫面必然照做。負例只要被允許 page／finish／新派送，V1 即失敗；本次沒有出現。

## C1：正常完整鏈

**合成來源。** 觀察 `S1/O1` 為合成頂端：卡片 `A` 完整，`B` 完整且下段接 `S1/O2` 頂端；`S1/O2` 為合成底端，`B` 與上一畫面為同一卡，`C` 完整。列表身分、頂端與底端有合成邊界標記。

**擬 rows。** `page 0: [A, B]`，`page 1: [B, C]`，`overlap_keys=[B]`。

**實際對帳。**

- 來源→rows：`A → page 0/A`、`B → page 0/B + page 1/B(overlap)`、`C → page 1/C`；無待解卡片。
- rows→來源：三個 row 都回到 `S1/O1` 或 `S1/O2` 的可區分區域；`B` 是同一張卡片的跨頁重疊，沒有算成新篇。
- 頁內順序為 `A, B, C`；跨頁尾 `B` 與下一頁頭 `B` 相同；頂底皆成立。

**判定。** `READY_FOR_FINISH_PRECONDITION`。這只表示 finish 前覆蓋條件成立，不是已呼叫 `finish`、已下載或已驗證檔案。

## C2：同時刻相鄰卡片與非下載附件

**合成來源。** 同一 viewport `S2/O1` 有兩張獨立卡片：`A` 顯示時間 `09:10`、內容 `alpha`、一般照片縮圖；`B` 也顯示 `09:10`，但作者列、卡片邊界與內容 `beta` 不同，只有附件圖示，沒有照片／影片縮圖；其後 `C` 完整。`B` 仍是列表貼文，只是不符合本次下載資格。

**擬 rows。** `page 0: [A, C]`。

**實際對帳。**

- 來源→rows：`A` 有 row，`C` 有 row，`B` 沒有 row；缺口位於 `A` 下邊界與 `C` 上邊界之間，是獨立可區分卡片。
- rows→來源：`A`、`C` 各自可回原件，但這不足以消除來源缺卡。
- 時間相同與「B 不下載」都沒有使 `B` 消失；`NO_MEDIA`／附件資格也不能改寫來源覆蓋。

**判定。** `STOP`。不呼叫 page／finish、不建立 intent、不開始照片或影片下載。將 rows 補成 `[A, B, C]` 並重新雙向核對後才可前進；此修正不改 `B` 的媒體分類。

## C3：高卡片與部分邊界

### C3-A：可唯一連接

**合成來源。** `S3/O1` 顯示高卡片 `H` 上段，`S3/O2` 顯示其中段，`S3/O3` 顯示其下段與下一卡 `N` 的作者列；`S3/O4` 是為解開 `N` 取得的連續小步補充，`N` 已完整。三段 `H` 以相同內容延續、上下邊界及相鄰卡片順序連接，`O1` 至 `O3` 的內容沒有越過另一張完整卡。

**擬 rows。** 同一 page `[H, N]`，`H` 只計一篇，`N` 只計一篇。

**實際對帳。**

- 來源→rows：`H` 的三個片段連到同一身分；`N` 作者列由 `O3` 延續到 `O4` 的完整卡；待解為零。
- rows→來源：`H` 回到三個片段組成的同一卡，`N` 回到 `O3/O4` 的同一邊界；沒有把片段另計新篇。

**判定。** `READY_FOR_PAGE_PRECONDITION`。允許為解卡而共頁的連續補充 viewport，不把 `O1–O4` 的多張新完整卡片事後併成模糊 page。

### C3-B：未解下一卡

**合成來源。** `S4/O1`、`S4/O2` 可證明 `H` 的前兩段；`S4/O3` 只露出與 `N` 相似的一條作者列，沒有共同內容錨點，也無法證明它是 `H` 的延續或 `N` 的開頭。

**擬 rows。** `[H]`，保留 `S4/O3` 為待解片段。

**實際對帳。** 來源→rows 少一個未解片段；rows→來源雖可回 `H`，但無法回答 `S4/O3` 是否為新卡。以「畫面相似」拼接或直接猜 `N` 會違反唯一對應要求。

**判定。** `STOP`。不提交該 page／finish，不以單一片段補假 row；保留待解並以小步補觀察，若仍不能唯一連接就交 Owner。

## C4：頁內中段漏篇（照片與影片）

### C4-P：照片篇

**合成來源。** `S5/O1` 顯示 `A`、`B-photo`、`C` 三張完整卡片，`B-photo` 有照片縮圖及獨立邊界。擬 `page 0: [A, C]` 可與前後頁 overlap，頂底也成立。

**實際對帳。** 來源→rows 缺 `B-photo`；rows→來源只有 `A`、`C`。CLI 即使能接受內部一致的 `[A, C]`，也不證明來源覆蓋；總數相同不提供外部真實總數。

**判定。** `STOP`。不呼叫 page／finish、不建立 intent、不下載。補成 `[A, B-photo, C]` 並重新雙向核對後，才是合格的正例；補全不會把這項算成已下載完成。

### C4-V：影片篇

**合成來源。** `S6/O1` 顯示 `A`、`B-video`、`C`；`B-video` 有影片指示及獨立邊界，沒有被 `+N` 或 viewer 總數取代。擬 `page 0: [A, C]` 的頂底、重疊與聯集均自洽。

**實際對帳。** 來源→rows 缺 `B-video`，理由只能是來源可區分但未入 rows，不能以媒體尚未就緒、影片不下載或頁面內部一致消除。rows→來源沒有對應 `B-video` 的 row。

**判定。** `STOP`。不提交 page／finish、不開始新派送；補入 `B-video` 後才重新對帳。影片驗證本身仍須另依原媒體 gate，不能由本離線案例代替。

## C5：缺重疊與相似片段

**合成來源。** `S7/O1` 顯示 `A` 的下段與一張只露作者列的卡片；小步移動後 `S7/O2` 顯示外觀相似的中段，但沒有共同卡片、邊界或可證明連續的相鄰內容。可能屬同一卡，也可能是新卡。

**擬 rows。** 候選 `[A, X]` 尚無唯一來源；若為了讓頁面有內容而猜 `X` 的 key，或把 `O2` 當成 `A` 的重複片段，均不成立。

**實際對帳。** 來源→rows 的 `X` 待解；rows→來源無法唯一回到 `O1/O2` 的同一卡或新卡；有序重疊未恢復。沒有可靠依據支持任何一個合併或拆分答案。

**判定。** `STOP`。以更小步距向回核對；未恢復時保持未完成，不以總數、相似外觀或新增 key 放行，也不宣稱整個列表完整。

## C6：來源變動且總數相同

**合成來源。** 第一次 `S8/O1` 為 `[A, B, C]`，擬 rows `[A, B, C]` 且原本可通過。完成前重讀 `S8/O2`：`B` 被編輯、`C` 與 `B` 重排，另有一張卡片調整使畫面總數仍是三張；既有 rows 沒有跟著改。

**實際對帳。** 來源→rows 已不是同一組可唯一對應的內容／順序；rows→來源無法同時解釋 `O1` 與 `O2`。剩餘卡片數相同不能證明覆蓋延續，改 key 或自稱「已更新」也不能覆寫前後差異。

**判定。** `STOP`。保存 `O1/O2` 的變動前後證據，覆蓋視為未成立，不呼叫 finish、不開始新派送、不改寫舊 scan；是否合法重掃或解除既有 gate 由 Owner 依原規則決定。

## C7：已知 F01 缺口重建

**合成來源。** 依診斷的公開結構重建 `S9/SOURCE`：`P04, P05, P06, P07, P08, P09`。其中 `P06` 位於 `P05` 的下段、互動列與時間之後，`P07` 的作者列之前；這是 `SYNTHETIC` 重建，引用診斷，不是本輪 GUI `OBSERVED`。

**擬 rows。** `page 2: [P04, P05, P07, P08, P09]`，頂底、相鄰 overlap 及聯集的內部一致性成立。

**實際對帳。** 來源→rows 缺少 `P05→P06→P07` 之間的 `P06`；rows→來源可解釋 `P04/P05/P07/P08/P09`，但不能讓 `P06` 消失。這正是舊 page 2 的失敗形狀；CLI 對輸入自洽的信心不等於來源完整。

**判定。** `STOP_AND_REPAIR_REQUIRED`。不呼叫 page／finish、不開始新派送；補成包含 `P06` 的未提交 rows 後才能通過本輪來源對帳。另做一個來源版本不含 `P06` 的對照時，不得為了「修好」而自行補出 `P06`；只能據該版本保留證據並另查身分／來源，不能把診斷中的舊 `OBSERVED` 冒充新版本畫面。

## 事實、推論、未知與限制

**事實。** 本輪七組案例均依三份候選文件完成來源、rows、雙向對帳與停止條件的文字推導；負例沒有被允許 page／finish／新派送，C1、C3-A 與 C4 的補全正例只在文字上顯示前置條件成立。案例的合成區域、邊界與判斷保存在本文件，未觸碰真實資料。

**推論。** 若 Agent 實際遵守候選文字，來源→rows 的頁內漏卡會先於 CLI 自洽而被暴露；但這只是一項行為假說，尚未有模型矩陣或實機證據。

**未知／NOT_RUN。** CLI 是否會接受某些自洽但不完整的 rows、Agent 在真實視窗的辨識率、跨模型遵循率、LINE 真實高卡片／同時刻案例、GUI、下載、帳本寫入、獨立 Acceptance 與 G-F01 均未執行。合成 fixture 不是真實歷史，也不改任何既有完成或 UNKNOWN。
