# 記事本導覽恢復修復與 Herdr 協作摘要

日期：2026-11-14（Asia/Taipei）。本文件是開發交付摘要，不是下載授權或真實 LINE 驗收。

## 意圖與根因

日常備份事故已有 51 篇卡片盤點、2 個 JPEG 完成基本檢查與 activation，另有 49 篇待媒體細盤；這些是既有提報事實，本次沒有重新操作或驗證私人資料。Agent 未依既有規則核對返回控制，連按兩次 Escape 後失去記事本入口。後續輸入通道回報 `noWindowsAvailable`，底層原因仍未知。

修復目標是讓 AI Agent 依 Skill 自主判讀畫面、單步返回及有限恢復；輸入能力確實不足時，只要求 Owner 開回同一列表並重新交接。不是建立固定座標腳本或另一套 GUI 控制器。

## 做了什麼

- 在記事本 GUI reference 集中維護返回契約、頁面／前景／能力分流、有限重新取得 app/window 及最小人工交接；Skill 與手冊連回相同規則。
- 進 viewer 前保存來源錨點，進入後核對返回控制；每次只返回一層，再重新觀察。AX 缺失時仍需當次視覺歸屬及映射，不猜按鍵或沿用舊座標。
- 分開 CUA handle 重新取得與 notes `bind`。真正前景中斷後，先核對新前景並以新 Session bind，再處理舊交易、必要的 scan interrupt 與新完整覆蓋；不以新 scan 解鎖 UNKNOWN。
- 在既有證據範本加入單次輸入保存 helper：request 寫入並讀回後才 invoke 一次，raw 與 diagnostic 分別保存；缺口不得冒充完整原件。
- 新增直接抽取文件內實際 helper 的合成回歸測試與匿名決策案例。
- 獨立反例發現 Symbol 自有錯誤欄位被漏存卻標為完整；只補偵測、缺口與不完整標記，保留其他可讀欄位，不將 Symbol 偽造成字串原件。

未修改 notes CLI、帳本格式、舊完成事實或相簿流程；未新增服務、GUI controller、固定座標流程或新的 CLI gate。新增 helper 只負責證據保存，不選擇下一個 GUI 動作，不重試、不派送下載。

## Herdr 多代理協作過程

| 角色 | 明確指定設定 | 工作及邊界 |
|---|---|---|
| 主代理 | 原 session | 梳理計畫、精確交接、監督差異與進度、分流問題、管理候選與交付；不把督導當獨立驗收 |
| Implementer | Codex，`gpt-6-luna`，`high` | 唯一產品寫入者；撰寫修復與必要測試、建立本機候選 commit |
| 獨立測試員 | Codex BYOK，`deepseek-v4.1-flash:1017`，`ollama_cloud`，`max` | 固定候選後獨立檢查及測試；不修改產品，不依賴實作者自測結論 |

1. 先將完整核定計畫與精確實作 prompt 保存於專案私有任務目錄，交接路徑與 SHA-256，避免只給摘要而遺漏邊界。
2. 依 Owner 指示建立 Implementer 分頁，之後移至主代理右側 pane；再於右下方建立獨立測試員 pane，讓 Owner 同時監看。
3. Implementer 最初以 workspace-write 啟動，寫入 `.agents/` 遭拒。保存阻塞證據並停止；Owner 明示同意後，在同一 pane 以 `--yolo` 恢復原 Codex session。此權限變更沒有解除 GUI／私人資料禁令。
4. 主代理校正一次事故報告來源誤讀，並在實作中檢查 Error 欄位、不可序列化回傳、接續順序與通用規則是否混入事故數字。
5. Owner 明確指定全部正式測試由 DeepSeek 執行。此後 Implementer 只實作及靜態核對；先前已自然完成的自測保留為歷史，不作獨立通過依據。
6. 候選固定後才交測試員。DeepSeek 發現 Symbol 欄位反例，保存拒絕報告；主代理依 Owner 授權將重現交 Implementer 修正，再交新 commit 複測。測試員未參與產品修改。
7. 第二次交接曾因主代理在最終凍結確認前取工作樹 hash，造成 manifest 與 commit 不符。保留阻擋證據後，改從固定 commit blobs 產生新 manifest，再獨立核對六個工作檔；產品 commit 未因此改變。
8. Owner 要求避免過度工程化。修正限於實證缺口；未為未知 GUI 狀態新增框架，也未把舊候選的 skip 推測成新候選結果。

模型證據須分層：上述設定有啟動參數及 UI 顯示證據；不據此宣稱供應商已證實後端模型、token 用量、費用、成本節省或平台隔離。

## 狀態與下一步建議

以下是整體交付狀態；獨立報告的 PASS 僅涵蓋其明示離線範圍。

| 狀態 | 值 | 範圍 |
|---|---|---|
| PRIMARY_OUTCOME_STATUS | PARTIAL | 修復候選已完成離線驗證，真實下載成果尚未確認 |
| IMPLEMENTATION_STATUS | COMPLETE | 計畫範圍內修復與 Symbol 修正已提交 |
| CORE_ACCEPTANCE_STATUS | PASS | 核定離線要求與實證反例 |
| REQUIRED_VERIFICATION_STATUS | PASS | 相稱的回歸與新候選複測；daily 適用範圍如上 |
| INDEPENDENT_ACCEPTANCE_STATUS | PASS | DeepSeek 獨立離線測試，不是實機驗收 |
| TASK_CLOSURE_STATUS | OPEN | 等待 Owner 以日常入口確認實際能力 |

下一步由 Owner 開好同一指定記事本列表，使用手冊唯一正式記事本 Prompt 交接前景，讓 Agent 依 Skill 接續；不另加 Harness Acceptance／E2E 啟動步驟。實機完整列表、影片、混合附件、即時 chooser、跨 Session 真實恢復與 CUA 底層輸入故障原因均未由本次離線工作證明，仍為 NOT_RUN／UNKNOWN。

本次沒有操作 LINE、讀取私人照片或真實帳本，也沒有下載或改寫交易。無關工作樹刪除保留，不納入提交。只推送功能分支；不合併 master。完成提交、推送與遠端精確 HEAD 核對後，依 Owner 指示關閉本次兩個代理 pane 及主 pane。
