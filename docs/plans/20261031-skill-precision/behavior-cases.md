# 離線行為案例與結果

## 方法及限制

同角色原生研究助手讀取候選手冊、Skill 及按情境所需 reference，在不操作 GUI、不讀真實備份資料及不修改檔案的前提下，回答下一步、是否問 Owner、停止範圍與證據。沒有提供預期答案給助手；由實作者將回答與核准計畫比對。這是合成文字推導，不是實際工具執行、模型遵循率統計或正式獨立 acceptance。派送未指定 model／effort；不據此推定 provider usage 或計算成本。

| 案例 | 助手實際推導摘要 | 與計畫比對 |
|---|---|---|
| 正式提交、無舊任務 | 核對真實列表／前景及歷史；確定新任務才建入口，盤點後自動下載，不等第二則指令 | 符合 |
| AX 看不到已開 popup | 補觀察既有 popup、驗證映射；不重開或重新索權 | 符合 |
| Save All 逾時 | 查原視窗／chooser／目的地；停止後續派送，不重點或另建 attempt | 符合 |
| 個別舊歷史受保護、另兩本合格 | 保留並跳過該本，繼續兩本；不報全列表完成 | 符合 |
| pending 命名交易造成保護 | 核對交易／hash，唯一狀態才 resume-naming，未解前不另送 | 符合 |
| 明確 UNKNOWN，後來照片完整 | decoder 唯讀驗證，分開報照片及無法提交 completion；不改寫或重下 | 符合 |
| 新 Session 同列表 | 新交接、bind、scan 及頂底／重疊；完成的跳過，不沿用舊定位 | 符合 |
| chooser 錯路徑 | 已核對 chooser 內修正完整空白路徑，讀回後才確認；不重新 Save All | 符合 |
| 到聊天且前景中斷 | 停全部 GUI，保存斷點，必要時請 Owner 重新交接；不搜尋／自動重開 | 符合 |
| STOPPED 且有初始恢復授權 | 核對停止未完成，引用原授權綁前次 attempt，保留原檔另建空目錄 | 符合 |
| 僅討論範本並口頭交前景 | 仍做文件工作，不操作 LINE；正式任務須另有範圍 | 符合 |
| 缺頁、同日期同張數不同卡 | 小步補接、用非名稱視覺脈絡區分，不合併；未解前不下載 | 符合 |

助手指出 backup-and-resume「開始下載前」仍泛稱受保護歷史跳過，可能單獨誤讀為可跳過 pending 命名交易。實作者已將該句限定為「個別舊證據不足」，並連至統一例外表；這是同角色機械澄清，不是正式審查拒絕或跨角色修復。修正後由實作者讀回，未另跑一輪模型案例；表中結果對應原回答，不冒稱已重測新版。

## 待人工安排的實機驗收：NOT_RUN

1. 新版文件精確 candidate 下，Owner 開啟同一列表（至少兩本合格未備份項），一次貼上範本，直到逐本驗證、completion 讀回與最終對帳，全程無追加開始／逐本下載指令。
2. 既有完成／排除／受保護項不重下，負向定位與前景案例不猜按或重送。不得為測試刻意破壞照片、製造不明派送或解除 UNKNOWN。
3. 新 Session 再交接同一列表，檢查新 scan 與已完成跳過。相簿級恢復須有真實且可證 STOPPED／NOT_SENT 的前次 attempt 才驗；沒有這種安全前提就維持 NOT_RUN，不以 UNKNOWN 或主動取消製造條件。
4. 分開保存 GUI 觀察、逐檔數量／穩定性／SHA-256／ImageIO、completion readback、daily 簿記及獨立驗收證據。舊 PASS 不轉移至新版。
