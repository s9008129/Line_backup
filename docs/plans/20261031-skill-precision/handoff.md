## 1. 目前能力與誠實界線

### 已具備的正確方向

1. `SKILL.md` 以問題導向的 router 將 Agent 導向 `backup-and-resume`、`daily-backup`、`inventory`、`visual-grounding` 或 `verified-experience`，符合按需載入。
2. 下載入口已收斂為 LINE 原生 `⋯ → 儲存全部`；`選擇項目`、單張或逐張下載不可替代。
3. 逐本流程已要求 `capture-group-name → capture-album-name → detail → intent → Save All → outcome → verify`，並在完成後保存 completion、讀回並對帳。
4. `daily` 只負責記錄、狀態投影、持久改名與驗證協調；它不授予 GUI 權限，也不觀察 LINE。
5. 已明定一次只處理一本、結果未知不重送、相簿級恢復使用新空白目錄、已完成／排除／受保護歷史不重下。
6. 已有前景中斷即停止 GUI 輸入、未知入口不猜 Escape／Command-W／關閉按鈕、popup 不可見時先查證等安全方向。

### 已觀察到的範圍

- 2026-10-31 在目前這台 macOS、目前 LINE 版本與目前 Computer Use 環境，曾使用本 Skill 完成一份 Owner 交接列表：5 本、86 張；檔案數量、連續命名、非空、穩定性、逐檔 SHA-256、ImageIO 完整解碼與 completion readback 均通過。
- 先前另有四本、141 張的獨立 E2E 紀錄；它的範圍不與本次 5 本合併，也不能互相升格。
- 「一份列表在已測試條件下可以完成」不等於任意 LINE 版本、縮放、多螢幕、帳號狀態、模型或 Session 都能成功。
- `daily summary` 的 PASS 是 Agent-attested 簿記，不是 OS 層 exactly-once 審計，也不是正式獨立 E2E PASS。
- 圖片可完整解碼不等於與 LINE 服務端原始位元完全相同。
- 本輪未執行新版 GUI 驗收；`real_line_e2e=NOT_TESTED`、`sensor_verified=false` 的工具語義不得被文字改寫成已驗證畫面事實。

## 2. 必須先釐清的一句話：「所有相簿」

本產品的正式範圍應明定為：

> Owner 當次交到前景、經 Agent 核對為同一個連續列表的所有尚未備份、未排除相簿。

它不是整個 LINE 帳號、所有群組、所有聊天室或所有歷史上曾出現的相簿。若 Owner 要處理多個列表，應分別交接每一個列表；Agent 不應自行搜尋、改配或跨越當前列表。

因此 Prompt 中的「所有相簿」應被理解為「這份已交接列表內的所有合格相簿」。若 Owner 的語意是帳號全域，這是新產品需求，不能在現行 Skill 中默默擴張。

## 3. 唯一支援的下載路徑

目前正式支援且授權的路徑只有這一條：

```text
已核對的相簿詳細頁
  → ⋯
  → 儲存全部
  → 資料夾選擇器
  → 前往本本新的空白目的地
  → 核對完整路徑
  → 單次確認
```

目前沒有其他經證明的 fallback。若找不到可辨識的 `儲存全部`、選單映射不可靠、locale 不同或 chooser 無法安全操作，應停止該筆輸入並保存證據；不得改用 `選擇項目`、單張下載、逐張下載、猜快捷鍵或重用舊座標。

如未來要支援其他入口，應另立需求並驗證身分、替代入口、重送風險、資料完整性與證據，不由 Agent 臨場發明。

## 4. Owner 最少需要明確提供什麼

Owner 不需要填模式、`RESUME`、JSON、座標、API 或逐本確認；但仍需要提供不可由 Agent 推測的授權與環境事實。下面分成「必須明示」與「可由本次任務或前次已有效紀錄沿用」。

### 4.1 必須明示或確認

| 項目 | Owner 需要表達的內容 | 為什麼不可由 Agent 猜測 |
|---|---|---|
| 任務性質 | 這是正式備份，不是 Skill 審查、文件整理或單純交出前景 | 審查與備份的 GUI 授權不同 |
| 範圍 | 只處理當次前景中的這一個相簿列表；若要跨列表需分別交接 | 防止操作錯列表或把「所有」擴張成全帳號 |
| 目的地 | `BACKUP_ROOT` 留空時使用目前專案根目錄的 `backup/`；若要其他位置，需是工具支援的專案內絕對路徑 | 保存位置與舊任務綁定不能由畫面猜測 |
| 排除 | `EXCLUSIONS=[]` 或明確的相簿辨識條件；`[]` 不解除既有排除 | 排除是資料政策，不應由縮圖或中文 OCR 自行決定 |
| 恢復 | 是否授權在確認中斷且未完成時，保留原檔並另建新空白目錄做相簿級恢復 | 恢復會影響資料處置與嘗試次數 |
| 前景合作 | 執行期間保持該 LINE 畫面在前景；Owner 要使用電腦時先要求 Agent 暫停 | Agent 不能在使用者接管後繼續依賴舊定位送輸入 |
| 禁止副作用 | 不發訊息、不刪除、不分享、不覆寫舊照片、不改寫舊完成事實、不操作其他列表 | 一般備份授權不包含這些不可逆或越界行為 |

### 4.2 環境前提；不是要 Owner 每次重填 Prompt

- LINE 已登入，指定的相簿畫面已由 Owner 人工開啟。
- 原生 Computer Use、輔助使用與螢幕擷取等所需權限在當次 Session 可用。
- 磁碟有足夠空間；目的地可建立並寫入。
- 若前次 Agent 程序已經結束，Owner 必須重新啟動 Session 並交回前景；Skill 不會自行喚醒程序。
- 若搬移造成舊任務路徑或目錄身分不符，Agent 保留原件並停止接續，不要求 Owner 填 JSON 或自行判斷下載結果。

### 4.3 建議的責任分工

**Owner Prompt 應只放：**

- 正式任務授權與範圍。
- 目的地、排除、恢復授權。
- 前景合作方式。
- 禁止副作用。

**Skill／references 應放：**

- 完整狀態機與 reference router。
- 每個工具的使用前提、成功訊號與停止訊號。
- 盤點、popup、chooser、下載、命名、驗證與 completion 的細節。
- 結果未知時的查證方式與不可重送規則。
- 固定回報節點與六類狀態的口徑。

這樣可避免 Prompt 與 Skill 各自維護一套互相矛盾的導覽細節，也降低模型因長篇重複指令而漏掉關鍵安全步驟。

## 5. 建議的 Owner Prompt 契約

以下是規格示例，不是本文件的執行授權；真正 GUI 操作仍需 Owner 當次交接有效前景。

```text
我授權本次正式 LINE 相簿備份，不是 Skill 審查。

範圍：只處理我現在交到前景的這一個相簿列表；其中所有尚未備份且未排除的相簿。不要搜尋或操作其他列表。
目的地：BACKUP_ROOT=；留空使用本專案內的 backup。僅使用已驗證、工具支援的專案內路徑。
排除：EXCLUSIONS=[]。

授權：可觀察、捲動、開相簿、每個 attempt 按一次「儲存全部」、操作資料夾選擇器、建立新空白目的地、下載、持久改名、本機驗證及保存進度；不必逐本再問我。
恢復：若確認先前已停止且未完成，保留原檔並另建新空白目錄做相簿級恢復；UNKNOWN 不重送。
禁止：其他下載方式、其他列表、訊息、刪除、分享、覆寫舊照片、改寫舊完成紀錄、push／merge／CI。

執行期間我會保持此 LINE 畫面在前景，不中途接管。若我需使用電腦，會先要求你暫停。若前景改變，你停止 GUI 輸入並保存進度。

找不到唯一可辨識的「儲存全部」、無法可靠定位、身分不明或結果未知時，先查證；仍無法解決就停止並告訴我一個具體問題，不要猜、不要換其他下載方式。

請在盤點完成、每本完成、遇到阻塞及最終對帳時回報。
```

這個 Prompt 不要求 Owner 提供群組中文名稱、座標、內部 ID、JSON 或逐本口令；那些應由 Agent 在授權內自行觀察、記錄與判斷。

## 6. 動態載入與工具路由

Skill 的 router 應讓 Agent 依「現在遇到什麼問題」載入最少且正確的 reference，而不是一次把所有細節塞進 Prompt。

| 當下情境 | 先讀什麼 | 使用的工具／能力 | 成功訊號 | 停止訊號 |
|---|---|---|---|---|
| 啟動、判讀前次任務、接續、完成檔案驗證 | `references/backup-and-resume.md`；需要 CLI 欄位時再讀 `references/daily-backup.md` | `daily memory`、目的地檔案核對、completion readback | 狀態分類與實際檔案相符，新的 intent 已讀回 | 路徑／目錄身分不符、紀錄衝突、工具拒絕 |
| 名稱取得、目錄布局、持久改名、名稱校正 | `references/daily-backup.md`；操作順序讀 `references/backup-and-resume.md` | `capture-group-name`、`capture-album-name`、`intent`、`verify`、`resume-naming` | 名稱只供顯示／路徑，交易讀回成功 | 名稱讀不到、來源不符、`FLAT_V1` 校正限制 |
| 列表頂底、漏卡、重複、排序變動 | `references/inventory.md` | 原生 CUA 觀察、重疊捲動、必要時離線 OCR | 有序清單、總本數、逐本狀態可對帳 | 入口不連續、覆蓋不足、疑似另一列表 |
| 入口判定、返回、開卡、選單、chooser | `references/verified-experience.md` | 當次原生 CUA；只在有可靠依據時使用已驗證快捷鍵 | 頁面／焦點符合預期，完整路徑已讀回 | 無可靠入口、身分不明、前景中斷 |
| popup 不可見、AX 缺標籤、座標映射不明 | `references/visual-grounding.md` | 當次允許的 AX／截圖／桌面觀察；OCR 只作輔助 | 唯一 Save All 與安全點位有當前證據 | 所有來源仍不能可靠定位；不盲點、不重用舊座標 |
| 結構化記憶、既有照片、身分未明項 | `references/daily-backup.md` | `daily` 唯讀查詢與紀錄工具 | 狀態、歷史與檔案證據一致 | 缺記憶、檔案漂移、來源不明 |

工具分工必須固定如下：

- **原生 Computer Use**：只使用當前 Session／平台文件明確提供的方法；不能把 repo 內舊座標或舊 Session 的 API 當成通用能力。
- **AX／截圖／輔助 OCR**：只用於觀察與定位；不得以群組中文名稱或中文 OCR 選列表、認領歷史或替代身分證據。
- **`daily.py`**：做結構化紀錄、狀態投影、持久改名與驗證協調；不授予 GUI 權限，也不證明使用者已按下 Save All。
- **ImageIO／SHA-256**：做數量、非空、穩定性、逐檔完整性與完整像素解碼；不是獨立 E2E，也不證明服務端原始位元相同。
- **資料夾選擇器**：只處理已核對的完整絕對路徑；不重用上次位置、不猜資料夾列、不把未知視窗的 Return 當通用確認。

若 router 找不到明確的一條路，Agent 應先唯讀查證，而不是同時載入互相矛盾的指令或自行發明工具。

## 7. 逐本狀態機

### 7.1 啟動與盤點

1. 讀 `.local/line-backup/active-task.json` 指向的真實 `backup-records` 與目的地。
2. 以 `daily memory` 讀取前次任務的結構化記憶、完成、操作與狀態。
3. 核對實際照片與目的地；不要用聊天記憶、Git 歷史、封存目錄或外層舊資料取代日常備份記憶。
4. 將前次狀態分類為：已完成、仍在下載、待驗證、確認已停止且未完成、結果未知、受保護歷史。
5. 依規則跳過已完成／排除／受保護；仍在下載的先觀察；待驗證的先驗證；確認停止且未完成的才依授權恢復；未知先查證且不重送。
6. 核對交接畫面是否為同一連續列表；不是列表、入口不明或疑似另一列表時，保留原視窗、停止依賴該定位的輸入，必要時問一個具體問題。
7. 從頂到底盤點，使用相鄰畫面重疊；保存總本數、逐本狀態與有序清單。名稱只用於顯示與目錄，不是身分判定。

盤點是備份必要階段，不是等待 Owner 再下令的獨立模式。盤點完成後，若入口與授權仍有效，Agent 應自動繼續下載。

### 7.2 每一本的順序

一次只處理一本：

1. 在同一列表先取得並保存一次群組顯示名，再對每本做視覺身分確認。
2. 取得相簿顯示名並保存；完全讀不到名稱時才問 Owner。
3. 以私有 evidence 記錄該本 `detail`，確認日期、張數與可區分視覺脈絡。
4. 以 direct `intent` 建立並讀回具名的新空白目的地，保存禁止重送紀錄。
5. 在該本詳細頁開啟一次 `⋯`；若已開啟，先觀察既有 popup，不再開第二次。
6. 用當次允許的觀察來源補足 popup／座標映射，確認唯一 `儲存全部`、安全點位與輸入來源。
7. 再確認授權、前景、身分、intent 讀回與未曾派送後，單次派送 Save All。
8. 立即觀察 chooser／進度／明確錯誤；呼叫成功不等於下載成功，逾時或畫面未變也不等於未派送。
9. chooser 顯示後，核對完整路徑與本本空白目錄，再單次確認。
10. 下載完成後，以 direct `outcome` 記錄第一個已知結果，再以 direct `verify --attempt-id` 持久改名；核對預期數量、連續命名、非空、穩定性、逐檔 SHA-256 與 ImageIO 完整解碼。
11. 保存完成紀錄、讀回，依當次可靠返回入口回到原列表並核對；接著才以新畫面定位下一本。
12. 每本完成即保存進度，不只依聊天上下文。

### 7.3 停止與恢復決策表

| 狀態 | 可以做的事 | 不可以做的事 | 應保存的證據／下一步 |
|---|---|---|---|
| 交接畫面不是已確認列表 | 唯讀觀察；有可靠返回入口時返回一次並核對原列表 | 用群組名稱、OCR 或猜 Escape／Command-W 改配列表 | 入口、焦點、可見控制項；必要時問 Owner 一個具體入口問題 |
| 詳細頁出處不明 | 保留原視窗，唯讀查證目前身分與來源 | 僅憑標題／日期／張數認領，或先下載再補證 | 詳細頁畫面、來源鏈、缺口；無證據就停止 |
| 找不到可辨識的 `儲存全部` | 改用當次允許的觀察來源查證 | 改用其他下載方式、猜選單列或重用舊座標 | 選單畫面、映射來源、缺失的具體能力 |
| popup 不可見或映射不可靠 | 觀察既有 popup、桌面／截圖等允許來源 | 重開選單、盲點、用固定 offset 當通用解 | 各來源回覆與最後安全判定 |
| 點擊結果未知 | 查原視窗、事件與目的地；分類為仍在下載、已下載待驗證或未知 | 第二次點 Save All、建立新 attempt／目錄解鎖 | 最後動作、時間、可能派送狀態；未知不重送 |
| chooser 路徑不符 | 依當次可靠流程修正或停止該筆輸入 | 用上次位置、猜資料夾列或未知 Return 確認 | 實際路徑、本本目錄、最後畫面 |
| 下載仍在進行 | 觀察既有進度與目的地 | 重送或建立另一個下載 | 進度畫面、檔案狀態與下一步觀察 |
| 已下載但未驗證 | 執行持久改名與逐檔驗證 | 重下、Finder 手改或改寫舊結果 | outcome、檔案清單、數量／雜湊／解碼結果 |
| 命名交易中斷 | 使用 `resume-naming` 並重驗 | 重新 Save All 或手動改名 | 原交易狀態、resume 結果與檔案證據 |
| 前景中斷或意外到聊天／不明頁 | 停止所有依賴舊身分／定位的 GUI 輸入；保存進度 | 自動重開、改配列表、連按快捷鍵 | 停止點、最後畫面、已保存進度；請 Owner 重新交接 |
| 疑似另一個列表 | 保留原視窗並請 Owner 釐清 | 以相簿名稱或中文 OCR 搜尋／改配 | 可見列表特徵與疑點，不擴及其他列表 |
| 已完成檔案漂移 | 保留來源，停止重下補帳，回報具體差異 | 覆寫、刪除、改寫舊完成事實 | 檔案差異、原始紀錄與保護狀態 |
| `UNKNOWN` 已寫入 | 唯讀查證；保留原檔與原狀態 | 以新目錄、新 attempt、零計數或改寫紀錄解鎖 | attempt 證據與工具回覆；必要時回報產品限制 |

## 8. 固定回報節點

「定期回報」需要具體化，避免 Owner 在長時間操作時誤以為 Agent 沒有執行。至少應在以下四個節點用白話回報：

1. **舊任務與入口核對完成**：前次狀態、目的地、入口是否為同一列表、是否需要恢復。
2. **盤點與總本數保存完成**：總本數、有序清單摘要、已完成／排除／待下載／先前未完成／未知／受保護歷史、將下載的第一本。
3. **每本完成或遇到阻塞**：目前一本、已驗證張數、剩餘數量；若阻塞，說明一個具體問題，不只說「失敗」。
4. **最終對帳完成**：列表是否確實看完、六類狀態是否相加等於總本數、哪些已驗證、哪些仍未解，以及是否真的可以宣稱本列表完成。

每本回報至少包含：

- 總本數
- 已完成
- 排除
- 待下載
- 先前未完成
- 未知
- 受保護歷史
- 已驗證張數
- 目前一本的狀態

對帳公式應維持：

```text
總本數 = 已完成 + 排除 + 待下載 + 先前未完成 + 未知 + 受保護歷史
```

只有列表確實看完、逐本對上，且待下載、先前未完成、未知與受保護歷史均為零，才可以回報「這次列表全部完成」。單本下載完成、文件規範通過或工具 exit 0，都不能單獨代替整批完成。

## 9. 必須維持的證據分層

下列五層不得互相冒充：

1. **GUI 觀察／操作**：Agent 看到什麼、做了什麼、輸入後畫面如何改變。
2. **照片檔案驗證**：檔案數量、順序、非空、穩定性、SHA-256、ImageIO 完整解碼。
3. **`daily` 簿記**：intent、outcome、verify、completion 與 summary；是 Agent-attested 的紀錄能力。
4. **Completion readback**：完成事件是否真的保存並讀回。
5. **獨立 acceptance**：另開主 Session、由 Owner 交接的正式 GUI 與 E2E 驗收。

`daily summary` PASS 不證明 OS 層 exactly-once，也不證明畫面沒有漏卡；影像可完整解碼不證明與服務端原始位元完全相同；一次成功列表不自動涵蓋所有環境。

## 10. 已知限制與不要繞過的地方

- 同一 attempt 的第一筆 `outcome` 不可改寫；曾寫入 `UNKNOWN` 時，即使後來檔案通過唯讀驗證，也可能無法提交 completion。這是產品限制，不以新目錄、新 attempt、零計數或改寫歷史解鎖。
- 跨 Session 恢復與名稱校正仍缺完整獨立驗收，不能寫成普遍已通過。
- Skill 不會自行喚醒已結束的 Agent 程序；Owner 仍需重新啟動並交回前景。
- 沒有 OS 層 exactly-once 審計；「一次派送」是 Agent 依證據遵守的規則，不是工具已簽發的保證。
- `FLAT_V1` 名稱校正目前不支援；不得在 Finder 手改或改寫紀錄繞過。
- 群組／相簿名稱只用於顯示與目錄；不得以名稱、縮圖或中文 OCR 取代本地身分、日期、張數與視覺證據。
- 若工具拒絕、身分歧義、目的地衝突、寫入衝突或結果未知，停止依賴該前提的動作，不換入口繞過。
