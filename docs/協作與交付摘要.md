# 記事本導覽修復與 Herdr 協作紀錄

日期：2026-11-14（台北時間）

這份紀錄說明修了什麼、怎麼分工，以及哪些事還沒確認。它不是下載授權，也不代表已在 LINE 實際操作成功。

## 為什麼要修

先前的紀錄顯示：51 篇貼文已完成列表盤點，其中 2 篇的照片已下載並通過基本檢查；另外 49 篇還沒逐篇檢查媒體。這些是既有提報內容，本次沒有重新查看私人照片或帳本。

當時 Agent 沒先確認畫面上的返回方式，就連按兩次 Escape。畫面因此離開記事本，回到群組聊天。之後，操作工具又回報找不到可用視窗。這次修正前，找不到視窗的原因仍不清楚。

修正的目標是讓 Agent 每次返回一個畫面後先重新查看，再決定下一步。如果操作工具真的不能用，就請使用者重新打開同一個記事本列表並交接畫面。這項修正依靠 Agent 閱讀當下畫面，不靠固定座標或自動點擊腳本。

## 修了什麼

- 先記下目前貼文與列表的畫面線索；進入照片檢視畫面後，先確認如何返回。
- 每次只返回一層，返回後先看畫面；不再猜按鍵，也不沿用舊位置。
- 把「重新找到 LINE 視窗」和「在系統中重新登記這次記事本工作」分開處理，避免把兩件事當成同一步。
- 如果使用者重新交接畫面，先確認記事本列表，再接續舊紀錄、處理尚未結束的工作，並重新盤點列表。
- 加入一個小工具，保存操作前的要求與操作後的結果，方便日後查對。若資料不完整，紀錄會明確標示不完整。
- 加入測試，檢查資料保存工具和容易出錯的案例。
- 獨立測試找到一種特殊欄位曾被漏掉、但紀錄卻顯示完整的情況。修正後，系統會標示資料有缺漏，不會假裝已完整保存。

這次沒有改記事本下載指令、永久紀錄格式、相簿流程或已完成的下載紀錄。也沒有新增背景服務、固定座標操作或新的下載關卡。小工具只保存證據，不會替 Agent 選畫面、重試操作或開始下載。

## 三個角色如何合作

主代理負責整理計畫、分派工作、檢查進度和統整交付。Implementer 負責修改產品。獨立測試員檢查固定版本的修改；測試員不改產品。

| 角色 | 使用設定 | 負責事項 |
|---|---|---|
| 主代理 | 原本的 Codex 工作階段 | 整理計畫、交接資料、監督修改、處理測試發現與交付 |
| Implementer | Codex；`gpt-6-luna`；推理設定 `high` | 修改功能、補上必要測試、提交候選版本 |
| 獨立測試員 | Codex BYOK；`deepseek-v4.1-flash:1017`；Ollama Cloud；推理設定 `max` | 檢查固定版本並執行核准的離線測試，不修改產品 |

這些設定有啟動參數和畫面紀錄可查。它們不能單獨證明模型服務商實際使用了哪個後端，也不能證明 token 用量、費用或省下多少成本。

## 合作過程

1. 主代理把核准計畫和實作指示存進專案的私人任務資料夾，並附上檔案位置和校驗碼，讓 Implementer 能找到完整版本。
2. 依使用者要求，Implementer 開在主代理右側；獨立測試員開在右下方，方便使用者同時查看。
3. Implementer 一開始沒有足夠權限修改 Skill 檔案，因此停止並留下紀錄。使用者同意後，才在原工作階段以較寬的本機權限繼續。這項同意沒有授權操作 LINE 或私人資料。
4. 主代理發現並指出幾個需要修正的地方，包括錯讀事故紀錄、錯誤資訊的保存方式，以及恢復工作的先後次序。
5. 使用者指定正式測試由 DeepSeek 執行。Implementer 之前已完成的自我檢查保留在紀錄中，但不算獨立測試通過。
6. DeepSeek 在第一個版本找到特殊欄位的漏存問題，因此拒絕該版本。主代理把可重現案例交回 Implementer 修正，再把新版本交給 DeepSeek 複測。
7. 第二次交接時，主代理太早檢查檔案校驗碼，當時檔案還在變動，導致清單和版本不一致。測試員因此停止測試。之後改用已固定版本的檔案重新製作清單，逐一比對後再測；產品版本本身沒有因此改變。
8. 使用者要求避免把修復做得過度複雜。最後只修正已找到的問題，沒有再為未知的畫面情況增加一套新系統。

## 測試結果

第一個候選版本 `e64d17ea7a85dd2d9dfd95eeaee491fc2ea98e48` 被獨立測試拒絕，原因是特殊欄位的漏存問題。

修正後的候選版本是 `4883604ad452b450977d35f71c617d3fa12987c1`。DeepSeek 對這個固定版本執行以下離線檢查，全部通過：

| 檢查項目 | 結果 |
|---|---|
| 記事本完整測試組 | 285 項通過，沒有跳過項目 |
| 證據保存工具測試 | 10 項通過；已包含在上面的 285 項中 |
| 獨立設計的錯誤案例 | 11 項通過，包含第一版失敗案例 |
| 記事本指令說明 | 正常顯示，結束代碼 0 |
| 相簿紀錄測試 | 73 項通過，結束代碼 0；這是在前一個候選版本執行，最終版本沒有重跑 |

測試使用專案內可寫的暫存位置，沒有更改電腦上的 Swift 工具。舊版本曾有 3 項測試跳過；當時沒有留下跳過原因，因此不能把那些測試算成通過。新版本重新執行後，285 項都有實際結果。

上述測試只確認離線工具和程式行為，不能證明真實 LINE 畫面操作成功。完整命令、測試輸出、版本校驗資料和測試報告放在專案私人任務資料夾：`notes-navigation-recovery-20261114`。私人原始資料沒有放進 Git 提交。
