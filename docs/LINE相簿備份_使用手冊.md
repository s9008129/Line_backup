# LINE 相簿與記事本備份：白話使用手冊

> **先說結論：** 你不需要懂程式、UUID、JSON 或命令列。你只要在 LINE 開好**一個正確的列表**，把本手冊的正式啟動指令貼到具備 macOS Computer Use 的 AI Agent 對話框，並在送出後把操作交給 Agent。盤點、下載、驗證與跳過完成項目由 Agent 依專案 Skill 執行；中斷接續會依紀錄嘗試，無法安全確認時會停止並保留現場。

> 本檔名 `LINE相簿備份_使用手冊.md` 是既有 Skill 與專案指令連結使用的入口，因此保留原名；內容同時涵蓋相簿與記事本兩條獨立流程。

**本手冊怎麼讀：** 第一次使用先看[共同準備](#開始前五個共同準備)，再選[相簿](#情境-a備份-line-相簿)或[記事本](#情境-b備份-line-記事本)；遇到中斷請看[接續方法](#中斷重開與換-session)，有錯誤訊息請查[異常處理](#異常處理看到什麼該怎麼做)。

## 先看這裡：60 秒選擇

| 你現在要做什麼 | 先打開哪個 LINE 畫面 | 使用哪份啟動指令 |
|---|---|---|
| 第一次備份一個群組相簿列表 | 群組相簿列表 | [從情境 A 開始](#情境-a備份-line-相簿) |
| 第一次備份一個記事本列表 | 單一記事本列表 | [從情境 B 開始](#情境-b備份-line-記事本) |
| 備份中斷、換對話或工作階段、電腦睡眠後要接續 | 重新打開同一個列表 | 貼原本使用的那一份；Agent 先查紀錄再決定能否安全接續 |
| 照片已搬到外接硬碟，或本機媒體區已刪除 | 打開同一個列表 | 貼原本使用的那一份；Agent 只確認過去已完成並標示本機副本目前不可用，不會重新下載；需要檔案時請從你的其他備份還原 |
| Agent 回報結果不明、檔案異常或工具錯誤 | 先不要重試 | 看[異常處理](#異常處理看到什麼該怎麼做) |

第一次使用請先完成下一節的共同準備，不要直接跳到附錄貼指令。

**三條安全紅線：**

1. **一次只處理一個列表。** 不要同時跑相簿與記事本，也不要同時備份兩個列表。
2. **相簿與記事本不可混用。** 兩者有各自的 Skill、啟動指令、下載入口、目的地與永久紀錄。
3. **結果不明時不要重送。** 不要自行重按「儲存全部」、換新資料夾、改名、刪檔或要求 Agent「再試一次」；先讓它查證。

## 這個專案是什麼？

這不是一個安裝後會常駐背景的 LINE 備份 App，而是一套**以 Skill 為核心的 Agent 工作流程**。

可以把整套流程想成一次受託整理與搬運：

| 角色 | 白話工作 |
|---|---|
| **Skill** | 給 AI 的專業工作手冊。它定義怎麼看畫面、怎麼判斷身分、何時可以下載、何時必須停止。 |
| **Agent** | 現場領班。讀 Skill、理解你的目標，依當次畫面決定下一步，並在授權範圍內完成整份列表。 |
| **Computer Use** | Agent 的眼睛與手。用來觀察 macOS 上的 LINE 畫面、捲動、點選與輸入。 |
| **小工具** | 倉管與驗貨員。保存交易與歷史、避免重複下載、計算雜湊、解碼檔案及核對結果；不操作 LINE，也不授予 GUI 權限。 |
| **永久紀錄** | 只追加的出貨簿。照片可以搬走，但完成、排除、未知與保護歷史不會因此消失。 |

因此，工具回傳成功不代表 Agent 已正確看畫面；Agent 回報完成也不能跳過檔案與紀錄核對。兩者必須一起成立。

## 兩條流程差在哪裡？

| 面向 | 相簿備份 | 記事本備份 |
|---|---|---|
| 目標畫面 | 群組相簿列表 | 單一記事本列表 |
| 備份內容 | 合格相簿內的照片 | 貼文內的照片與影片 |
| 不備份的內容 | 聊天文字、留言、其他列表 | 貼文文字本身、留言、貼圖、連結、PDF、Word、網頁文件及其他附件 |
| 一次處理的單位 | 一本相簿 | 一個媒體 attempt |
| 預設媒體位置 | `backup/` | `backup/記事本/` |
| 永久紀錄 | `backup-records/` | `notes-backup-records/` |
| 下載入口 | 相簿詳細頁的 `⋯ → 儲存全部` | 記事本當次畫面可證明的自身下載控制 |
| 恢復方式 | 相簿級新空白目錄恢復 | `outcome`、`reconcile`、`resume` 與精確 restart 批次 |
| 目前狀態 | 有特定 macOS Computer Use Session 的實機操作紀錄（`OBSERVED`），但非所有環境通用 | 分支預覽；完整列表 GUI E2E、影片、混合附件與跨 Session 仍為 `NOT_RUN` |

不要因為兩個畫面看起來相似，就把相簿的按鈕、選單、chooser、座標或紀錄套到記事本。反過來也一樣。

## 開始前：五個共同準備

### 步驟 1：在正確的專案啟動 Agent

1. 開啟你使用的 AI Agent／AI 助理，並以本專案 `Line_backup` 為工作目錄開一個新對話。本專案不綁定單一 AI 品牌，但這個 Agent 必須**能讀取本專案的 Skill 檔案**，而且具備**原生 macOS Computer Use**；只有純文字聊天能力、不能載入 Skill 或不能操作視窗的助理，不能執行備份。
2. 第一次使用時，打開 macOS 的「系統設定 → 隱私權與安全性」，確認實際執行 Agent 的 App 或 Terminal 已取得「螢幕錄製」（有些版本顯示為「螢幕與系統音訊錄製」）與「輔助使用」權限。macOS 清單不一定會出現一個名叫「Agent」的項目，請授權給真正執行 Computer Use 的程式；改動權限後通常要完全結束並重新啟動該程式。
3. 先做一次不操作的預檢：請 Agent 只讀取 `.agents/skills/line-album-agent-cua/SKILL.md`（記事本改用 `.agents/skills/line-notes-agent-cua/SKILL.md`），並確認能看到 LINE 視窗標題；在它回報可讀取 Skill 與畫面之前，不要提交正式啟動指令。若 Agent 回報看不到 LINE、不能操作視窗或缺少工具，先停在原畫面處理；不要改用其他下載入口或自行點選來繞過。

只有對話能力、沒有 GUI 能力時，Agent 只能討論，不能實際備份。若 Agent 為了觀察 LINE 彈出視窗而需要截取桌面局部，其他可見視窗也可能暫被拍到；開始前請先關閉私人視窗。這些證據只保存在本機專案的私有區域，不上傳外部 OCR／雲端服務。

日常備份使用本手冊的正式啟動指令，不需要另外交接開發計畫、Git 分支、測試報告或 Acceptance／E2E 角色文件。

### 步驟 2：只打開一個正確列表

- **相簿：** 打開本次要備份的群組相簿列表。畫面應該是一排相簿卡片，不是聊天室，也不是單本相簿內頁。
- **記事本：** 打開本次要備份的單一記事本列表。畫面應該是貼文列表，不是相簿列表、聊天室或單一媒體檢視頁。

不確定是否開對時，先停在原畫面讓 Agent 核對。不要用群組中文名稱、日期、張數或封面自行猜測。

### 步驟 3：決定要不要改媒體位置

不確定就留空，使用預設位置：

- 相簿照片：專案根目錄的 `backup/`。
- 記事本照片與影片：專案根目錄的 `backup/記事本/`。

若要用其他位置，填工具支援的**專案內絕對路徑**，例如 `/Users/你的名字/dev/Line_backup/我的備份`。不要只填資料夾名稱，也不要填 `~/...`；不確定就留空。永久紀錄由 Agent 自動管理；不要把紀錄位址填進媒體位置欄位。

### 步驟 4：複製對應的正式啟動指令

- 相簿：[附錄 B](#附錄-b相簿正式-prompt)。
- 記事本：[附錄 C](#附錄-c記事本正式-prompt)。

只修改最上方的備份位置；相簿的 `EXCLUSIONS` 初次請保持 `[]`。只有 Agent 完成盤點並提出精確候選後，才依它的指示修改排除欄位。中間的任務範圍、授權、資料保護與停止條件請整段保留，不要自行縮短、翻譯或重寫。指令很長是正常的：它是任務合約，不是給你逐行閱讀的程式碼。

### 步驟 5：在 Agent 對話框送出，並交出現場

把 LINE 開在正確列表，不要關閉或最小化；切到 **AI Agent 的對話框**，貼上啟動指令並送出。**不要貼到 LINE 聊天室。** 送出後由 Agent 重新帶出 LINE 並接手操作，請不要搶滑鼠或鍵盤。

> **提交這個動作，同時代表你只授權 Prompt 指定的這一個列表與本次備份範圍，並交接當下的 LINE 前景。** 不包含其他列表、其他流程或整個 LINE 帳號；也不需要再補一句「開始下載」。

Agent 會先核對畫面、列表身分與永久紀錄，再開始盤點。盤點可能花一些時間；畫面暫時沒變不代表卡住。除非 Agent 要你處理一個具體問題，否則不要在備份期間接管滑鼠、點 LINE、按「儲存全部」或移動正在下載的檔案。

> **要立即停止時：** 先按 Agent 的停止／暫停按鈕（若有），或在 Agent 對話框輸入：「立即停止所有 GUI 操作；不要重送、改寫或刪除紀錄；保存目前 intent／outcome 與畫面證據，回報最後安全狀態。」不要直接按掉下載視窗或強制關機；若不得已必須強制關閉，請保留原檔與紀錄，下次不要當成「沒有下載」而重送。

> 若你不小心使用 Acceptance／E2E 角色 Prompt，Agent 應先提醒：「本專案使用日常正式備份 Prompt 確認 Skill 的實際能力；Acceptance／E2E 角色 Prompt 會引入不同的角色限制，請使用手冊中對應的正式 Prompt。」提醒不是新的下載授權，也不會取代當次的前景交接。

## 情境 A：備份 LINE 相簿

### A1. 開始前要看到什麼

你應該看到本次要備份的**相簿列表**。Agent 需要從這個連續列表辨識每一本相簿，因此請不要先開到單本相簿內頁，也不要先選照片。

### A2. 啟動指令的兩個欄位

| 欄位 | 怎麼填 | 留空時 |
|---|---|---|
| `BACKUP_ROOT` | 要自訂照片位置時，填工具支援的專案內完整絕對路徑。 | 使用專案根目錄的 `backup/`。 |
| `EXCLUSIONS` | 建議保持 `[]`。若確實要排除，先讓 Agent 完成盤點並提出精確候選，經你確認那本相簿的身分後再描述；不要只憑日期、張數或封面自行猜測。 | `[]` 表示沒有新增排除，不會解除既有排除或歷史保護。 |

不要填 UUID、座標、API key、內部 JSON 或群組中文名稱。Agent 會從畫面、當次入口與永久紀錄自行核對列表身分。

### A3. Agent 會替你做什麼

1. 查全部相簿帳本與最近任務，核對目前列表和歷史狀態。
2. 從列表頂端盤點到底端，用相鄰畫面重疊、共同卡片與邊界證據避免漏卡或重複。
3. 逐本核對相簿身分、日期、張數與詳細頁；已完成的跳過。
4. 對每個合格相簿的新 attempt 先保存下載交易與新空白目的地，再開 `⋯`、確認選單，並將「儲存全部」最多派送一次。
5. 下載完成後核對目的地、穩定檔數、非空檔、逐檔 SHA-256 與 ImageIO 完整像素解碼。
6. 保存完成紀錄並讀回；下一次啟動不必重下已完成相簿。
7. 遇到已授權且可確認的中斷，保留原檔並在另一個新空白目錄做相簿級恢復；結果不明的派送不重送。
8. 最後用白話回報盤點、逐本結果、未解項目與驗證界限。

你不需要逐本說「開始」、逐本選資料夾，也不需要自己按「儲存全部」。

### A4. 什麼情況才算完成？

一份好的完成回報應該讓你看得出：

- 這次是哪一份相簿列表，以及入口是否已核對。
- 盤點到幾本相簿，以及六類狀態各有多少。
- 每本相簿下載到哪裡、已驗證多少張照片。
- 哪些項目尚未解決；有未解項目時，不能宣稱整份列表全部完成。
- GUI 觀察、照片驗證、完成紀錄與未測能力是不同層級的證據。

照片可完整解碼，代表這次指定檔案的完整性檢查通過；不代表與 LINE 伺服器上的原始位元完全相同。

### A5. 什麼時候應停止？

- 列表身分、入口或前次是否已派送無法確認。
- 下載結果不明，或檔案目錄出現缺檔、額外檔、內容漂移、symlink 等異常。
- 當前相簿已有 `UNKNOWN`、活動下載或未完成的命名交易。
- 儲存空間不足、權限不足，或工具回報無法安全完成。
- Agent 想改用單張、逐張或其他相簿流程作為替代下載入口。

遇到上述情況時，保留原檔與畫面，讓 Agent 查證。不要自己重按、換資料夾、改寫紀錄或建立新的空白相簿。

## 情境 B：備份 LINE 記事本

### B1. 開始前要看到什麼

你應該看到本次要備份的**單一記事本列表**。Agent 會先盤點整個列表的貼文，再逐篇辨識照片與影片，不是只下載目前打開的那一張圖片。

不要使用相簿列表、聊天室或單一媒體檢視頁作為記事本入口。記事本也不得把相簿的 `⋯ → 儲存全部`、相簿選單、按鈕、chooser 或座標當成 fallback。

### B2. 啟動指令的欄位

| 欄位 | 怎麼填 | 留空時 |
|---|---|---|
| `NOTES_BACKUP_ROOT` | 要自訂照片／影片位置時，填工具支援的專案內完整絕對路徑。 | 使用專案根目錄的 `backup/記事本/`。 |

永久紀錄會放在另一個獨立位置 `notes-backup-records/`，不會與相簿紀錄混在一起，也不需要你手動搬移或填寫。

若這個列表有影片，Agent 需要在開始下載前確認 `/opt/homebrew/bin/ffmpeg` 與 `/opt/homebrew/bin/ffprobe` 都存在、可執行且屬於同一組固定版本。缺少工具時，照片可能仍可處理，但影片不能算完成；請讓 Agent 先回報缺少項目，由維護者處理，不要自行改用 PATH 中的其他版本。

### B3. 會備份什麼，不會備份什麼？

- **會備份：** 貼文內的照片與影片。
- **只盤點、不下載：** 純文字貼文；它會記為貼文層 `NO_MEDIA`，不是下載完成。
- **不備份：** 貼文文字本身、留言、貼圖、連結、PDF、Word、網頁文件及其他附件。
- **不跨列表合併：** 名稱、日期、張數、序號或單一檔案雜湊，都不能單獨認領另一個列表的歷史。

> **格式與工具限制：** 目前嚴格照片驗證只接受 JPG／JPEG／PNG；HEIC、WebP、TIFF、GIF 等格式可能只保留原檔，不能算完成。影片需要固定的 Homebrew `ffmpeg`／`ffprobe`；缺少工具或解碼失敗時會停下並回報。影片與混合照片／影片附件目前也還沒有真實 GUI E2E 證據。

### B4. Agent 會替你做什麼

1. 查全部記事本帳本、最近任務與相符的永久記憶，核對目前列表身分。
2. 新列表在沒有缺損歷史或候選歧義時自動初始化；既有列表綁定原帳本。
3. 先處理舊的未決交易，再從列表頂端到底端完整盤點貼文與媒體。
4. 依紀錄跳過已完成項，對每個合格媒體一次只處理一個 attempt。
5. 下載前先保存並讀回 intent、新的空白目的地與「可能已派送」紀錄；記事本自己的下載控制與 chooser 最終確認各最多一次。
6. 下載後先保存第一筆結果，再依 `DOWNLOAD_FINISHED`、`UNKNOWN`、`reconcile`、`resume` 等狀態分流；沒有收斂前不驗證、不建立新下載、不派下一項。
7. 照片使用 ImageIO 完整像素解碼；影片使用固定成對的 Homebrew `ffmpeg`／`ffprobe` 檢查有效影像串流並完整解碼。
8. 最後回報貼文總數、`NO_MEDIA` 篇數、六類媒體狀態、已驗證照片／影片數、本機不可用或內容異常項與未解缺項。

### B5. 什麼情況才算完成？

完成回報應該包含：

- 列表、貼文、媒體三層身分是否完成核對。
- 貼文總數、來源逐卡對帳結果與未解缺頁。
- `NO_MEDIA` 篇數、六類媒體狀態及目前項目。
- 已驗證照片數、已驗證影片數。
- `LOCAL_MISSING`、`LOCAL_CHANGED` 等本機可用性，與仍待處理的項目。
- 工具簿記、ImageIO／ffmpeg 解碼結果、真人觀察與真實 LINE E2E 分開列示。

有未解項目時，只能回報部分完成，不能宣稱整份列表全部完成。

### B6. 特殊停止條件

- `UNKNOWN`、活動下載或未完成命名交易，在查證收斂前不得重送、驗證或派下一項。一般情況如此；記事本唯一的精確 restart 例外見本節下一條。
- 記事本若提出「精確重啟批次」，Agent 必須先列出受影響列表、貼文／媒體、舊位置、新 `versions/gNNNNNNNN/` 目錄、額外空間、缺項與保留項；只有你對該精確範圍明示同意，才可繼續。沉默、逾時或一般「繼續」不是同意。
- 記事本：整篇完成目錄不見時記 `LOCAL_MISSING`，保留完成且禁止重下；目錄仍存在但有缺檔、非屬合格環境附屬項的額外檔、內容／身分漂移或 symlink 時記 `LOCAL_CHANGED`，保護原件並停止未確認的新派送。
- `INTERNAL_ERROR`、`UNEXPECTED_EXCEPTION` 或工具退出碼 70 是未預期錯誤，不是可重試的業務拒絕。停止並保留命令輸出、畫面與紀錄，不要重送、改寫 ledger、建立新 attempt 或換目的地。

## 中斷、重開與換 Session

### 最簡單的接續方法

1. 重新打開同一個相簿列表或記事本列表。
2. 確認 LINE 已登入，且畫面在前景。
3. 切到 Agent 對話框，貼上原本使用的那一份啟動指令並送出；由 Agent 重新帶出 LINE。
4. 保留已下載檔案、暫存目錄與永久紀錄，不要自行清理或重建。

Agent 會從永久紀錄找回前次任務；你不需要填 `RESUME`、回想上次做到哪一本，或重新說明整個任務。

| 情境 | 你可以做什麼 | 請不要做什麼 |
|---|---|---|
| Agent 程序結束、Session 關閉或電腦睡眠 | 重開同一列表，貼原本的啟動指令。 | 不要刪除下載到一半的檔案，也不要另開新資料夾重來。 |
| 你需要使用電腦，前景被中斷 | 先請 Agent 停止新增 GUI 操作並保存進度；處理完再交接同一畫面。 | 不要讓 Agent 在背景繼續點選，也不要把重新交接當成重送許可。 |
| 不確定下載是否已送出 | 請 Agent 查原事件、目的地與當次畫面。 | 不要叫它「再試一次」，也不要自己按「儲存全部」。 |
| 下載結果不明 | 保留現場，先查證；證據不足就停止並回報。 | 不要換新目錄、重置紀錄、改寫狀態或重送同一項。 |
| 完成後本機媒體目錄不見 | 保留完成紀錄；Agent 會另報本機不可用。 | 不要要求重下，也不要宣稱外接硬碟副本已驗證。 |

### 記事本列表入口失去時

若 Agent 回報 `HANDOFF_REQUIRED`，請把同一個指定記事本列表帶回前景，再提交手冊中的正式記事本 Prompt。你不必提供 UUID、JSON 或逐篇指令。重新交接不代表重送下載許可；Agent 會先唯讀查歷史並核對新前景與列表，再以新 notes Session 執行 `bind`。`bind` 成功後才收斂舊交易；若仍有 open scan，再明確 `scan interrupt`，最後以普通完整掃描接續。未綁定前不寫 outcome／reconcile。

若 Agent 只回報 CUA app／window handle reacquire，且前景仍有效，這不會重跑 notes `bind`。若前景確實中斷，重新交接後會使用新的帳本 Session ID。Agent 不會用猜測按鍵、舊座標、全螢幕切換或測試輸入恢復入口；輸入通道仍失效時只會要求上述最小交接。

## 看到這些狀態，代表什麼？

### 六類業務狀態

每一本相簿或每一個媒體只能歸入一個目前狀態：

相簿的 `daily.py` 原生投影只有 `COMPLETED`、`EXCLUDED`、`INCOMPLETE`、`UNKNOWN`、`PROTECTED_HISTORY`；它的 `PENDING` 與 `PREVIOUSLY_INCOMPLETE` 是 Agent 依證據再從 `INCOMPLETE` 拆分的回報類別，不是你需要手動填寫的欄位。記事本 `notes.py` 則直接保存六類狀態。

| 狀態 | 白話意思 | 會不會重下？ |
|---|---|---|
| `COMPLETED` | 已下載、驗證並保存完成紀錄。 | 不會。 |
| `EXCLUDED` | 已有有效排除決定並保留來源。 | 不會。 |
| `PENDING` | 已盤點、符合資格，但尚未派送。 | 可在本次授權與排程中處理。 |
| `PREVIOUSLY_INCOMPLETE` | 先前明確停止或未完成，需要受控恢復。 | 先依 Skill 恢復，不是一般新下載。 |
| `UNKNOWN` | 可能已送出，但結果無法確認。 | **不會自動重送。**必須先查證。 |
| `PROTECTED_HISTORY` | 舊資料證據不足，先保護而不升格為完成或排除。 | 不會。 |

「已人工備份」是來源註記，不是第七類。只有工具能依既有規則認定完整證據時才算 `COMPLETED`；只有 Owner 聲明或照片存在、但證據不足時，屬 `PROTECTED_HISTORY`。人工聲明不能覆蓋既有 `UNKNOWN`、`PENDING` 或未完成的交易。

### 本機可用性不是業務狀態

`LOCAL_MISSING` 與 `LOCAL_CHANGED` 是貼在狀態盒外的「本機位置」標籤，不是第七類，也不是下載完成。

| 標記 | 白話意思 | 安全處理 |
|---|---|---|
| `VERIFIED_PRESENT` | 本機檔案目前存在，且與對應完成紀錄的檔名、大小、時間戳與 SHA-256 相符；不是本次重新完整解碼。 | 可依紀錄保留。 |
| `LOCAL_MISSING` | 完成紀錄仍在，但整份本機目錄目前不在。 | 保留完成、禁止重下；外接副本未經驗證。 |
| `LOCAL_CHANGED` | 目錄仍在，但有缺檔、額外檔、內容或身分漂移、symlink 等異常。相簿不接受任何額外檔；記事本僅對規則可辨識的合格環境附屬項保留特定例外。 | 相簿保護原件並停止；記事本先提出精確 restart scope，經你明示同意後才可另建版本目錄；不要自行修補或改名。 |
| `NOT_APPLICABLE` | 這項沒有可套用的本機媒體狀態。 | 不當成完成或失敗。 |

相簿與記事本都遵守「完成事實與本機可用性分開」；但兩邊的欄位與恢復流程不可互換。

| 你會看到的情況 | 白話意思 | 你可以做什麼 | 請不要做什麼 |
|---|---|---|---|
| 無法確認列表或入口 | Agent 不確定目前畫面是不是你要備份的那一份。 | 保持原視窗，重新開好指定列表再交接。 | 不要用名稱、日期或張數硬猜，也不要叫它直接下載。 |

## 檔案與永久紀錄放在哪裡？

### 預設位置

| 流程 | 預設媒體位置 | 永久紀錄位置 |
|---|---|---|
| 相簿 | `backup/<相簿目錄>/` | `backup-records/<列表識別>/` |
| 記事本 | `backup/記事本/` | `notes-backup-records/<列表識別>/` |

`backup/` 是兩條流程共用的媒體父目錄，不是單一相簿資料夾。相簿與記事本的媒體都在它底下；不要用「清空 `backup/`」的方式整理，否則可能同時刪掉另一條流程的媒體。

`.local/line-backup/active-task.json` 與 `active-notes-task.json` 只協助 Agent 找回最近任務，不是唯一歷史來源。即使它們不見，也不代表沒有紀錄；Agent 會重新查全部帳本。

### 可以搬照片，但不要刪紀錄

- 照片與影片可以複製到外接硬碟，或在你確認**某個特定相簿或貼文子目錄**已有可讀副本後，只整理那個子目錄；不要刪除整個 `backup/`。
- **不要刪除** `backup-records/`、`notes-backup-records/` 或 `.local/line-backup/`。它們保存完成事實、來源與接續依據。
- 不要用手編輯 JSON、把帳本搬到另一個專案，或互換相簿與記事本紀錄。
- 專案整個搬移後，若 Agent 發現舊路徑或身分歧義，先讓它安全對帳；不要手改歷史或重新下載。

只保留完成歷史，不代表本流程已驗證你的外接硬碟副本。外接硬碟不需要在線，才能查詢歷史或跳過已完成項目。

## 完成回報怎麼看？

一份可信的回報會把不同層級分開說：

- **GUI 觀察：** Agent 看見什麼畫面、如何認出列表與項目。
- **下載結果：** 是否明確完成、停止、未送出或結果不明。

如果 Agent 只說「已啟用」、「應該完成」或「全部備份好了」，卻沒有列出列表身分、盤點、逐項結果與未解項目，先要求它依 Skill 重新核對，不要直接相信或自行補操作。

## 常見問題

### Q1：我需要看懂整份啟動指令嗎？

不需要。你只要看懂最上方的備份位置，並在正確畫面提交。中段是 Agent 的任務範圍、授權、資料保護與停止條件；它是為了避免 Agent 把日常備份誤當成開發驗收，或在不確定時亂重送。

### Q2：同一份啟動指令可以一直用嗎？

可以。首次、下次、新 Session、換模型，以及 Agent 修正後的試用，都使用同一份相簿或記事本指令。差異由永久紀錄與當次畫面決定，不需要你手動選「新模式」。

### Q3：重複貼啟動指令會不會重複下載？

不會因為重貼就自動重下已完成項目。Agent 會先查永久紀錄、核對列表與本機檔案，再跳過已完成項目。但若前次結果不明、工具缺少、來源到期或交易未完成，重貼也不能保證本次一定成功；Agent 應如實回報。

### Q4：需要另外發一則「開始下載」嗎？

不需要。正式啟動指令提交時已包含本次授權與前景交接。你只要確認提交當下 LINE 停在正確列表。

### Q5：可以一次備份很多列表，或相簿與記事本一起跑嗎？

不可以。一次只處理一個列表；相簿與記事本各自使用自己的 Skill、工具、目的地與紀錄。完成一份列表後，再開下一份列表並使用對應入口。

### Q6：我需要提供群組名稱、UUID、座標或 JSON 嗎？

不需要。Agent 以當次畫面、連續入口與永久紀錄核對身分。名稱、日期、張數、序號或單一檔案雜湊都不能單獨認領歷史。若畫面有歧義，Agent 會提出具體問題。

### Q7：備份完成後，我可以自己改名或整理資料夾嗎？

媒體檔案可依你的保存習慣另存；但不要在 Agent 尚未完成或結果不明時移動、改名、覆寫下載中的檔案。新格式相簿若需要名稱校正，應交給 Agent 依 Skill 處理；不要自己在 Finder 改名。無法安全校正時，保留原名比破壞紀錄好。

### Q8：驗證通過是否等於和 LINE 伺服器上的原始檔完全相同？

不完全等於。驗證包含檔數、非空、雜湊、完整解碼與完成紀錄讀回，能證明這份本機檔案在指定範圍內一致；但不能證明服務端位元完全相同，也不等於外部硬碟副本已驗證。

### Q9：如果我需要使用電腦，該怎麼辦？

先請 Agent 停止新增 GUI 操作並保存進度。你處理完後，把 LINE 開回同一列表，切到 Agent 對話框貼同一份啟動指令並送出，讓 Agent 重新帶出 LINE。重新交接只恢復同一任務的操作前提，不是新的下載授權；若改變列表、目的地或擴張範圍，仍需新的明確授權。重新交接也不會自動解除 `UNKNOWN` 或已完成保護。

### Q10：備份到一半可以關掉 LINE 或 Agent 嗎？

可以關，但請先請 Agent 在安全節點停止新增 GUI 操作並保存進度，保留已下載的檔案與永久紀錄，下次用同一份啟動指令接續。不要刪除暫存目錄、重建空白紀錄或自己重按下載。若 Agent 已送出下載但結果不清楚，先保留證據查證，不要強制關閉後當成「沒下載」。

## 附錄 A：為什麼啟動指令要寫這麼長？

啟動指令是 Agent 的任務合約，不是給人閱讀的程式碼。它會同時交代：

1. 這次是實際備份，不是開發驗收或其他角色流程。
2. 要處理哪一份列表、使用哪個預設或自訂位置，以及哪些項目不納入。
3. 允許 Agent 在範圍內自行盤點、下載、驗證與恢復，不必逐本請示。
4. 哪些動作禁止，例如發訊息、刪除、分享、跨列表、改寫歷史或繞過工具拒絕。
5. 下載結果不明、來源到期、前景中斷或本機檔案異常時要如何停止與回報。
6. 完成時要提供哪些盤點、結果、未解項目與驗證界限。
