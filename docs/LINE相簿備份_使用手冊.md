# LINE 群組相簿與記事本自動備份：使用者手冊

> **先說結論：** 你不需要懂程式、UUID、JSON 或 CLI。你只要開好正確的 LINE 畫面，複製這份手冊提供的 Prompt 給 Agent，並在備份期間保留 LINE 前景。盤點、下載、驗證、跳過已完成項目與中斷接續，由 Agent 依專案 Skill 執行。

這份手冊是給人看的操作指南，不是 Agent 規格書。Agent 的詳細操作規則在對應的 Skill；你不需要手動執行命令，也不需要自己判斷下載是否成功。

## 30 秒快速判斷

| 你現在想做的事 | 先打開哪個畫面 | 使用哪份 Prompt |
|---|---|---|
| 第一次備份一整個 LINE 群組相簿列表 | 群組相簿列表頁 | 附錄 B：相簿 Prompt |
| 第一次備份一個 LINE 記事本列表 | 單一記事本列表頁 | 附錄 C：記事本 Prompt |
| 備份被中斷，想接續 | 重新打開同一個列表 | 貼原本使用的那份 Prompt |
| 換了 Session、關掉 Agent、電腦睡眠後重來 | 重新打開同一個列表 | 貼原本使用的那份 Prompt |
| 照片已搬到外接硬碟，或本機照片區已刪除 | 打開同一個列表 | 貼原本使用的那份 Prompt |
| Agent 回報錯誤、結果不明或檔案異常 | 先不要重試 | 查第 6 節「異常處理」 |
| 不確定檔案與永久紀錄放在哪裡 | 不需要開 LINE | 查第 7 節「檔案與永久紀錄」 |

**三個不要：**

1. 不要同時備份兩個列表。一次只處理一個相簿列表或一個記事本列表。
2. 不要把相簿與記事本混用。兩者有各自的 Skill、Prompt、目的地、紀錄與下載入口。
3. 不要在結果不明時自行重按「儲存全部」、重開新資料夾、改名或刪檔。先讓 Agent 查證。

## 先認識四個名詞

| 名詞 | 白話意思 |
|---|---|
| Agent | 你正在使用的 AI 助理。它會讀取本專案 Skill、觀察 LINE 畫面並執行備份。 |
| Prompt | 你貼給 Agent 的啟動指令。它同時說明任務範圍、下載授權、前景交接與完成回報方式。 |
| 列表 | 這次要備份的範圍。相簿流程是一個相簿列表；記事本流程是一個記事本列表。 |
| 永久紀錄 | Agent 保存備份歷史的地方。它不同於照片資料夾；刪除照片不會自動刪除紀錄，也不應手動修改紀錄。 |

## 1. 這份手冊會備份什麼？

| 流程 | 會備份 | 不會備份 |
|---|---|---|
| LINE 群組相簿 | 指定相簿列表內，各本合格相簿的照片。 | 聊天文字、留言、其他列表、LINE 以外的檔案。 |
| LINE 記事本 | 指定記事本列表內，各貼文的照片與影片。 | 貼文文字的下載、留言、貼圖、連結、PDF、Word、網頁文件或其他附件。 |

兩條流程都是「以 Agent 判讀畫面並操作 LINE」為主。相簿流程會逐本處理相簿；記事本流程會逐篇、逐媒體處理。工具只協助記錄、去重與檔案驗證，不會自行操作 LINE，也不會替你授權。

## 2. 第一次使用：五個步驟

### 步驟 1：打開正確的 LINE 畫面

先登入 LINE，然後依你要備份的內容打開其中一個畫面：

- **相簿：** 打開「群組相簿列表」；畫面應該是一排相簿卡片，不是聊天室，也不是單本相簿內頁。
- **記事本：** 打開「單一記事本列表」；畫面應該是這次要備份的貼文列表，不是相簿列表，也不是單一貼文的媒體檢視頁。

一次只打開一個目標列表。若不確定是否開對，先停在原畫面，讓 Agent 核對；不要用群組中文名稱、日期或張數自行猜測。

### 步驟 2：在正確的專案中啟動 Agent

在本專案 `Line_backup` 的 Agent Session 中執行。Agent 必須具備原生 Mac Computer Use、輔助使用與螢幕擷取能力；否則它只能討論，不能實際操作 LINE。

不需要另外交接開發計畫、Git 分支或測試報告。日常備份使用的是對應的正式 Prompt，不是 Acceptance／E2E 開發驗收 Prompt。

### 步驟 3：決定要不要改備份位置

不確定就留空，使用預設位置即可：

- 相簿照片：專案根目錄的 `backup/`。
- 記事本照片與影片：專案根目錄的 `backup/記事本/`。

若要用其他位置，必須是工具支援的專案內絕對路徑。永久紀錄由 Agent 自動管理，不要把紀錄位址填進照片欄位。

### 步驟 4：複製正確的 Prompt

- 相簿請用 [附錄 B：相簿正式 Prompt](#附錄-b相簿正式-prompt)。
- 記事本請用 [附錄 C：記事本正式 Prompt](#附錄-c記事本正式-prompt)。

只修改 Prompt 最上方的備份位置與排除欄位；不需要改其他內容。中間的任務範圍、授權與安全邊界請整段保留，不要自行縮短、翻譯或改寫。Prompt 很長是正常的：它同時扮演任務合約與資料保護規則，不是給人逐行閱讀的程式碼。

### 步驟 5：貼上並保持前景

確認 LINE 仍停在正確列表，再把整份 Prompt 貼給 Agent。**提交這個動作，同時代表你授權這次備份，並交接當下的 LINE 前景。** 不需要再補一句「開始下載」。

Agent 會先核對畫面與列表身分，再查永久紀錄、盤點、下載與驗證。第一次盤點可能需要一些時間；畫面暫時沒變不代表卡住。除非 Agent 要你處理一個具體問題，否則不要中途點選 LINE、按「儲存全部」或移動正在下載的檔案。

## 3. 情境一：備份 LINE 群組相簿

### 3.1 開始前要看到什麼

你應該看到本次要備份的相簿列表。Agent 需要從這個連續列表辨識每一本相簿；所以請不要先開到單本相簿內頁，也不要先選照片。

### 3.2 相簿 Prompt 的兩個欄位

| 欄位 | 怎麼填 | 留空時 |
|---|---|---|
| `BACKUP_ROOT` | 要自訂照片位置時，填工具支援的專案內完整絕對路徑。 | 使用專案根目錄的 `backup/`。 |
| `EXCLUSIONS` | 沒有新增排除就填 `[]`。要排除時，描述相簿日期、張數與可辨識的封面或內容。 | `[]` 代表沒有新增排除，不會解除既有排除，也不會允許重下已完成相簿。 |

不要填 UUID、座標、API key、內部 JSON 或群組中文名稱。Agent 會自行從畫面與永久紀錄核對列表身分。

### 3.3 Agent 會替你做什麼

1. 核對當前相簿列表、入口與永久紀錄，不只看最近一次任務。
2. 完整盤點這份列表，逐本確認資格與歷史狀態。
3. 對尚未完成且合格的相簿，逐本開啟「⋯ → 儲存全部」。
4. 每次選擇新的空白目的地，下載後進行檔案完整性與照片解碼驗證。
5. 保存完成紀錄並讀回；已完成的相簿跳過，不再重下。
6. 若先前已停止且未完成，依原授權在另一個新的空白目錄恢復；結果不明的下載不重送。
7. 最後回報盤點、逐本結果、未解項目與驗證界限。

你不需要逐本說「開始」、逐本選資料夾，也不需要自己按「儲存全部」。Agent 會在任務授權內自行處理。

### 3.4 什麼情況才算完成？

Agent 的完成回報應該讓你看得出：

- 這次是哪一份列表，以及是否已完成入口核對。
- 盤點到幾本相簿、哪些已完成、哪些被排除、哪些受保護或遇到問題。
- 每本相簿下載到哪裡、已驗證多少張照片。
- 哪些項目尚未解決；若有未解項目，不能宣稱「整份列表全部完成」。
- 畫面觀察、檔案驗證與永久紀錄讀回是不同層級的結果，不能互相替代。

檔案可完整解碼，代表這次指定檔案的完整性檢查通過；不保證與 LINE 服務端原始位元完全相同。這是誠實的驗證界限，不是備份失敗。

## 4. 情境二：備份 LINE 記事本

### 4.1 開始前要看到什麼

你應該看到本次要備份的單一記事本列表。這個流程會逐一盤點列表中的貼文，再處理每篇貼文內的照片與影片；不是只下載目前打開的那一張圖片。

不要使用相簿列表、聊天室或單一媒體檢視頁當作記事本入口。記事本也不得把相簿的「⋯ → 儲存全部」、相簿選單、按鈕或座標當成替代入口。

### 4.2 記事本 Prompt 的欄位

| 欄位 | 怎麼填 | 留空時 |
|---|---|---|
| `NOTES_BACKUP_ROOT` | 要自訂照片／影片位置時，填工具支援的專案內完整絕對路徑。 | 使用專案根目錄的 `backup/記事本/`。 |

永久紀錄會放在另一個獨立位置 `notes-backup-records/`；它不會跟相簿紀錄混在一起，也不需要你手動搬移或填寫。

### 4.3 Agent 會替你做什麼

1. 核對當前記事本列表、入口與獨立的記事本永久紀錄。
2. 完整盤點貼文與媒體，辨識照片、影片、純文字貼文與非媒體附件。
3. 逐貼文、逐媒體下載；一次只處理一個媒體。
4. 每次下載前保存並讀回交易紀錄、使用新的空白目的地，並確認不重送。
5. 下載後驗證照片或影片，保存完成紀錄並讀回。
6. 接續中斷、待驗證或已停止但未完成的項目；不確定的結果先查證，不自行重下。
7. 最後回報貼文總數、純文字貼文數、媒體狀態、已驗證照片／影片數與未解缺項。

純文字貼文只會被標成「沒有媒體」，不會被當成下載完成。PDF、Word、網頁文件與其他附件即使出現在貼文中，也不在下載範圍。

### 4.4 什麼情況才算完成？

完成回報應該包含：

- 列表、貼文與媒體三層身分是否完成核對。
- 貼文總數與純文字貼文數。
- 已驗證照片數、已驗證影片數。
- 完成、排除、待處理、受保護歷史、結果不明等狀態，以及本機目錄是否可用。
- 仍待處理的媒體或貼文；有未解項目時，只回報部分完成，不宣稱全部完成。

### 4.5 目前版本提醒

記事本功能目前在 `feature/line-notes-media` 分支開發；你實機確認並明示同意前，不會合併到 `master`。若你在 `master` 找不到記事本入口，這是版本狀態，不是 Prompt 寫錯。

目前已有個別照片與小型照片列表的完成紀錄，但前次整體測試未通過；影片、混合附件、跨 Session 接續與恢復的完整能力仍未證實。請不要把局部成功、文件或離線測試當成整份備份已通過實機驗收。

## 5. 中斷、重開與換 Session：如何接續

### 5.1 最簡單的接續方法

1. 重新打開同一個相簿列表或記事本列表。
2. 確認 LINE 已登入，畫面在前景。
3. 貼上原本使用的那一份 Prompt。
4. 不要自行刪除暫存照片、改名、移動資料夾或重按「儲存全部」。

Agent 會從永久紀錄找回前次任務；你不需要填 `RESUME`、回想上次做到哪一本，或重新說明整個任務。新 Session、換模型、電腦睡眠、Agent 被關掉，都使用同一個入口。

### 5.2 不同中斷情境

| 情境 | 你應該做什麼 | 不要做什麼 |
|---|---|---|
| Agent 程序結束、Session 關閉或電腦睡眠 | 重開同一個列表，貼同一份 Prompt。 | 不要刪掉下載到一半的檔案，也不要另開新資料夾重來。 |
| LINE 前景被中斷，或你需要使用電腦 | 先請 Agent 停止操作並保存進度；處理完再重新交接同一個畫面。 | 不要讓 Agent 在背景繼續點選，也不要重新授權一次當成重送許可。 |
| 不確定下載是否已送出 | 請 Agent 先查證原事件、目的地與當次畫面。 | 不要叫它「再試一次」，也不要自己按「儲存全部」。 |
| 已下載但結果顯示不明 | 讓 Agent 先查證；證據不足就保留原狀並回報。 | 不要換新目錄、重置紀錄、改寫狀態或重送同一個下載。 |
| 完成後照片搬到外接硬碟，或本機目錄不見 | 打開同一個列表，貼同一份 Prompt。Agent 仍會跳過已完成項目，並另報本機不可用。 | 不要因為本機沒有照片，就要求重新下載或宣稱外接硬碟副本已驗證。 |
| 本機目錄仍存在，但缺檔、有額外檔或內容改變 | 紀錄與目前檔案不一致，可能不能安全接續。 | 相簿依 Skill 保護並停止該項新派送；記事本若提出精確批次，確定範圍後才明示同意。不要自行用 Finder 修正、覆蓋或刪除，也不要用一般「繼續」當成批次同意。 |
| 記事本 Agent 說需要重新下載某一批 | 先閱讀它列出的列表、受影響貼文／媒體、舊位置、新位置、額外空間與保留項；確定同意才明確回覆。 | 不要在範圍不清楚時回「繼續」。沉默、逾時或一般「繼續」都不是批次同意。 |

### 5.3 需要追問時，可以這樣說

如果 Agent 的報告不清楚，先讓它調查，不要直接要求重下載：

```text
請先保留現狀，不要重送、刪除、改名或覆寫任何檔案。
先查永久紀錄，告訴我目前卡在哪個列表、哪個項目、你已經確認了什麼，
以及需要我處理的唯一一件事。這一步先不要下載。
```

如果 Agent 表示需要重新下載某批項目，先要求它把影響範圍講清楚：

```text
如果這批需要重新下載，請先列出受影響的列表、貼文與媒體、舊位置、
新位置、需要的額外空間，以及哪些資料會保留。
在我明確同意這個精確範圍前，不要重送或覆寫。
```

這些只是在異常時釐清用語，不是新的日常啟動流程。正常備份仍然只需附錄 B 或附錄 C 的正式 Prompt。

## 6. 異常處理：看到什麼，該怎麼做

先用這一張表判斷。Agent 回報的技術名詞不代表你一定要懂；重點是知道哪些事情可以做、哪些事情不能做。

| 你會看到的情況 | 白話意思 | 你可以做什麼 | 請不要做什麼 |
|---|---|---|---|
| Agent 說無法確認列表或入口 | 它不確定目前畫面是不是你要備份的那一份。 | 保持原視窗，描述你看到的是相簿列表還是記事本列表；不確定就重新開好指定列表再交接。 | 不要用群組名稱、日期或張數硬猜，也不要叫它直接下載。 |
| LINE 已登出，或畫面換成聊天室 | 前景交接失效，後續點選不可靠。 | 重新登入、開回同一個列表，貼同一份 Prompt。 | 不要讓 Agent 對著錯誤畫面繼續操作。 |
| macOS 權限不足 | Agent 看得到或操作不到 LINE。 | 授予螢幕擷取／輔助使用權限，關閉遮擋視窗，重新交接。 | 不要改 Prompt 或換另一個下載入口來繞過。 |
| 磁碟空間不足 | 下載無法安全完成。 | 清出空間，保留原檔，重新貼同一份 Prompt。 | 不要為了繞過錯誤而換新資料夾、改目的地或要求重送。 |
| 畫面停在 `0/N` 或看似沒有進度 | 可能仍在等待 LINE 回應或寫入檔案。 | 先觀察；必要時請 Agent 只做唯讀查證。 | 不要按取消、重開選單、連點或自行重下。 |
| 你曾按取消或關閉視窗 | 取消不一定代表沒有檔案，畫面也可能落後。 | 保留畫面與檔案，讓 Agent 查實際目的地與紀錄。 | 不要假設「取消就沒下載」而立刻重送。 |
| Agent 回報結果不明（`UNKNOWN`） | 目前無法證明下載成功或失敗。 | 請 Agent 先查證、保存第一筆真實結果；未收斂就停止並回報。 | 不要換新目錄、改寫紀錄、建立新下載或重按一次。 |
| 本機目錄不見（`LOCAL_MISSING`） | 完成紀錄仍在，但本機這份複本目前不可用。 | 保留完成與禁止重下；需要時自行從你的其他備份還原。 | 不要把它當成空帳，也不要宣稱外接硬碟副本已驗證。 |
| 本機檔案缺檔、額外檔或內容改變（`LOCAL_CHANGED`） | 紀錄與目前檔案不一致。 | 保護原件，讓 Agent 依 Skill 停止或提出精確批次確認。 | 不要自己在 Finder 修補、改名或覆蓋。 |
| 記事本 Agent 要求批次重新下載 | 舊交易或本機檔案無法直接安全接續。 | 先看它列出的精確範圍；確定同意才明示批准該批。 | 不要用「繼續」代替確認，也不要把一次同意擴大到其他列表。 |
| 來源已到期 | 這個項目目前拿不到，但不代表其他項目也失效。 | 讓 Agent 保留欠件、回報來源狀態，繼續依規則處理其他合格項。 | 不要推論整份列表都到期，也不要重送該項。 |

## 7. 檔案與永久紀錄放在哪裡？

### 7.1 預設位置

| 流程 | 預設照片／影片位置 | 永久紀錄位置 |
|---|---|---|
| 相簿 | `backup/` | `backup-records/<列表識別>/` |
| 記事本 | `backup/記事本/` | `notes-backup-records/<列表識別>/` |

另外，`.local/line-backup/active-task.json` 與 `.local/line-backup/active-notes-task.json` 只是協助 Agent 找回最近任務的定位資訊，不是唯一歷史來源。即使這些檔案不見，也不代表沒有歷史；Agent 會再查全部永久紀錄。

### 7.2 可以搬照片，但不要刪紀錄

- 照片與影片可以複製到外接硬碟，或在你確認已有其他副本後刪除本機照片區。
- **不要刪除** `backup-records/`、`notes-backup-records/` 或 `.local/line-backup/`。它們保存完成事實、來源與接續所需資訊。
- 不要把永久紀錄改名、搬到另一個專案、用手編輯 JSON，或把相簿紀錄與記事本紀錄互換。
- 專案整個搬移後，若 Agent 發現舊路徑或身分歧義，先讓它安全對帳；不要為了解除問題而手改歷史或重新下載。

### 7.3 外接硬碟與刪除照片

你可以自行把已完成的照片複製到外接硬碟，再刪除本機的 `backup/` 或 `backup/記事本/` 目錄。下次仍使用同一份 Prompt；Agent 會保留完成紀錄，將整本目錄缺席視為本機目前不可用，而不是重新下載的理由。

但這只代表「本機副本不見了」，不代表 Agent 已驗證外接硬碟上的副本。外接硬碟不需要在線才能繼續查歷史；若目錄仍存在但內容異常，Agent 會保護原件並停止依賴該項的新派送。

## 8. 常見問題

### Q1：Prompt 這麼長，我需要看懂每一行嗎？

不需要。你只要看懂最上方的備份位置，並在正確畫面提交。Prompt 的中段是 Agent 的任務授權、資料保護、下載與回報規則；它的長度是為了避免 Agent 把日常備份誤當成開發驗收，或在不確定時亂重送。

### Q2：為什麼 Prompt 裡有 Harness、Acceptance 或 E2E 這些字？

那些句子是在告訴 Agent：「這次是日常備份，不要切換成開發驗收角色。」你不需要操作那些角色。若你不小心使用 Acceptance／E2E 角色 Prompt，Agent 應先提醒你改用本手冊的正式入口。

### Q3：同一份 Prompt 可以一直用嗎？

可以。首次、下次、新 Session、換模型，以及 Agent 修正後的試用，都使用同一份相簿或記事本 Prompt。差異由永久紀錄與當次畫面決定，不需要你手動選「新模式」。

### Q4：重複貼 Prompt 會不會重複下載？

不會因為重貼就自動重下已完成項目。Agent 會先查永久紀錄、核對列表與本機檔案，再跳過已完成項目。但若前次結果不明、工具缺少、來源到期或交易未完成，重貼也不能保證本次一定成功；Agent 應如實回報。

### Q5：需要另外發一則「開始下載」嗎？

不需要。正式 Prompt 提交時已包含本次授權與前景交接。你只要確認提交當下 LINE 停在正確列表；不需要在盤點完成後再發一次開始指令。

### Q6：可以一次備份很多列表或兩條流程一起跑嗎？

不可以。一次只處理一個列表；相簿與記事本也各自使用自己的 Skill、工具、目的地與紀錄。完成一份列表後，再開下一份列表並使用對應 Prompt。

### Q7：我需要提供群組中文名稱、UUID、座標或 JSON 嗎？

不需要。Agent 以當次畫面、連續入口與永久紀錄核對身分；中文名稱、日期、張數、序號或單一檔案 hash 都不能單獨認領歷史。若畫面有歧義，Agent 會提出具體問題。

### Q8：備份完成後，我可以自己改名或整理資料夾嗎？

照片檔案可依你的保存習慣另存；但不要在 Agent 尚未完成或結果不明時移動、改名、覆寫下載中的檔案。已完成的新格式相簿若需要名稱校正，應交給 Agent 依 Skill 處理；不要自己在 Finder 改名。無法安全校正時，保留原名比破壞紀錄好。

### Q9：驗證通過是否等於和 LINE 伺服器上的原始檔完全相同？

不完全等於。驗證包含非空檔、雜湊、完整解碼與完成紀錄讀回，能證明這份本機檔案在指定驗證範圍內一致；但不能證明服務端位元完全相同，也不等於外部硬碟副本已驗證。

### Q10：如果我需要使用電腦，該怎麼辦？

先請 Agent 停止新增 GUI 操作並保存進度。你處理完後，把 LINE 開回同一個列表，再貼同一份 Prompt 或重新交接前景。重新交回前景只恢復操作前提，不會自動解除結果不明或已完成保護。

### Q11：備份到一半可以關掉 LINE 或 Agent 嗎？

可以關，但請保留已下載的檔案與永久紀錄，下次用同一份 Prompt 接續。不要刪除暫存目錄、重建空白紀錄或自己重按下載。若 Agent 已送出下載但結果不清楚，先讓它查證，不要把它當成「沒下載」。

### Q12：Agent 說「全部完成」時，我應該檢查什麼？

看它有沒有列出列表身分、盤點結果、逐項處理結果、未解項目與驗證界限。若還有 `UNKNOWN`、本機不可用、異常檔案或待處理交易，就不是整份列表全部完成。文件、離線測試或帳本摘要的 PASS，也不能單獨證明真實 LINE GUI 已全部備份。

## 9. 目前能力與驗證界限

這份手冊描述的是日常入口，不是正式驗收報告。相簿與記事本的完成訊號要分開看：

- **相簿：** 歷史上有一次特定 macOS 實機操作 Session 完成四本、共 141 張照片的操作與檔案／紀錄核對；這支持核心流程曾有真實經驗，但不自動等於現行版本的跨 Session 接續、中斷恢復或名稱校正都已通過。相關情境沒有當次證據時仍是 `NOT_RUN`。
- **記事本：** 已有個別照片下載及小型照片列表完成紀錄；前次整體測試未通過，沒有進入下載。影片、混合照片／影片附件、跨 Session 接續與恢復仍未被證實，不能宣稱記事本功能已全面完成。
- **工具結果：** 工具產生的備份紀錄一致，只表示紀錄與摘要投影相符；個別檔案驗證只表示指定檔案的驗證通過；兩者都不是真實畫面操作、真實 LINE E2E 或獨立驗收的替代品。
- **本機可用性：** 完成紀錄、本機照片缺失、本機檔案異常與外部副本驗證是不同事情；回報時不得互相升格。

未實際執行真實 GUI、混合附件 chooser、跨 Session 恢復或影片解碼的項目，應維持 `NOT_RUN`，不要用文件、離線測試或局部成功補成 PASS。
