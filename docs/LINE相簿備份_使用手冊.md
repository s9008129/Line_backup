# LINE 相簿備份使用手冊

你人工開好要處理的 LINE 相簿列表、指定照片保存位置，再把前景交給 Agent。Agent 依專屬 Skill 先看完整份列表、列清單，再按你授權的範圍處理。不需要輸入群組名稱。

## 開始前

- 使用已登入 LINE、具有原生 Mac Computer Use 的 Codex Session；只有終端機或瀏覽器工具不能代替它。
- 準備容量充足的保存位置，並告訴 Agent 舊照片與完成紀錄在哪裡。新目錄不代表從未備份。
- 操作期間讓 Agent 使用 LINE 前景；需要使用電腦時先請它停止新增操作、保存進度。Agent 不自行啟動或尋找另一個列表。

在專案資料夾啟動 Codex，貼上下方提示詞。提示詞是啟動方式；具體操作方法集中在 [專屬 Skill](../.agents/skills/line-album-agent-cua/SKILL.md)。

## 可重複使用的啟動提示詞

先填保存位置，再選模式：`INVENTORY_ONLY` 只盤點、`BACKUP` 盤點後備份、`RESUME` 接續原任務。只檢查 Skill 時直接說明，不需填路徑或開 LINE。

```text
MODE=INVENTORY_ONLY
BACKUP_ROOT=請填實際保存位置
EXCLUSIONS=[]

請使用本專案 $line-album-agent-cua，依上述模式處理我人工開啟並交到前景的 LINE 相簿列表。由 AI Agent 判讀並操作，不新增控制器或授權框架。

先讀舊完成、排除與中斷紀錄，再用 Skill 的完整盤點方法看完列表，保存總本數、逐本狀態與有序待下載清單。不要依群組名稱或中文 OCR 判斷是哪個列表；接續任務若疑似開到另一列表才問我。

等我確認前景已交接後才操作。INVENTORY_ONLY 僅授權觀察、列表捲動及盤點紀錄，不開下載選單、不下載，列完清單就停止。

若我選 BACKUP 或 RESUME，交接後也授權依確認好的清單，逐本下載尚未開始、未完成備份且未排除的新相簿至上述位置的新空白目錄。一次只處理一本，保存操作前紀錄，儲存全部只送一次，逐檔核對數量、SHA-256 與 ImageIO 完整解碼，保存並讀回完成紀錄後才繼續。

接續時先核對原列表與紀錄；已完成的跳過。先前中斷的一本須先確認已停止、保留原檔，另取得我對該本的恢復授權，才下載到另一個新空白目錄。結果未知先查證，不重送、不改舊紀錄解鎖。

不發訊息、刪除、分享、覆寫舊照片或變更正式完成事實；不操作其他列表。不 push、merge 或啟動雲端 CI。前景中斷、身分不明、儲存位置不符或工具拒絕時，保存進度並用白話告訴我需要處理的一件事。

定期回報總本數、已完成、排除、待下載、先前未完成、未知與受保護歷史，以及已驗證張數。只有列表確實看完、逐本對上且待辦與未知均為零，才回報這次全部完成。不要把未實測的能力寫成成功。
```

這份範本只有你實際提交後，才提供所選模式的授權。寫在手冊裡不等於已交接或已授權下載；路徑仍是佔位內容時 Agent 會先問。

## 中斷後怎麼繼續

使用相同保存位置，把模式改成 `RESUME`，人工開回原列表後貼提示詞。Agent 先讀進度，不靠上次聊天記憶或舊畫面位置續跑。

已完成的一本不重下；還在下載的先觀察；已下載完但未驗證的先驗證現有檔案；確定停止且未完成的，向你提出那一本的恢復安排。採相簿級恢復，不承諾 LINE 能只補缺少的照片。

若前次到底有沒有開始下載仍不清楚，Agent 會先查紀錄與檔案，不因你再次啟動就自動重送。

## 怎麼知道全部完成

盤點清單的總本數應等於「已完成＋已排除＋待下載＋先前未完成＋未知＋受保護歷史」。已完成與排除以外均為零，並有從頂到底的列表覆蓋及逐本驗證證據，才算這次處理完成。這不保證日後新增照片也已備份。

進度與完成紀錄要保存在正式保存位置的 `backup-records`，照片放在各次的新相簿目錄。舊資料來源另有位置時保留連結；不會因這份手冊自動搬移照片。

## 目前仍要驗證的地方

已有真實列表捲動、選單、儲存位置選擇與完整檔案驗證經驗。這輪整理了方法，沒有操作 LINE 或下載；新版完整盤點、跨 Session 接續及相簿級恢復仍需另外安排實測。

獨立選單視窗能否觀察，要看當次工具支援。歷史成功不保證每個 Session 都有相同能力；缺工具時先停下說明，不盲點。

日常 Agent 備份不等於舊正式 AUTO 驗收。舊研究資料另外保存，不作日常使用者的額外設定表單；既有程式若拒絕，Agent 仍不會繞過它。
