# LINE 相簿備份 Skill 說明

> **這是技術背景與操作規則，不是日常啟動入口。** 第一次使用請先讀[白話使用手冊](LINE相簿備份_使用手冊.md)。

> **一句話：** 這是一份給 AI Agent 的專業工作手冊，讓它在 macOS 上接手你已打開的 LINE 相簿列表，安全地盤點、逐本下載、驗證照片並保存可接續的紀錄。

## 1. 先認識這個 Skill

`line-album-agent-cua` 不是安裝後會常駐背景的 App，也不是 LINE 的官方備份功能。它是一套以文字規則為核心的 **Agent Skill**：Agent 讀懂這份 Skill 後，透過 macOS Computer Use 觀察與操作 LINE，並在需要時呼叫本專案的小工具記錄交易、避免重複下載及驗證檔案。

可以把角色分工想成這樣：

| 角色 | 白話比喻 | 實際工作 |
|---|---|---|
| Skill | 工作手冊 | 定義怎麼認列表、何時能下載、何時要停、哪些資料不能碰。 |
| AI Agent | 現場領班 | 理解你的目標，依當次畫面決定下一步，完成整份列表。 |
| Computer Use | 眼睛與手 | 看 LINE、捲動、點選、輸入路徑；由 Agent 下判斷。 |
| `daily.py` | 倉管 | 保存交易、歷史與完成紀錄；不操作 LINE。 |
| `image_decode.swift` | 驗貨員 | 計算 SHA-256、用 ImageIO 完整解碼照片；不判斷畫面。 |
| 永久紀錄 | 只追加的出貨簿 | 照片可搬走，但完成、排除、未知與受保護歷史仍保留。 |

## 2. 真正的意圖

這個 Skill 的目標不是「盡量多點幾次下載」，而是完成**一個指定相簿列表內所有合格、尚未備份的相簿**，同時做到：

1. 先知道整份列表有多少本，以及每一本目前屬於哪種狀態。
2. 只處理你這次交接的那一份列表，不擴及其他群組或相簿。
3. 每本相簿使用新的空白目的地，避免不同相簿的檔案混在一起。
4. 每個相簿 attempt 最多派送一次「儲存全部」，結果不明時先查證，不用重試猜運氣。
5. 下載後核對張數、非空檔、SHA-256 與照片完整解碼。
6. 保存完成紀錄並讀回；下次啟動時跳過已完成項目，並依紀錄嘗試安全接續中斷的工作。
7. 有未解項目就誠實列出，不把「大部分完成」說成「全部完成」。

因此，這個 Skill 的價值不只是下載，而是**在真實 GUI 的不確定性中，維持身分、交易與資料的一致性**。

## 3. 適合與不適合的情況

### 適合

- 你使用 macOS，已登入 LINE，並能授予 Agent 螢幕擷取與輔助使用權限。
- 你已人工打開一個**群組相簿列表**，希望備份這份列表中的合格相簿。
- 你願意在任務期間把 LINE 前景交給 Agent，不中途搶滑鼠或鍵盤。
- 你要的是本機照片備份，以及可跨 Session 查詢的完成紀錄。

### 不適合

- Windows、Linux、手機或其他沒有本專案所需 Computer Use 的環境。
- 整個 LINE 帳號匯出、聊天文字備份、留言、貼圖或連結備份。
- 只下載某張照片、只選幾張照片，或把單張檢視器當成整本相簿入口。
- 同時備份多個列表，或把相簿流程拿來備份記事本。
- 期待安裝後自動監看 LINE、自行啟動或永久在背景執行的服務。

## 4. 你需要做什麼，Agent 負責什麼

| 你 | Agent |
|---|---|
| 人工登入 LINE，打開正確的相簿列表。 | 核對當次畫面是否為同一份連續列表，不確定的話先查證。 |
| 提交使用手冊中的正式相簿 Prompt。 | 將提交視為本次備份授權與前景交接，開始查歷史、盤點與下載。 |
| 任務期間保持 LINE 前景，不接管操作。 | 依 Skill 自主導覽；遇到前景中斷就停止 GUI 輸入。 |
| 只在 Agent 提出具體阻塞時處理。 | 先嘗試安全查證；仍不能解決時保留原狀並回報一件事。 |

你不需要提供群組中文名稱、UUID、座標、內部 JSON 或逐本下載口令。Agent 會從當次入口、畫面脈絡與永久紀錄自行核對；名稱可以幫助顯示，但不能單獨用來認領歷史。

## 5. 這個 Skill 包含哪些工具與技術

### 原生 macOS Computer Use

Agent 使用當次可用的 AX（輔助使用樹）、LINE 視窗截圖、經授權的桌面局部觀察、捲動、點擊與文字輸入來操作 LINE。AX 與截圖都只是觀察來源；如果兩者看不到獨立 popup，不能直接推論「按鈕不存在」或「沒有授權」，而要依 Skill 改用當次允許的觀察方式，重新建立安全映射。

每次輸入前都要重新確認：目前是哪個畫面、目標控制項是什麼、前次是否可能已送出。舊座標、舊畫面與舊 Session 的滑鼠位置不會被當成新的可靠依據。

### `daily.py`：只做簿記與交易

`src/line_backup_batch/daily.py` 管理相簿的永久紀錄、盤點頁面、下載 intent、outcome、驗證、命名交易與恢復查詢。它**不會**自己找按鈕、點 LINE 或授予 GUI 權限。

永久紀錄以追加式事件保存；`index.json` 只登錄帳本位置，`active-task.json` 只協助找回最近任務，真正的事實來源是各帳本內的 events。這種設計讓照片區可以被搬走，而不會把「照片不在」誤判成「從來沒有備份過」。

### `image_decode.swift`：照片驗貨

這個工具會逐檔計算 SHA-256，並使用 macOS ImageIO 對照片做完整像素解碼，而不是只看副檔名、縮圖或檔案是否存在。驗證還會核對目的地、預期張數、實際檔數與每個檔案的解碼結果。

它只接受本流程支援的單張影像與大小限制；超限或格式不支援時要如實回報，不能跳過後宣稱全部通過。完整解碼成功也只代表**這份本機檔案在該次範圍內可讀且一致**，不代表與 LINE 伺服器原始位元完全相同。

### 選用的離線 OCR

`scripts/agent_resume/modern_ocr.swift` 可在需要時輔助讀取已保存的畫面文字，但它是輔助觀察，不是列表身分的唯一證據，也不會自行截圖、點擊或操作 LINE。

### 紀錄保存技術

本專案以檔案鎖、先寫暫存檔再獨占發布、`fsync`、避免 symlink 與寫後讀回等方式降低紀錄中斷或競態的風險。這些是本機軟體層的保護機制，不是 OS sandbox、網路隔離，也不是「作業系統保證每一次點擊都恰好一次」。

## 6. 完整工作流程

```text
你交接已打開的相簿列表與正式 Prompt
        ↓
核對入口、前景與列表身分
        ↓
查全部永久帳本與最近任務
        ↓
從列表頂端到底端完整盤點，逐本分類
        ↓
對合格且未完成的相簿逐本處理
        ↓
建立 intent → 新空白目的地 → Save All 一次 → chooser
        ↓
記錄 outcome → 驗證檔案 → 保存 completion 並讀回
        ↓
回到列表，核對下一本，直到完整對帳
```

### 步驟 1：核對入口

目標必須是**相簿列表**，不是聊天室、單張照片檢視器或不相關的頁面。若入口或返回後的位置無法確認，先唯讀查證；沒有可靠依據就保留原視窗，不猜 Escape、Command-W 或關閉視窗。

### 步驟 2：找回前次任務

先查全部相簿帳本，再讀 `.local/line-backup/active-task.json` 與相符帳本的記憶。active-task 只是書籤，不是唯一歷史入口；帳本缺少、索引損壞或列表身分有歧義時，不能開一份空帳假裝重新開始。

### 步驟 3：完整盤點

Agent 從列表頂端到底端，以相鄰畫面重疊、共同卡片、卡片順序與底端重複觀察建立完整清單。每本相簿至少要有足以區分的身分依據；日期與張數相同不能自動合併。缺頁先小步回捲補接，仍不能證明連續性就停止並回報。

### 步驟 4：逐本下載

只有合格、未完成、未排除、未受保護且沒有未決交易的相簿才進入下載。每本都使用自己的新空白目的地，先保存並讀回 intent，再確認相簿詳細頁與唯一選單。選單的 `⋯ → 儲存全部` 是唯一整本下載入口；`選擇項目`、單張或逐張下載都不是替代方案。

### 步驟 5：記錄結果與驗證

下載後先記錄第一筆真實 outcome。只有明確完成且檔案穩定時才進入驗證；工具會核對目的地、張數、非空、SHA-256 與 ImageIO 完整解碼。照片可讀但紀錄寫入失敗時，正確回報是「照片已驗證，完成紀錄尚未保存」，不是重新下載。

### 步驟 6：保存完成並繼續下一本

驗證成功後保存 completion 並讀回，再依可靠返回入口回到原列表，重新觀察下一本。已完成的跳過，未完成的依狀態處理；不重用上一本的座標或畫面游標。

### 步驟 7：最終對帳

只有完整盤點成立、`unresolved=0`，且沒有已辨識卻在當次畫面消失的卡片時，六類回報類別的總和才應等於本次已辨識的相簿總本數。工具 `summary.total` 只計算當次 scan 已辨識的卡片；若仍有 `unresolved` 或缺卡，不能把 `total` 當成真正的列表總數，也不能宣稱六類剛好相加。只有待下載、先前未完成、未知與受保護歷史都已解決或明列，才能說這份列表沒有未解項目；不能把局部成功包裝成全部完成。

## 7. 為什麼「完整盤點」不是可省略的步驟

如果沒有完整盤點，Agent 只知道目前看得到的幾本，可能會漏掉列表下方的相簿，也可能把同一本重複算成兩本。盤點是備份的一部分，不是要求你另外選「盤點模式」，也不是盤點完還要你再下第二次開始指令。

以下都不能單獨證明相簿身分：

- 群組或相簿的中文名稱。
- 日期或照片張數。
- 單一封面縮圖。
- 某個檔名、單一雜湊或目前畫面位置。

Agent 必須交叉使用當次入口、連續列表、相鄰卡片、詳細頁內容與歷史紀錄。若真的存在無法自行解決的歧義，才向你提出一個具體問題。

## 8. `⋯ → 儲存全部` 的安全邊界

在當時觀察到的 LINE 介面中，相簿詳細頁沒有一個常駐的「儲存全部」按鈕；它位於 `⋯` 開啟的原生 popup，通常出現在右上附近，不同版本的位置可能不同。這個 popup 也可能不在 app-bound AX／截圖範圍內，所以 Agent 必須把「選單是否開啟」與「按鈕是否已派送」分開判斷。

- 開啟 `⋯` 只改變選單狀態，不是下載。
- 只有 `儲存全部` 才可能送出下載。
- 每個相簿 attempt 的 `儲存全部` 最多一次；這是 Agent 的操作紀律，不是作業系統或 LINE 提供的 exactly-once 保證。
- 選單狀態未知時，不得先找位置盲點；已派送但結果不明時，不得重開選單或再點一次。
- 結果不清楚時，先保存證據、查原視窗、目的地與事件，不換新目錄或改寫紀錄來解鎖。

選擇儲存位置時，Agent 會使用本 attempt 的新空白目錄，讀回 chooser 的完整路徑並確認沒有混入其他相簿的檔案。下載進度停在 `0/N` 或短暫沒有變動，可能是仍在等待，不是立刻重送的理由。

## 9. 六類回報類別與「已人工備份」

`daily.py` 的原生投影是 `COMPLETED`、`EXCLUDED`、`INCOMPLETE`、`UNKNOWN`、`PROTECTED_HISTORY`。下表是 Agent 依證據回報時，再把 `INCOMPLETE` 分成 `PENDING` 與 `PREVIOUSLY_INCOMPLETE`；這兩個名稱不是工具額外保存的獨立狀態欄位。

| 狀態 | 白話意思 | 會不會自動重下？ |
|---|---|---|
| `COMPLETED` | 有工具可核對的完整下載與驗證證據。 | 不會，依紀錄跳過。 |
| `EXCLUDED` | 你或既有規則已明確排除。 | 不會。 |
| `PENDING` | 已盤點，尚未處理或正在等待處理。 | 會依排程處理。 |
| `PREVIOUSLY_INCOMPLETE` | 以前曾開始但未完成，仍需受控恢復。 | 會先依恢復規則處理，不是普通新下載。 |
| `UNKNOWN` | 可能已送出，但無法證明成功或失敗。 | **不會自動重送。** |
| `PROTECTED_HISTORY` | 舊資料證據不足，先保護而不升格成完成或排除。 | 不會把猜測當成完成。 |

Agent 不會把 `INCOMPLETE` 一律當成同一種情況：沒有前次 attempt、待處理 naming 或 `STOPPED`／`NOT_SENT` 等阻礙時，才回報 `PENDING`；若有先前 attempt 或明確的停止／未送紀錄，則依原本 group、album 與 previous-attempt scope 走受控恢復，回報 `PREVIOUSLY_INCOMPLETE`。`UNKNOWN` 永遠不能併入這一類。這些是 Agent 讀紀錄後的回報方式，你不需要手動選擇內部代碼。

「已人工備份」是來源註記，不是第七類。只有工具依既有規則認定完整證據時才算 `COMPLETED`；只有你的口頭聲明或照片存在、但證據不足時，屬 `PROTECTED_HISTORY`。人工聲明也不能覆蓋既有的 `UNKNOWN` 或未完成交易。

## 10. 中斷、UNKNOWN 與相簿級恢復

### 重新交接不是重送許可

前景中斷時，Agent 應停止所有 GUI 輸入並保存目前狀態。你重新打開同一列表、貼同一份 Prompt，只恢復「可以繼續觀察與操作」的前提，不會自動解除 `UNKNOWN`、已完成保護或未完成命名交易。

### 結果未知時先查證

若 Agent 無法確認「儲存全部」是否送出、下載是否仍在進行，或 chooser 後的結果是什麼，就必須保留證據並以 `UNKNOWN` 處理。它不能：

- 用新目錄或零計數假裝沒有下載。
- 重寫 UNKNOWN 為 STOPPED。
- 建立第二個 attempt 繞過原交易。
- 用「再試一次」換取心理上的確定感。

### 已確認停止後的相簿級恢復

只有在原任務已授權恢復、前次結果明確為 `STOPPED` 或 `NOT_SENT`、且符合原本的相簿與 previous attempt scope 時，Agent 才可在**另一個新空白目錄**恢復未完成的那一本；原目錄與已下載檔案全部保留。已完成的相簿不重跑。`UNKNOWN` 不在這個恢復範圍內；若結果仍未知、授權不足或工具無法安全調和，應停止並回報，不得自行擴大恢復範圍。

現有工具對同一 attempt 的第一筆 outcome 有不可任意改寫的限制；若已明確記錄 `UNKNOWN`，即使後來看到某些檔案，也不能直接把舊事實改成完成。這是刻意的資料保護，不是 Agent 可以順手繞過的小麻煩。

## 11. 照片區與永久紀錄

| 位置 | 放什麼 | 可以搬走或刪除嗎？ |
|---|---|---|
| `backup/` 底下的相簿子目錄 | 相簿照片，預設媒體區。 | `backup/` 是兩條流程共用的父目錄，不要整包刪除；只在確認某個相簿子目錄已有可讀副本後整理它，且不要在交易中移動。外接副本是否可靠由你自行判斷，本流程不驗證它。 |
| `backup-records/<列表識別>/` | 追加式事件、完成、目的地綁定與來源證據。 | **不要刪除或手改。** |
| `.local/line-backup/` | 最近任務書籤與私有證據。 | 不要用手編輯；它是輔助定位，不是唯一歷史。 |

### 完成事實與本機可用性要分開

- `LOCAL_MISSING`：完成紀錄仍在，但整本本機目錄目前不見。仍保留完成、禁止重下；外接副本未經本流程驗證。
- `LOCAL_CHANGED`：目錄還在，但有缺檔、任何額外檔（相簿流程沒有 `.DS_Store` 等環境附屬項例外）、內容／身分漂移或 symlink。應保護原件並停止依賴該目錄的新派送。
- `VERIFIED_PRESENT`：本機檔案目前存在，且檔名集合、大小、時間戳與逐檔 SHA-256 與 completion manifest 相符；這是可用性核對，本次沒有重新執行 ImageIO 完整像素解碼。

這些是本機可用性標籤，不是第七類業務狀態。照片不在，不代表可以把 `UNKNOWN` 解鎖；照片在，也不代表已完成事件的證據自動成立。

## 12. 驗證到什麼程度，不能宣稱什麼

請把以下幾層分開看：

| 層次 | 能證明什麼 | 不能證明什麼 |
|---|---|---|
| GUI 觀察 | Agent 在當次畫面看到什麼、做了什麼。 | 不能單獨證明檔案完整或歷史正確。 |
| `daily.py` 簿記 | 事件、狀態、交易與摘要彼此一致。 | 不是 GUI、下載成功或獨立驗收。 |
| ImageIO／SHA-256 | 指定本機檔案可讀、可解碼、內容在該次檢查中一致。 | 不證明與 LINE 伺服器原始位元完全相同。 |
| 真實 E2E | 某個特定環境與 Session 的實際流程曾走通。 | 不能外推到所有 macOS、縮放、螢幕、模型或版本。 |

工具輸出中的 `dispatch_authorized=false` 只是「工具沒有授予 GUI 權限」的簿記欄位，不是使用者同意、下載成功或實機 PASS。

## 13. 目前已知的實機證據

2026-10-30 曾有一次特定 macOS Computer Use Session 的實機操作紀錄（`OBSERVED`），完成 4 本、共 141 張照片，涵蓋重新觀察 popup、共同錨點映射、chooser、命名、檔案與完成紀錄核對。這是特定 Session 的觀察事實，不是獨立 E2E 驗收；也不代表現行版本在跨 Session 恢復、名稱校正、所有 macOS 版本、縮放比例、多螢幕或所有模型上都已通過。

未在當次環境實際執行的情境，應維持 `NOT_RUN`。離線測試、單本 summary PASS 或一次成功，都不能自動補成普遍保證。

## 14. 安全邊界

這個 Skill 不會因為取得一次備份任務，就順便取得其他授權。一般備份授權不包含：

- 發送訊息、刪除相簿、分享內容或修改 LINE 設定。
- 覆寫舊照片、改寫既有完成事實或把歷史 UNKNOWN 清空。
- 操作其他列表、其他群組或記事本流程。
- 修改產品程式、紀錄規則或建立新的授權框架。

Agent 若遇到工具拒絕、身分歧義、寫入衝突或不明派送，應停止依賴該前提的動作；不能改走另一個入口繞過。

## 15. 什麼時候應該停止並交還給你

- 列表身分、入口或前次派送狀態無法確認。
- 下載結果不明，或本機目錄出現缺檔、額外檔、內容漂移、symlink 等異常。
- 當前相簿已有 `UNKNOWN`、活動下載或未完成命名交易。
- 儲存空間、權限、前景或工具能力不足。
- Agent 想改用單張、逐張或其他流程替代唯一的 `⋯ → 儲存全部` 入口。

停止不是失敗；在不確定時保留原狀，通常比多按一次更安全。
