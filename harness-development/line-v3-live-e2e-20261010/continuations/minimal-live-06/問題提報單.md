## 要解決的問題

minimal-live-06 必須先以可信的固定輸出政策、一次性 check runner 和完整配對 inventory 建立保全基線，才可以修改產品或擷取 LINE 證據。目前已建立的 `inventory_pair.py`、`run_command.py`、`test_evidence_policy.py` 與 `output-policy-frozen.json` 彼此不一致，也未覆蓋核准計畫要求的輸出生命週期。若繼續，B01 的 PASS 不足以證明 G_BASELINE_06；兩本相簿交易之後，B02 會把計畫明確允許的 evidence／state／ledger 變更判為未授權，G_PRESERVE_06 無法按目前政策通過。與此同時，扁平 `fixed_files` allowlist 又可能把未到階段或沒有 producer 收據的新增檔案錯當成已核准。

這是證據完整性與 gate 可驗收性阻塞，**不是**觀察到資料遺失。為避免用一個不可信 PASS 繼續，已停止在 E01/E02/B01 之前。

## 已核實的主要事實

1. `tools/inventory_pair.py` 的 `compare_baseline_to_pair`（第 133–147 行）只讀 `fixed_files` 和可選的 `dynamic_registered_paths`。凍結政策實際使用 `check_output_rule`、`inventory_output_rule`、`gate_output_path_template`、`dynamic_artifacts`／事前 registration，以及 `transaction_path_policy`；比較器都沒有讀取或展開這些規則。它也把任何 `fixed_files` 新增一律放行，不檢查階段或 producer，卻把所有既存路徑內容變更一律 BLOCKED。因此，B01 自己在 scan 後才發布的四個 inventory 檔不在 scan baseline 中；之後的 check/gate/CUA evidence 不會從模板獲准；canonical state／ledger 即使有交易 receipt 仍會被 BLOCKED。計畫要求的精確範圍和交易收據檢查因此無法成立。

2. `B01` 模式（`tools/inventory_pair.py` 第 190–195 行）只比較這次兩份 scan，沒有把 bootstrap 輸出與 `prewrite-anchors.json` 對帳，也沒有驗證 protected preimage 或把 Git HEAD／branch／index 綁進基線。故即使兩次 scan 相同，仍不能單獨支持 G_BASELINE_06。

3. `output-policy-frozen.json` 第 11–93 行以 flat `fixed_files` 為主，沒有每個固定輸出的 exact parent、建立／有限更新階段、type、size cap、producer、readback/lifecycle。它宣稱有 no-follow/fsync/readback，但沒有為每個輸出定義可核對的生命週期。這不符合 `plan.md` §5.2，也讓上面的比較器可能僅憑路徑名稱放行錯階段輸出。

4. `checks/run_command.py` 第 43–53 行仍綁定 `scope-recovery-05/recovery-02` 與舊 task ID；依第 48–50 行，tool/spec/freeze/evidence/tmp 也都指向 recovery-02。從 minimal-live-06 執行會與其 `validate_location` 的固定工具位置衝突，不能成為本輪 runner。第 344–367 行只檢查輸出檔是否已存在，沒有在 child launch 前 O_EXCL 建立不可重用的 ID claim；也未按 §5.3 preflight HEAD、branch、empty index，沒有記錄 effective environment diff。

5. `checks/test_evidence_policy.py` 第 58–73 行用同步 stub 和記憶體 list 代替真實配對掃描／延遲 stream，無法證明 scan 中沒有寫檔。第 100–129 行的 unknown-special fixture 只檢查 violation，沒有證明 socket 沒被 open/read/hash。第 131–166 行只測單檔 exclusive write/readback/collision、symlink parent 和政策欄位存在；沒有測 tail publication ordering、錯誤 cwd/source drift、或 dynamic path 未先註冊就寫入的拒絕。計畫 §7.3 明列的 assertions 因而不完整。

6. `checks/test_run_command.py`、`check-specs.json`、`check-specs-freeze.json` 尚不存在。E01、E02、B01 都沒有 launch；它們的正式 ID 目前仍未消耗。使用 Python `compile(source, path, 'exec')` 的記憶體語法解析不是 E01/E02，也不是 task PASS。

7. 複製進 R 的 runner 是以 `cp` 從 recovery-02 複製到已確認不存在的目標；沒有觀察到覆寫既有檔案，但未使用或證明 `O_EXCL`。這違反 bootstrap policy 對固定輸出的 exclusive-create 約束，且目前沒有足夠證據把這項寫入宣稱為 exclusive。
