# Granted correction semantics

Only producer and its Python tests change. The original Plan03, machine Handoff, wire v1,
Swift public inputs/consumer, source53, config/state/photos and old fixtures remain immutable.
Original3/3 and independent FAIL stay visible; this segment has one explicit user-granted
candidate (aggregate4). Any failed candidate/acceptance stops; no implicit fifth attempt.

Referenced JSON is decoded strictly, then content is joined by kind. Filesystem join/fixture
must match exact app/group/fingerprint/run/destination and the run's VERIFIED event reference.
For the retained `actual_cua_source_identity_join` v1 shape, its uniquely named filesystem
verification artifact is read under the explicit selected root, size/hash checked, parsed
strictly and compared to the run verification with exact JSON types. Other declared join
artifact entries are checked for normal selected-root paths, digest shape and uniqueness;
they are not recertified as native observations. Unsupported join shapes fail closed.
A fixture needs the same exact history anchors and verification payload and remains synthetic.

`user_fact` v1 supports only a user_attestation registry with null machine run pointer. Its
CONFIRMED/source-correspondence/merge flags, raw requested group, fingerprint, actual answer
part2 group/date/count and explicit-root proof bytes are checked. Its optional destination
must agree with the registry, and a machine-run claim is refused. The old helper is not used
because it reads with historical workspace rules; new reads use the existing no-follow
ProjectReader and are included in its final stable snapshot. No proof is promoted to native
readiness, OS code attestation, writer lease, dispatch permission or fresh GUI group proof.

New fixtures rebase the retained join content along with state and update only fixture
reference hashes/events. The new task-local filesystem verification copy matches the state's
verification. Old incoherent fixtures and the actual production records/bytes are untouched.
