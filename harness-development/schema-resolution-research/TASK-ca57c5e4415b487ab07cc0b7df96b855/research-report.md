## Finding

The DNS failure came from Python `jsonschema`’s default reference resolver. The failing review constructed `Draft202012Validator(schema)` without a registry. In the pinned `jsonschema` 4.26.0 implementation, that default includes a backward-compatibility retrieval callback that calls `urllib.request.urlopen` when a `$ref` is missing from the registry. The callback performs that call **before** it emits its deprecation warning, so warning-as-error would not prevent the network attempt. The library maintainers document this automatic retrieval as deprecated; it remains active for compatibility. [Pinned `validators.py`](https://github.com/python-jsonschema/jsonschema/blob/v4.26.0/jsonschema/validators.py#L108-L134), [v4.26.0 referencing guide](https://github.com/python-jsonschema/jsonschema/blob/v4.26.0/docs/referencing.rst#L375-L380), [v4.26.0 changelog](https://github.com/python-jsonschema/jsonschema/blob/v4.26.0/CHANGELOG.rst).

The exact URI follows from the pinned schema: its `$id` is `https://codex.local/schemas/v3/task.schema.json`, and `gate_specs.items` references `gate.schema.json`. Resolving that relative reference against the `$id` yields `https://codex.local/schemas/v3/gate.schema.json`. The schema IDs are identifiers; they do not promise that those URLs host downloadable schemas. [task.schema.json](/Users/hsiaojohnny/.codex/harness-releases/4.7.0/1bf92f52081df904cf30e1da488734643ee5ec3603464b4bf81b566263ec670d/schemas/v3/task.schema.json:3).

The immediate cause, entry-point gap, and network boundary are separate:

- **Library behavior:** an unresolved non-fragment reference reaches the default retrieval callback, which tries `urlopen`; DNS failure is then wrapped as `URLError`, `Unretrievable`, and `Unresolvable`.
- **Entry-point gap:** the reviewer’s raw validator call bypassed the pinned Harness validation path. The release’s `contracts.py` checks references, loads local resources by canonical ID and filename, and passes a registry to the validator. The result-schema validator also rejects non-fragment references before using a bare validator. [Harness contract validator](/Users/hsiaojohnny/.codex/harness-releases/4.7.0/1bf92f52081df904cf30e1da488734643ee5ec3603464b4bf81b566263ec670d/tools/harness/contracts.py:94), [task orchestrator]( /Users/hsiaojohnny/.codex/harness-releases/4.7.0/1bf92f52081df904cf30e1da488734643ee5ec3603464b4bf81b566263ec670d/tools/task-orchestrator.py:255).
- **Network boundary:** the reviewer’s record says the lookup failed during DNS and produced no remote schema response; it is not OS transport telemetry. The role’s `networkOFF` instruction does not prove OS enforcement. OpenAI’s Codex docs describe the separate command sandbox/network settings, but they do not establish which enforcement applied in this review. [Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security), [Sandboxing](https://learn.chatgpt.com/docs/sandboxing).

The pinned runtime currently reports Python 3.14.3, `jsonschema` 4.26.0, and `referencing` 0.37.0; the release lock pins those library versions. The original trace did not record package versions at the time, although its path points to this release’s venv. [requirements-harness.lock]( /Users/hsiaojohnny/.codex/harness-releases/4.7.0/1bf92f52081df904cf30e1da488734643ee5ec3603464b4bf81b566263ec670d/requirements-harness.lock:4).

## External first-hand cases and source limits

A user report in `python-jsonschema` issue #1454 uses `jsonschema` 4.26.0 and an explicit `Registry` for multi-file relative references, but still gets an `Unresolvable` error because of relative URI handling. That is a different failure; it supports testing the entire local reference graph when building the registry, not the cause of this DNS lookup. [Issue #1454](https://github.com/python-jsonschema/jsonschema/issues/1454).

The `referencing` package’s own `Registry()` defaults to a fail-closed retrieval function, while `jsonschema`’s bare Draft validator supplies a different compatibility registry. [referencing v0.37.0 Registry source](https://github.com/python-jsonschema/referencing/blob/v0.37.0/referencing/_core.py#L293-L329), [resource lookup path](https://github.com/python-jsonschema/referencing/blob/v0.37.0/referencing/_core.py#L410-L438).

## Minimum safe Harness change

Keep the schema IDs. Route every Harness schema-validation call through the pinned offline wrapper, preload the complete pinned schema set under its canonical IDs and local names, and fail closed on any missing resource. The release already has this pattern; the observed review bypassed it. Add a release check that traverses the schema reference graph through that wrapper, with retrieval callbacks that fail immediately, and verify that no network retrieval path is reached. Avoid relying on warning filters: the request happens before the warning.
